# ADR 0022：站内统一登录与同源身份入口

状态：已实现，2026-10-16。作为 0.24 的登录体验增量，业务 API、数据库版本及权限定义不变。

## 决策

用户打开管理端即看到本站账号密码表单，登录、错误重试和退出全程使用管理端域名。继续采用 ADR 0002 的机密客户端 Authorization Code + PKCE S256，保留 state、浏览器绑定、nonce、签名、issuer / audience 校验，以及服务端加密令牌和 HttpOnly 业务会话。

不启用 Direct Access Grants，不在 Vue 或 Python 业务接口中增加密码换令牌接口。Keycloak 官方已将该密码授权方式列为不应使用的流程；定制主题及反向代理是其支持的集成方式：[OIDC 流程](https://www.keycloak.org/securing-apps/oidc-layers)、[主题](https://www.keycloak.org/ui-customization/themes)、[反向代理](https://www.keycloak.org/server/reverseproxy)。

## 页面与协议

1. 管理端先读取 `/auth/session`；无会话时进入 `/auth/login`。会话失效或退出后同样返回登录表单。
2. `/auth/login` 保持原有一次性 state、PKCE verifier、nonce 和 MED_LOGIN cookie，跳转到同源 `/identity/realms/medinv/...`。
3. `medinv` 主题继承 Keycloak 26.8.0 的 `keycloak.v2`。仅增加 CSS、中文文案和品牌页脚，原生表单、错误处理、密码显隐、认证步骤和必要操作模板继续继承。
4. 账号密码通过原生表单提交到同源身份服务。授权码返回 `/auth/callback`，Python 服务换取并验证令牌、核验企业成员、创建业务会话，进入工作台。
5. 回调失败仍回到 `/?login_error=1` 并显示重试入口；该页面不自动启动新登录，避免未分配成员权限时无限跳转。

同源意味着浏览器不离开网站域名，并非取消 OAuth 内部重定向。没有把授权码、访问令牌、刷新令牌或密码持久化到前端存储。

## 开发部署

- Keycloak `KC_HOSTNAME=http://127.0.0.1:5173/identity`，`KC_HTTP_RELATIVE_PATH=/identity`，主题目录只读挂载。
- 应用 issuer 改为 `http://127.0.0.1:5173/identity/realms/medinv`，回调地址仍为 `http://127.0.0.1:5173/auth/callback`。
- Vite 仅代理 `/identity/realms/medinv/` 和 `/identity/resources/`；其余身份路径返回 404。路径中百分号编码、反斜杠及点路径段均拒绝，查询参数保持原样。
- master realm、管理控制台、健康和指标端点不从管理端公开。开发运维仍通过回环端口 8080 访问。
- Python 身份服务的 discovery、换码和刷新均通过已配置的 issuer，继续验证该 issuer 下的端点及签名；因此必须先启动管理端代理，再启动认证服务。

## 已有数据升级

`prepare_identity.py` 生成新主题配置；`sync_demo_identity.py` 通过固定回环管理入口应用主题、中文语言设置并补齐缺少的演示账号。仅迁移三个预置演示账号的已知旧 issuer；更新前验证 principal ID、旧 issuer、原 subject 与实际 Keycloak subject 的对应关系，在一个控制库事务中改写映射并撤销有变动账号的旧会话。

不按邮箱或用户名自动绑定生产身份，不迁移其他 principal，不重置已有密码和成员权限。重复同步若映射未变，不撤销已有会话。业务库不迁移，仍为 b0025；控制库仍为 c0014。

## 验证和边界

真实身份服务和浏览器覆盖本站表单登录、错误密码、PKCE、回调错误重试、退出、权限隔离、会话刷新两次和入口路径限制。桌面及手机截图检查；进销存原有页面测试均通过同源真实登录执行。

生产部署须将真实 HTTPS 域名、issuer、客户端回调和可信代理配置一起更新，并部署主题与对应的路径白名单；不能把 Vite 或 start-dev 配置用于生产。生产身份 issuer 迁移需独立核对映射、备份和撤销旧会话，不运行本机演示同步脚本。MFA、企业 SSO、自助密码找回仍未在本项目启用；此次保留原生认证模板以便后续配置，不宣称这些能力已验收。
