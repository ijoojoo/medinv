# ADR 0021：同仓移库与共享成本池

状态：已实现于 0.24。日期：2026-10-16。

## 决策

新增 `location_move` 和不可变 `location_move_item`，每单一个来源余额、一个同仓目标库位、固定基本数量。与跨仓调拨分开建单，不经过虚拟在途仓，不改变质量状态。复用 `transfers.read/write/review/dispatch` 及 `transfer_commands_enabled` 开关。

状态链为 `DRAFT → APPROVED → POSTED`，审核拒绝或确认移动前取消进入 `CANCELLED`。制单人不能审核；独立审核之后有发出权限的人员可确认实物移动。草稿和审核不预占库存，避免引入第二套预占分配规则；确认时再次检查可用量。

## 事务与账务

沿用会话写守卫和永久创建操作 ID。确认按主体、单据、商品 / 批次、来源和目标余额加锁，验证原批号、同仓不同库位、资质、效期、质量冻结、可用量和开放期间。复用 `stock_movements.balance/move`，一个 `LOCATION_MOVE` 过账及明细生成两个库存流水效果，来源为负、目标为正。

来源和目标属于同主体、同货主、同 SKU 和批次的共享成本池，不改变成本数量 / 金额，不创建成本流水、应收应付或现金单。目标相同维度库存合并，不新建批次。与销售、盘点等既有写入共用主体锁和数据库盘点冻结保护。库存、过账、单据状态、审计、Outbox 和幂等结果在同一业务事务中提交；提交前授权失败整体回滚。

已成功单据按原过账结果返回，重复确认不会再次移动；不同单据竞争同一剩余库存时只有满足可用量的事务成功。已完成 / 已取消头记录不可变，原数量和目标位置不可改；明细仅可插入，运行角色无更新删除权限。

## 边界

不增加预占，不支持部分确认、多行调配、在途、跨仓或质量转换。移库完成不重开原采购 / 销售履约，原单退货仍遵循其既有原库位规则。显示名称使用当前仓库 / 库位名称，商品与包装事实保留创建快照；库位编码与所属仓库不可通过本功能修改。

两个新表启用 FORCE RLS，外键均包含租户；读取与写入额外校验主体权限。控制库和业务库不形成分布式原子事务，继续保留原生产上线边界。
