# ADR 0023：销售缺货与关联补货采购

状态：已实现。日期：2026-10-16。

## 问题

销售已支持缺货开单、按可售量分批发货，采购已支持分次到货、验收和入库。业务人员需要从原销售需求准备补货，并在采购完成后找到原单继续发货；仅复制商品清单不能长期保留来源，也容易针对同一缺口重复采购。

## 决策

1. 以单张销售单为范围，按SKU汇总未分配需求，复用可售库存规则，并扣减本销售单已关联采购中仍未入库的非拒收数量。普通未关联采购不参与抵扣；不构建跨订单需求计划或独占供需分配。
2. 查询和生成均需sales.read及purchase.read，生成再要求purchase.write，沿用采购写入开关与提交前授权复核。生成只创建待审核采购，继续使用原有独立审核、收货、验收和过账。
3. 抽取采购创建的事务内方法，由普通采购命令和补货命令调用。补货命令先按既有锁顺序锁经营主体，再重新读取来源版本、状态、缺口及关联采购，验证请求数量后在同一事务创建采购及审计。幂等重试复用原结果；不同请求并发生成时，后者读取前者生成后的抵扣数量。
4. b0026在purchase_order增加可空source_sales_order_id与source_sales_version。租户外键、成对非空检查及触发器约束创建时来源主体、仓库、状态和版本；来源关联创建后不可改写。既有采购无来源字段值，兼容原操作。
5. 可售库存读取提取为复用当前SqlSession的快照方法，避免补货命令嵌套开启另一个业务事务。普通批发 / 零售库存查询保持原规则与接口。
6. 页面从销售生成并打开采购，从采购可返回来源销售；来源关系持久化，不依赖浏览器内存。企业及权限上下文变化清除临时导航，原单仍重新鉴权。

## 边界与后果

建议属于操作参考。共享库存不因查询或采购而预占，待到货和待验收量不等于已合格可售。正式分配和出库继续检查资质、信用、批号、效期和冻结。来源关联不是订单不可变约束；修改、关闭销售或修改采购不会联动改写另一方，应由人员核对并分别办理。

本轮入口按基本单位、每次一个供应商。跨销售单合并、跨订单优先级、供应商推荐、交期承诺、自动采购、采购独占库存和包装补货不在本次范围。
