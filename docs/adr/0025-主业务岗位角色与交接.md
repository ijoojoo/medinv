# ADR 0025：主业务岗位角色与交接

状态：已实现。日期：2026-10-16。

## 问题

原业务操作员同时拥有建档、采购、收货、销售、拣货和收银能力，不能用于验证独立岗位之间的真实交接。直接给每个岗位使用管理员账号会掩盖权限缺失、页面依赖及审计归属问题。

## 决策

1. 增加PURCHASER、WAREHOUSE、SALES、CASHIER四种角色，显式组合已存在的权限。不新增权限码，不改动已有角色，不修改已有成员，不需要数据库迁移。
2. 采购负责建档与采购写入，仓储负责收货、拣货及库存作业申请，销售负责批发写入及发货分配，收银负责普通零售收款和交付；质管与财务沿用已有角色。资金账户和客户授信继续由原管理角色设置。
3. 新角色从独立权限集合构造，放在旧角色的累加逻辑之后，避免继承无关模块写权限。现有成员管理和平台开通复用同一角色目录；组合角色取并集，重新分配角色全量重算权限并撤销旧会话。
4. 角色只控制允许的命令，职责分离继续按真实principal判断。工作台仍提供可读业务的共享进度；进入原单后由已有按钮及后端命令鉴权，不另建派单状态或复制业务单据。
5. 本机开发身份清单统一为固定八个账号，其中五个岗位账号新增，所有既有密码及业务数据保留。只补身份，不把新账号自动加入旧演示企业；岗位验收通过明确的企业开通清单加入独立企业。

## 验证与边界

认证集成验证新岗位进入核心会话、主体范围约束、跨岗写入阻断、组合角色及降权后旧会话撤销。真实OIDC验收由七个独立账号从采购、收货、验收、入库、批发、拣货、复核、零售到财务核销完成交接，读取余额核对结果。

仓库、现金账户和单据归属仍未作为独立授权维度，读取权限可能包含相关价格/成本；不宣称字段级保密。三类退货的共享写权限尚未拆分，新四岗不自动取得退货办理权，继续使用原操作员/质管/财务组合。前台角色名增加对应中文展示，不更改业务菜单分类。
