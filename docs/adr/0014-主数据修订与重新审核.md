# ADR 0014：主数据修订与重新审核

日期：2026-10-14。版本：0.14。状态：已实现。

2026-10-17 补充（b0032）：以下重新审核规则仅适用于身份 / 资质字段变动。商品及单位的推荐级别、ABC 两维、经营备注、助记码，及单位简称、日常联系人、电话、收货地址，在经营卡片直接保存并审计；不改变审核状态、审核人、审核时间或资质修订人。新经营接口只允许固定字段白名单；旧完整修订接口按实际变化字段判断，全为经营字段时不重审，混合资质变化仍重审。经营与资质共用档案版本、权限检查和提交守卫，避免并发覆盖。字典、卡片和当前版本详见[基础资料与对接编码](../development/基础资料与对接编码.md)。下文保留原方案背景。

## 业务范围

原商品及往来单位只有建档、审核和停用，不能更正错误、补齐旧资料或续期。本轮增加按原 ID 修订、重新审核以及资料变更记录，沿用既有采购、销售、零售和库存的当前资质检查。

| 对象 | 可修订字段 | 本入口固定字段 |
| --- | --- | --- |
| 商品 | 名称、生产企业名称、规格说明、批准 / 注册 / 备案编号、资质日期、药品销售分类 | 商品 ID / 编码 / 药械类别，SKU ID / 编码 / 基本单位 / 数量精度，序列号与特殊类别控制 |
| 往来单位 | 名称、经营许可 / 备案编号、资质日期、经营类别 | 单位 ID / 编码 / 信用代码 / 供应商客户类型 / 所属主体 |

修订用于同一实物商品或同一法人单位的资料更正、人工资质续期；不能用它替换现有库存的实际品种或单位身份。真正不同的商品或法人需另建档。允许补齐旧商品缺失的说明与资质字段。器械不能设置 OTC / RX；药品可以修订 UNKNOWN / OTC / RX，仍须独立审核，处方流程依旧未开放。

本轮未实现仓库库位维护、多包装、批量导入、附件、证照外部核验、待生效修订副本或原子回滚到旧版本。资料修订不会改动批次、库存、成本、信用额度、应收应付及已过账快照。旧查询若使用当前名称关联仍会显示最新名称，不能据此声称全部历史列表字段都有不可变快照。

## 状态及职责

保存修订后，DRAFT / APPROVED / SUSPENDED 均进入 DRAFT，清空 reviewed_by / reviewed_at，资料版本递增。本次已批准资质立即失效，相关业务检查会阻止依赖其资质的后续动作，直至独立审核通过；不自动取消已存在订单、预占或收款。

业务人员可修订，审核权限保持原有分工：OWNER / ADMIN / OPERATOR 使用 `catalog.write`；OWNER / ADMIN / QUALITY 使用 `catalog.review`。读取使用 `catalog.read`。商品为租户级共享资料，往来单位额外校验经营主体范围，缓存重放之前也重验权限及范围。

建档人始终不能审核通过本资料。另用 `revision_editors uuid[]` 累积尚未通过审核的修订参与人，阻止这些人审批；多人交替编辑或先停用再审批不能绕过职责分离。SUSPEND 保留修订人员，APPROVE 在独立校验通过后清空本轮人员，下一轮重新积累。停用操作仍允许建档或修订人员执行。

没有内容变化的请求返回 CATALOG_UNCHANGED，不制造虚假修订或撤销已有审核。审核原有资质日期、资料完整性和类别限制保持生效。

## 数据和迁移

业务迁移 `b0015` 给 `product`、`party` 各新增非空 `revision_editors`，默认空数组；历史建档人限制仍由原 created_by 保留。没有新增业务表，业务库仍为 69 张 FORCE RLS 表；控制迁移保持 `c0012`，没有新增角色权限，也不要求强制退出旧会话。

复用不可变的 `audit_event`，不建立另一份可修改历史账。修订事件 `catalog.revised` 保存 before / after 全部可编辑字段、变更前状态 / 版本、修订原因、结果状态 / 版本及操作者和时间。已有建档及审核事件同样出现在详情。`audit_resource_history` 索引按租户、资源类型、资源 ID、时间和 ID 支持每页 50 条历史记录。数据库已有不可变触发器与低权限授权阻止修改、删除审计事实。

创建者、修订参与人是当前授权系统的主体 UUID；界面区分“本人 / 其他成员”，展开记录可查看操作人 ID。本轮未增加跨数据库展示姓名查询。旧种子可能没有原始建档事件，界面明确说明，不补造历史记录。

## 事务与竞争

1. 在幂等缓存之前校验读取 / 写入权限及目标资源范围。
2. 往来单位修订先共享锁定有效经营主体，再锁单位；商品修订仅锁目标商品。沿用现有业务对商品、SKU、单位的共享锁，避免在过账资质检查期间插入修改。
3. FOR UPDATE 锁目标资料，校验十进制字符串 expected_version；审核与修订并发时只允许一个相同版本命令成功。
4. 只从服务端固定字段名单生成更新。身份字段不在 DTO 中，额外字段被拒绝；日期、长度、药品分类和经营类别由 DTO 及业务校验。
5. 原子更新内容、DRAFT 状态、版本和修订人员，并追加前后值审计。提交前执行现有授权守卫；撤权探测失败全部回滚。

沿用 HTTP Idempotency-Key：同键同体返回原响应，同键改体冲突。幂等缓存清理后，旧 expected_version 被拒绝，因此不会重复修订；本轮没有宣称缓存清理后永久返回原成功响应。网络失败应先刷新详情核对记录，再决定是否重试原请求。

当前订单或收款不会因修订自动变化；采购到货与入库、销售后续检查、零售最终出库等按既有流程重验当前资质。资质失败时保留可恢复单据；重新批准后可继续，原订单数量、价格和已记录付款不能被修订接口改写。零售已收款待出库需要按原单恢复或退款，不能另收一次款。

## 实际接口

新增 4 条路径、4 个操作，核心总计 91 条路径。权限与原主数据写开关一致，`MED_PROCUREMENT_COMMANDS_ENABLED` 默认关闭，本机开发配置启用。

| 接口 | 契约 |
| --- | --- |
| GET /api/v1/catalog/products/{id} | 当前商品、SKU 列表、当前页历史与 has_more；offset 默认为 0 |
| GET /api/v1/catalog/parties/{id} | 当前单位及当前页历史；额外校验所属主体 |
| POST /api/v1/catalog/products/{id}/revise | expected_version、全部商品可编辑字段、reason |
| POST /api/v1/catalog/parties/{id}/revise | expected_version、全部单位可编辑字段、reason |

详情当前记录的 version 是字符串。写入要求上下文代次、CSRF、Origin 与幂等头；禁止浏览器传入新 tenant_id、entity_id、状态、审核人或身份字段。常见错误 CATALOG_UNCHANGED、DRUG_CLASS_INVALID、VERSION_CONFLICT、SEPARATION_REQUIRED、QUALIFICATION_EXPIRED 和权限错误。详情及审计范围与目标资料一致，不提供全租户任意审计检索。

## 升级和验收

升级需要暂停业务写入、执行 b0015 并部署一致版本，防止旧审核服务忽略本轮修订人员；不需要重建历史库存或重新过账。

13 项真实 PostgreSQL 集成场景覆盖商品 / 单位修订后的采购拦截与恢复、已过账事实保持、多人编辑职责分离、停用后的审批控制、新一轮编辑、重复 / 无变化 / 过期版本请求、不可变历史、审核竞争、撤权回滚、租户主体角色范围、身份字段及器械分类拒绝、已收款零售恢复、客户经营范围及信用保持。真实 OIDC 浏览器验证双人商品和单位续期、记录对比、采购选项恢复及零售预占、只读成员直接 HTTP 写入拒绝。
