# ADR 0018：采购未收余量关闭

日期：2026-10-15。状态：已实现，0.18 开发验证版。

## 业务决定

已审核采购订单可能因供应商停止交付而无法收齐。增加关闭全部未到货余量的操作，原订购数量、交易单位、价格和已有履约事实保持可查。审批状态和履约状态继续分开：只有 APPROVED + OPEN 可关闭，关闭后为 APPROVED + CLOSED。草稿仍用原取消功能，已收齐不需要关闭；已经关闭的单据不能重新打开。

| 事实 | 关闭后的处理 |
| --- | --- |
| 原订购数量 / 包装 / 单价 | 保留原值，作为历史约定及后续计价依据 |
| 未到货余量 | 每行 closed_qty = qty − received_qty，剩余可收数量归零 |
| 已到货待验数量 | 继续按原单分次独立验收 |
| 已验收合格待入库 | 继续原入库过账，重新检查资质、批次、期间等条件 |
| 拒收及未入库保管 | 仍是原有保管事实；关闭不代表实物已交还 |
| 已入库、成本、供应商应付 | 原事实保留；关闭自身没有库存、成本或应付过账 |
| 后续采购退货 | 按原入库处理，不冲回累计到货数、不重开订单 |

例如订购 10 个、到货 4 个、其中 2 个已经判合格但尚未入库。关闭后订购 10、已收 4、已关闭 6、待收 0；余下 2 个仍可验收，4 个均可按原结论入库。关闭不能把待验或已判合格数量算作未收数量。

## 数据与接口

业务迁移 b0019；控制链仍为 c0013。没有新增表，69 张业务表继续 FORCE RLS。

- purchase_order.fulfillment_state 增加 CLOSED；closed_by、closed_at、close_reason 必须在 CLOSED 时完整存在，其他状态保持空值。关闭时 approval_state 必须仍为 APPROVED。
- purchase_order_line 新增 closed_qty numeric(20,6)，默认 0；非负且 received_qty + closed_qty ≤ qty。
- 关闭头触发器要求全部行的已收加已关闭数量等于订购量，至少一行关闭数量大于零，原状态是 APPROVED + OPEN。已保存关闭状态、人员、时间和原因不可改写。
- 关闭订单的行禁止新增、改写、删除或移入。验收 / 过账修改 receipt_line 等履约事实，不会修改已关闭采购行。
- 详情新增 closed_qty、unreceived_qty；remaining_qty 改为 qty − received_qty − closed_qty，表示当前可继续收货数量。unreceived_qty 表示历史未到货差额，关闭后可能大于零。

新增 `POST /api/v1/purchase-orders/{id}/close`，请求复用 Transition（expected_version、reason）。权限为 purchase.write，主体范围、会话、CSRF、Origin、Idempotency-Key 及提交前授权守卫沿用采购命令。受 MED_PROCUREMENT_COMMANDS_ENABLED 控制，生产默认关闭。无新权限迁移或人类角色变更。核心 API 路径数为 98。

成功返回 id、version、fulfillment_state、closed_by、closed_at、close_reason 以及本次实际关闭的行 ID / 数量。状态不合法或无剩余数量拒绝；旧版本返回 VERSION_CONFLICT。同键相同请求返回保存结果，同键改变请求拒绝。新幂等键再次提交已关闭订单不会再次产生关闭事实，应重新读取原单。

## 事务、权限和计价

关闭沿用主体行排他锁、订单锁和通用命令事务，与收货、验收及入库保持统一顺序。收货和关闭争用同一订单版本，只能一个先成功，另一个须刷新核对；验收 / 入库和关闭串行执行但可以都完成。

关闭不要求供应商及商品当前仍有可采购资质，也不因商品冻结而阻止结束未交付约定；主体必须处于活动状态。后续合格验收与入库仍执行原资质和质量拦截，没有通过关闭绕过检查。

purchase.write 角色可关闭（OWNER / ADMIN / OPERATOR），质量审核、财务及只读角色不因能查阅订单而获得该权限。沿用现有草稿取消、销售余量关闭的操作员结束剩余履约模式，本次没有额外审批流。

所有行关闭数量、头关闭信息、版本、purchase.closed 审计及幂等结果同事务提交；撤权探测或任一数据库异常整体回滚。关闭没有生成库存事件或新增往来义务。既有跨控制库与业务库授权的最终提交故障窗口仍存在。

包装订单保留原订购基本数量作为金额分摊分母。1 箱 = 3 个、箱价 1 元，仅收到 1 个后关闭 2 个，随后入库仍按原约定分摊为 0.33 元；关闭部分不会转嫁给已收数量。采购退货继续依据原过账金额和成本。

## 验证和后续

新增 23 项真实 PostgreSQL 验证：未收关闭、多行余量、待验 / 合格待入库 / 已入库 / 拒收保管、包装分摊、关闭后采购退货、状态与租户 / 主体 / 角色限制、收货竞争、入库竞争、同键重试、提交失败回滚、数据库不可变约束及 HTTP 认证 / 开关 / 请求头。

真实 OIDC + Edge 浏览器验收覆盖双人采购、部分收货及部分验收、操作员关闭、质量人员完成原到货验收入库、库存数量核对、关闭原因展示及只读限制。记录与截图保存在 artifacts。

本次为整单未收余量关闭，不支持选择部分行关闭、重开、改商品 / 数量 / 价格、供应商协同变更、赔偿结算或拒收保管自动交还。需要追加采购时新建订单。后续继续推进采购变更及逐行验收质量结论。


## 本轮回归补充：采购 / 销售 / 库存资料选项分页

本机持续验收后，商品与往来单位超过旧 200 条选项上限，导致采购 / 销售开单及库存查询页面无法完成加载。本轮将 purchasing/options、selling/options 与 inventory/options 增加 offset（默认 0，最大 100000），每类数组每页最多 200 条，返回 has_more、next_offset。需要完整目录的调用方必须继续取页，不能只用第一页判断商品或单位不存在。

管理端依次取页、按 ID 去重，加载期间企业上下文变化则停止本次加载；订单最终提交仍重新校验资格与主体范围。接口保持租户隔离和稳定名称 / ID 排序。分页之间目录变更不是一致快照，刷新后重新读取；目前仍加载完整下拉选项，超大目录的远程搜索和前端容量优化留待后续，不宣称生产大目录性能已验收。

新增 6 项真实 PostgreSQL 验证：206 个供应商 / 客户、库存 SKU 及仓库的跨页完整性、空尾页、类别数量不一致时的取页行为、主体和租户隔离及三个 HTTP 接口的 offset 边界。没有清空或停用演示资料来绕过旧上限。
