# ADR 0020：销售分配前变更

日期：2026-10-16。状态：0.22 已实现。

## 问题与决策

日常销售需要在履约前纠正客户、数量、价格和送货约定。新增原单修改，范围限定 DRAFT / APPROVED 且没有任何 reservation / shipment 历史。已取消的分配也保留关联事实，因此不重新开放修改；履约后的更正使用原有关闭、退货及另开新单流程。

保存变更保持单号、主体和制单人，递增 revision_no / version，转为 DRAFT，并累计本轮修改人。原制单人及本轮任一修改人不能审核；批准后清空本轮集合。旧资料失效不阻止替换为当前合格客户或商品；新约定仍完整通过销售准入和包装精度检查。

## 事务与信用

复用 sales.write、会话 / CSRF / 租户 / 主体 / 提交前授权守卫及销售命令开关。幂等记录 → 主体 → 销售单 → 需求记录加锁。主体锁与需求锁将改单、正常分配、通用预占及信用变动串行化。

修改已批准单时，按旧客户及 remaining_exposure 释放信用占用；新客户与新金额待重新批准时重新计入。额度释放、订单及行替换、需求停用、版本和不可变审计在同一事务提交。任何资质、数量、版本、信用一致性或提交授权错误均回滚。改单不产生库存、成本、应收或资金过账。

保留 inventory_demand 头，置 CANCELLED / checks_completed=false 并递增版本；仅删除无占用、无履约且无任何预占历史的旧需求行。重新批准复用该停用需求头，恢复 APPROVED，更新仓库与资质截止时间，再创建新需求行；不删除或复用实际预占、分配、发货及台账事实。

## 数据保护与查询

b0024 给 sales_order 增加 revision_no 和 revision_editors；数据库触发器保护原单身份、履约后的约定及行。仅给 sales_order_line、inventory_demand_line 增加受状态和历史检查约束的 DELETE 权限；需求头不增加 DELETE 权限。两类行替换均保留 before / after 审计快照，历史发货所依赖的行禁止删除。

新增 POST /sales-orders/{id}/revise、GET /sales-orders/{id}/history；详情返回 can_revise、版本和本轮修改人。历史读取沿用 sales.read，按 50 条分页。新创建及审批事件保留当时约定，升级前历史不伪造补全。

## 验证与范围

20 项真实 PostgreSQL 专项覆盖信用释放及跨客户重算、多修改人职责分离、包装数量、部分出库金额、失败回滚、隔离权限、幂等，以及改单与审批 / 分配的竞争。真实 OIDC 页面验证两箱 60 元改为三箱 120 元，重新独立审核并出库九件；全量结果以开发验证记录为准。

本增量不增加履约后改价、价格审批层级、差价单或复杂变更协议版本管理；保持前期聚焦主体进销存。
