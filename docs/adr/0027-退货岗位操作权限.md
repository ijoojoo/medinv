# ADR 0027：退货岗位操作权限

状态：接受；日期：2026-10-16。

原returns.write涵盖三类退货申请、取消、隔离收货及交还客户。直接授予四种新岗位会同时放开无关渠道及实物环节，因此保留旧权限作为兼容入口，增加四个明确动作权限。

| 新权限 | 岗位 | 服务端判定 |
| --- | --- | --- |
| returns.purchase.write | PURCHASER | 已持久化来源/退货单kind=PURCHASE，允许申请及符合条件的取消 |
| returns.sales.write | SALES | 已持久化来源/退货单kind=SALES，允许申请及符合条件的取消 |
| returns.retail.write | CASHIER | 已持久化来源/退货单kind=RETAIL，允许申请及符合条件的取消 |
| returns.custody | WAREHOUSE | 允许原客户退回品隔离收货及未过账实物交还 |

四岗同时具有returns.read，原returns.review、returns.post、finance.reverse及retail.refund沿用质管/财务职责。所有者、管理员和操作员的returns.write不改变；组合角色按并集，不引入角色名称判断或管理员绕过。

申请类型由数据库来源确定，不信任客户端类型提示。创建和取消在读取缓存幂等结果前完成动作及主体校验；事务内继续检查主体启用、版本、数量、单据状态和实物保管。收货及交还选择旧returns.write或新returns.custody，使用相同业务事务。前端按相同权限映射显示原单按钮，后台拒绝伪造调用。

迁移c0016只为已有四岗成员补充相应权限，组合岗位只提升一次成员权限版本，不改变启用状态、经营主体、角色或其它权限。仅在权限数组发生变化时更新版本；撤销版本不一致的旧会话并清除旧令牌密文。重复执行补权SQL不重复提升版本。新成员分配与企业开通使用更新后的ROLE_PERMISSIONS。

业务库仍为b0026，无新增业务表、命令路径或响应字段。读取范围仍按企业与主体，不做渠道/字段保密隔离。采购退货沿用质管核对交接并过账，不引入独立仓储发运子单。

验证包括三个来源类型的越岗申请与取消、幂等重放前权限及租户主体检查、独立复核、仓储拒收交还、成本数量变化、财务退款、已有成员升级和会话撤销，以及七身份真实页面交接。结果见 [退货岗位验证](../development/退货岗位验证.json)。
