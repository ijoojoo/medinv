# ADR 0017：预占到期自动回收

日期：2026-10-15。状态：已实现，0.17 开发验证版。

## 业务决定

库存预占到期后不能继续付款或出库，但此前只能人工取消。增加独立回收进程，释放可以安全重新销售的占用，并在同一事务结束对应来源单据。已付款单和已拣货实物保留占用，避免把已交付或已移位的商品再次销售。

| 来源 / 状态 | 自动行为 |
| --- | --- |
| 零售 RESERVED、无任何付款记录、无保护标记 | 释放分配量，零售单和库存需求转 CANCELLED |
| 批发发货 ALLOCATED | 释放分配量，子单转 CANCELLED；父订单版本加一，审批状态与信用占用保留 |
| PICKED / VERIFIED / POSTED | 跳过；已拣货或复核的超时单须核对归位后人工取消 |
| PAID_PENDING_POST 或任何零售付款记录 | 跳过；继续原单出库或实际退款取消 |
| 任意非空 protected_until 或 PAID_PROTECTED 需求 | 跳过，即便保护时间已过，亦不把已收款当作未收款 |
| 其他已到期普通 ACTIVE 预占 | 复用普通释放事务，恢复需求可分配量 |
| 非活动企业或主体、未到期、已释放 / 已消耗 | 跳过 |

只减少 stock_balance.reserved 与 demand_line.reserved_qty、增加 allocation.released_qty。实存、成本、往来义务、收付款、原销售订单信用占用不变。释放之后是否可售仍取决于质量、效期和冻结等现有规则。

## 执行和事务

入口 `python -m medinv.entrypoints.expiry_worker`，与 API 独立部署。复用 med_runtime 和 control_runtime；启动检查禁止 owner、超级用户和 BYPASSRLS。默认开关关闭，无 HTTP 管理入口，不授予任何人类角色 inventory.expire 权限。内部固定审计身份为 `518175a3-fcca-50e3-8dcb-68d4508031b3`，不是可登录账号。

每轮按控制库活动租户 UUID 游标取至多 10 家，各自按 `(expires_at,id)` 游标取至多 25 条（可配 1–100）。进程在单项之间检查 5 秒软预算；单项仍受数据库语句 / 锁超时约束，不承诺每轮严格 5 秒。轮间默认等待 15 秒。游标仅在内存中，最多保留 1000 家的逐租户位置；重启从头扫描，终态校验防止重复释放。尾部回绕存在一个空扫描轮次。实际延迟受企业数、队列长度和持续占用影响，15 秒不是每张单的回收 SLA。

执行单项时，控制库 `lock_maintenance_tenant(uuid)` 以 SECURITY DEFINER、固定 pg_catalog 搜索路径检查 active 并持有租户 FOR SHARE；PUBLIC 无 EXECUTE，仅 control_runtime 可调用。运行角色仍不能修改租户。业务提交前探测控制事务连接；失效则回滚。租户停用须等待已持有锁的回收事务结束。与现有用户写事务相同，两库不提供分布式原子提交，最后一次授权探测至业务提交之间仍有故障窗口。

业务库先以 tenant_id 设置 RLS，再锁主体 `FOR UPDATE SKIP LOCKED`。忙碌主体跳过，避免与正常收款 / 拣货争锁。之后锁父订单、发货 / 零售来源、库存需求及预占，重新检查状态、付款事实和到期时间，再调用现有 `_release`。主体锁与现有写入统一（普通库存命令使用共享主体锁），因此不会在预占与收款锁之间形成相反顺序。一个来源单据一个事务；失败不影响下一项，游标前移避免坏记录长期阻挡其他记录，下一循环可重试。

复用 RELEASED，不新增状态。b0018 增加 auto_released_at、状态约束和不可变标记触发器，以及活动无保护预占的扫描索引；c0013 增加控制库租户守卫函数。仍为 69 张 FORCE RLS 表、97 条核心 API 路径。auto_released_at 不允许被清除或随状态回退，用于区别自动与人工取消；审计保存原因、原到期时间和来源。

库存释放已有 `inventory.released` 审计及 Outbox 在同一事务写入，另记 `inventory.auto_expired`，来源分别记 `retail.expired` 或 `sales.shipment_expired`。重复扫描、人工取消和多工作进程竞争不会重复减少预占或重复产生释放事件。当前没有新的事件消费者或自动发通知。

## 验证和限制

新增 23 项真实 PostgreSQL 测试覆盖时间边界、相同到期时间分页、租户 / 主体权限、付款与物理状态保护、付款和拣货并发、多进程与人工释放竞争、忙行重试、坏项不阻塞后续、提交失败整体回滚、租户停用串行化、运行角色权限以及重启重复扫描。

浏览器通过真实 OIDC 和业务 API 创建虚拟采购库存、零售及批发单，测试时间夹具仅对精确 UUID、创建 10 分钟内且带软件验收商品标识的预占提前到期；再使用真实回收事务、租户守卫和工作进程 tick，范围限定到该条测试记录。没有伪造接口响应、付款、库存或单据状态。真实 CLI / Linux 镜像另行冒烟。尚未完成生产容量和故障注入压测。

暂不提供到期续期、按租户配置 TTL、已拣货自动归位、任务管理页面和告警投递。生产应使用进程管理器监督独立任务，并监测扫描错误、长时间未释放的符合条件预占、保护单积压。人工取消仍可作为业务恢复入口。
