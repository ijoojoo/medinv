# ADR 0016：包装换算与交易单位快照

日期：2026-10-14。状态：0.16 已实现，属于主体进销存迭代。

## 决策

库存、批次、成本数量、预占和履约全部保留基本单位；包装仅作为开单的交易单位。采购、批发销售、零售行增加可选 `packaging_id`。指定时，`qty` 是包装数量，`unit_price` 是每包装的含税价。未指定仍为基本单位，旧请求序列化省略空包装字段，保持既有请求指纹与重试兼容。

换算为 `base_qty = trade_qty × numerator / denominator`。用 Fraction 作精确有理数运算，结果必须符合 SKU 的 0–6 位小数精度及 numeric(20,6) 上限，否则整个命令拒绝。不得用浮点数或四舍五入产生库存。输入数量最多 6 位小数；比例分子、分母通过 API 接收 1–999999999 的整数字符串，保存约分后的值。比例可小于 1，实际每次交易仍须满足基本单位精度。

## 包装版本

复用租户级 `med.packaging`，与商品相同，不附加经营主体归属。

- 创建 DRAFT：`catalog.write`，校验 `expected_sku_version`，基本单位同名禁止另建，同 SKU/单位最多一个待审版本。
- APPROVE：`catalog.review`，建档人不得批准；新版本获批时，原同名 APPROVED 原子转 RETIRED。每个 SKU 最多 20 个启用单位。
- SUSPEND：停用 / 拒绝版本，进入 RETIRED 终态；不能复活、改比率或删除。重做须创建后续版本。
- 使用 SKU 行锁串行化包装维护；开单按既有次序锁定 SKU，再读取包装共享锁。审批和开单竞争时，以成功事务实际读到的有效版本为准。新版本不改变已建订单。
- 两类维护都更新 SKU 版本，提交前沿用授权检查，修改与审计同事务；失败或提交撤权时整体回滚。原 expected_version 与幂等键防止重复修改。

数据库触发器固定包装身份、比率、版本与创建字段，并禁止已停用行再变更；历史交易行快照也不可改。审核原因和凭据保存至既有 append-only audit_event。界面显示包装状态、比例、版本及批准人标识；独立附件存储后置。

## 单据与金额

| 位置 | 保存及使用规则 |
| --- | --- |
| 采购行 | `qty` 为基本数量；包装交易保存 `trade_qty`、package_snapshot、订单行含税 / 未税总额；unit_price 为交易单位单价 |
| 销售行 | `qty` 为基本数量，新增 trade_qty / package_snapshot；总额按原输入交易数量乘单价，信用与需求数量延续原规则 |
| 零售行 | 同销售，复用既有 package_snapshot，新增 trade_qty；按基本数量 FEFO 预占与交付 |
| 收货、验收、发货、退货、调拨、盘点 | 输入和过账数量均为基本单位；不再次乘包装比例 |
| 过账行 | 带入来源单据原包装快照，不重新读取当前包装配置；快照中的 trade_qty/base_qty 表示原交易行，实际本次数量在 posting_line.base_qty |

package_snapshot 包含 base_unit、qty_scale、unit_name、numerator、denominator、trade_qty、base_qty；包装交易另有 packaging_id、revision。对既有单据空快照采用原基本单位逻辑，不能追溯补算交易包装。

包装采购先按交易数量×交易单价计算含税总额到分，再计算未税总额。每次合格入库以“累计已过账基本数量”分摊该总额：累计比例金额分别四舍五入到分，本段取两次累计值之差。未税总额按累计含税金额继续分配，防止小额分段出现未税额大于含税额。全量最终段收齐尾差；关闭未履约余量只保留实际入库部分。拒收、待验不占已过账分摊数量。

示例：1 箱 = 3 个，1 箱价 1 元，税率 13%；三次各合格入库 1 个，含税分别 0.33、0.34、0.33，未税合计 0.88。基本单位采购沿用原逐次金额算法，避免改变旧单行为。销售沿用已有累计分摊算法，分母现在是换算后的基本数量。退货按原过账行基本数量及已保存金额 / 成本分摊，包装后续改变不影响退款依据。

## 接口、开关与迁移

- GET / POST `/api/v1/catalog/skus/{id}/packaging`：列表 / 新建。
- POST `/api/v1/catalog/skus/{id}/packaging/{packaging_id}/review`：批准 / 停用。
- GET 默认每页 50，`offset` 0–100000；`approved_only=true` 用于开单选择，启用项最多 20。
- 写入沿用 `MED_PROCUREMENT_COMMANDS_ENABLED`，默认关闭，本机 dev.py 启用；开单分别沿用采购 / 销售 / 零售开关。权限未新增，不需会话权限迁移。
- 迁移 b0017 / 控制 c0012，仍为 69 张 FORCE RLS 表，核心 API 共 97 条路径。
- 若存在以前手工写入的 packaging 数据，迁移保留原值并标为 RETIRED，避免未经此审核流程的比例直接进入开单。须按原实物核实后另建版本；不伪造历史批准或影响原过账。
- 升级先暂停写入，备份并执行迁移，再部署一致版本服务；不能混跑新旧版本。旧服务不理解包装交易价。

## 验证与范围

覆盖精确 / 不可表示 / 溢出换算，旧指纹兼容，独立审核与版本替代，权限 / 租户 / SKU 归属，乐观锁并发，撤权回滚，数据库不可篡改，分批采购 / 销售，零售预占与完成，按基本单位分次采购 / 零售退货。实测结果见开发进度及验证记录。

本轮不区分“未拆封箱”和“散件”库存，不做整箱限制、拆装箱作业、包装条码 / 追溯码绑定、自动包装报价、包装级库存报表、批量导入与生效预约。库存上显示的基本数量不证明可发完整包装；现场仍须核对实物。
