# 部署与运行手册

版本1.0。此手册为后续实现和演练规范。当前交付为技术文档及契约，尚未提供可运行应用、Compose文件或生产基础设施。下述流程在对应工程交付后执行，禁止将参考DDL直接施加到现有生产库。

## 环境和配置清单

| 配置 | 所在进程 | 要求 |
| --- | --- | --- |
| APP_ENV | 全部 | dev test stage prod之一 启动时明确显示 |
| BUSINESS_DB_URL | API及业务worker | 私网TLS连接；runtime非owner无DDL |
| CONTROL_DB_URL | 控制面和会话模块 | 与业务库分离；会话专用最小权限账号 |
| OIDC_ISSUER_URI OIDC_CLIENT_ID | BFF | 校验issuer audience redirect URI |
| OIDC_CLIENT_SECRET_REF | BFF | 仅秘密引用，轮换和撤销可操作 |
| SESSION_COOKIE_NAME | BFF | MED_SESSION HttpOnly Secure SameSite=Lax |
| STORAGE_ENDPOINT STORAGE_BUCKET | 文件模块 | 私有桶；生产身份采用短期服务凭证 |
| KMS_KEY_REF | 文件及敏感字段模块 | 可恢复的密钥版本及封装加密策略 |
| CACHE_ENDPOINT | 查询限流 | TLS和ACL；禁止保存唯一交易事实 |
| OTEL_EXPORTER_ENDPOINT | 全部 | 私网遥测；敏感数据过滤 |
| MAX_DB_CONNECTIONS | 各进程 | 统一预算；不能每实例独立开过量连接 |
| WORKER_CONCURRENCY LEASE_SECONDS | worker | 有限并发 租约和fencing token |
| BUSINESS_TIMEZONE | 核心服务 | 默认Asia/Shanghai且规则版本化 |

开发和测试只使用脱敏数据；生产域名、证书、密钥、桶和回调白名单由发布配置注入。示例接口域名example.invalid不可替换成第三方账号猜测地址。身份系统和业务系统各自备份，关联subject映射必须可恢复。

## 建仓与首次数据库准备

1. 锁定Java、Boot BOM、Maven Wrapper、Node、pnpm、Vue和数据库版本，保存供应商许可证及镜像digest。生成SBOM。
2. 分别创建控制数据库、业务数据库和身份数据库。创建NOLOGIN对象owner、临时migration及无owner继承的runtime角色。禁止runtime拥有SUPERUSER、BYPASSRLS、CREATEROLE或数据库管理权。
3. 在独立评审空库执行core-reference.sql验证结构，仅用于核心切片原型。生产由各模块Flyway迁移创建完整结构及权限；不使用该文件替代完整迁移。
4. 配置RLS并用runtime连接做A/B/缺上下文三组试验。事务中set_config必须与业务SQL同连接。
5. 初始化平台租户开通流程、主体及管理员；药师和质量岗位由有权人员验证真实资格后绑定，初始化不虚构证照。
6. 初始化存储桶、KMS、对象保留与扫描队列；验证附件跨租户拒绝和停用后导出。
7. 接入监控后，跑采购合格入库、预占、零售收款恢复和库存重算的核心切片。

## 发布步骤

发布前核对变更单、迁移摘要、前后版本兼容、备份和归档新鲜度、剩余连接数、事故值班与试点窗口。完成预生产同版本演练后由单独迁移作业执行expand脚本，再发布worker兼容版本和API灰度实例。验证readiness、OIDC、租户隔离、单据查询、幂等重试及模拟过账后扩量。

新功能先按试点租户启用；观察错误率、P95、锁等待、paid_pending_post及Outbox积压。若错误预算或正确性异常，停止扩量，关闭受影响新入口；只有数据库兼容的应用版本可回退。已经提交的交易不通过旧备份抹除，使用前向修复或业务更正。

结束时保存镜像digest、迁移版本、功能开关、配置版本、验收报告和监控截图索引。迁移凭证到期撤销。contract删除旧列放在独立后续发布，不与新增功能同次急推。

## 故障处置

| 信号 | 先做什么 | 恢复判定 |
| --- | --- | --- |
| 库存重算差异 | 暂停受影响SKU写入 保全流水和日志 | 找到原因 经审查修复 重算为零差异 |
| 已收款待出库积压 | 查询原销售 付款来源和质量状态 | 原销售合法完成或退款证据闭环 |
| 数据库不可用 | 停交易写入显示维护 禁止本地假成功 | 数据库恢复并核对在途提交结果 |
| 锁等待升高 | 看阻塞链和事务范围 暂停大后台任务 | 核心延迟恢复 无强杀造成的未核实状态 |
| 外部平台超时 | 保留任务及回执状态 按策略退避 | 查单或收到业务回执 对账无重复 |
| 身份平台异常 | 已有有效会话按策略短期服务 新登录受控失败 | OIDC验证恢复 撤权同步确认 |
| Redis故障 | 缓存降级与全局并发保护 限流保守 | 核心账本正常 限流和缓存恢复 |
| 附件扫描失败 | 禁止使用未通过文件 转人工排查 | 文件清洁状态和业务引用权限明确 |
| 密钥或凭证泄露 | 撤销轮换 限制通路 审计影响范围 | 新旧凭证隔离 验证无持续越权 |

不要凭接口超时判断支付失败，不要用手工UPDATE余额修库存，不要通过删除Inbox消除对账异常。查询或重放都应使用原业务标识，人工处置保留工单、操作者、审批及证据。

## 备份与恢复演练

RPO目标15分钟、RTO目标4小时。数据库持续WAL归档和定期全量备份；对象存储保留版本和可恢复清单；配置、身份数据和密钥恢复材料独立备份。备份访问与生产运维权限分离，加密密钥不能只存在唯一已失效生产设备。

演练顺序：宣布测试隔离范围，记录灾难假设及开始时间；选择可恢复时间点；在隔离网络恢复数据库、对象和必要身份映射；应用以只读启动；对每租户抽样和聚合核对数量、成本、结算、码与审计；取得恢复水位后查询外部付款、订单、监管回执；通过业务命令补齐缺失事实；执行幂等重放验证；完成业务签字再切流量。记录实际数据丢失窗口与总耗时。

单租户误操作不恢复整个平台。先在隔离完整恢复环境导出目标租户和附件引用，按依赖顺序比对，确认所有外部既成事实，停目标租户写入后采用经审查的迁移或补偿流程。其他租户继续服务。不存在“直接把某个旧租户快照覆盖回生产”通用按钮。

## 数据迁移与首次营业

至少两轮演练。源数据先标准化商品、包装、批号效期、往来和编码；分别生成主数据、期初数量及成本、期初应收应付和追溯持有记录。历史销售作为历史归档或明确来源导入，不能触发真实外发或当期收入。

预检提供行级错误、重复身份、金额与数量汇总；导入按batch_id及row_id防重，正式提交调用受控应用服务，不能绕过资质和不支持品种拦截。余额和成本按主体、仓库、SKU、批次逐级核对，无法解释差异不得上线。

切换前清理未决收款、预占、在途与未回执上传，锁定旧系统截止水位。冻结旧系统写入，导出增量，核对后初始化新系统期初和开放期；明确每个平台唯一发送方。新系统试营业期间保留旧系统只读查询，不能让双方同时主控同一库存。

## 日常运维节奏

每日检查备份新鲜度、库存和结算重算、已收款未完成、追溯回执超时、任务积压及证照到期。每周复核权限、支持授权和差异任务；每月检查版本支持、依赖漏洞、容量和成本；每季度灾备演练。提醒不能替代交易时实时阻断。

租户退出先确认数据范围、留存义务、未决款项和上传任务，提供带版本说明的加密导出与附件清单；下载有时效与审计。保留规则和legal_hold优先于物理清理计划，结束订阅不自动销毁全部业务记录。
