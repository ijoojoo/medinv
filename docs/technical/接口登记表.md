## 状态转换登记
审批DRAFT→SUBMITTED→APPROVED，驳回回DRAFT；关键内容变更重新审批。过账后不可修改关键字段。
预占ACTIVE可部分消费，余量为0后CONSUMED；释放剩余后RELEASED；冻结则INVALIDATED。只有剩余量才释放。
零售DRAFT→READY→PAID_PENDING_POST→COMPLETED；无款取消CANCELLED；付款未知PAYMENT_UNCERTAIN；已款失败由恢复单驱动完成或退款关闭。
付款确认记录CONFIRMED不因库存失败回退；退款是新事实，原付款可派生展示PARTIALLY_REFUNDED或REFUNDED。
上传READY→SENDING→AWAITING_RECEIPT→SUCCEEDED；可重试失败进入RETRYABLE_FAILED，永久失败进入MANUAL_REQUIRED。
## 外部平台边界
外部回调URL、签名、枚举及限流在取得对应平台正式文档后登记。通用Webhook不能替代各平台验签算法。内部事件订阅与平台上传任务独立授权。

## 0.15 已实现补充：仓库与库位（2026-10-14）

以下以运行契约为准；上方原规划条目不代表全部交付。当前已实现核心 API 为 95 条路径。

| 路径 | 方法 | 请求关键字段 / 参数 | 权限 |
| --- | --- | --- | --- |
| /api/v1/warehouses | GET | entity_id、search、offset | inventory.read |
| /api/v1/warehouses | POST | 原 WarehouseCreate：client_operation_id、entity_id、code、name、location_code | warehouses.write |
| /api/v1/warehouses/{id} | GET | search、offset（库位）、history_offset（维护历史） | inventory.read |
| /api/v1/warehouses/{id}/rename | POST | expected_version、name、reason | warehouses.write |
| /api/v1/warehouses/{id}/locations | POST | client_operation_id、仓库 expected_version、code、name、reason | warehouses.write |
| /api/v1/warehouses/{id}/locations/{location_id}/rename | POST | 库位 expected_version、name、reason | warehouses.write |

列表和两种详情子列表每页 50 条；has_more / history_has_more 独立表示后续页。维护限实体仓库，系统在途仓返回 SYSTEM_WAREHOUSE；编码重复、旧版本、无变化和跨父仓库均拒绝。写入开关 MED_WAREHOUSE_COMMANDS_ENABLED 默认 false，与调拨开关独立；必须带既有上下文、CSRF、Origin 和 Idempotency-Key。创建操作号永久防重，名称修改采用 HTTP 幂等及版本检查。

/api/v1/inventory/availability 的 AvailabilityItem 新增必返 location_id、location_code、location_name；采购和调拨库位选项新增 name。未命名的历史库位返回 code 作为 name。内置契约与规划契约中该已实现响应同步扩展，其他规划路径保留。完整规则见 [ADR 0015](../adr/0015-仓库与多库位维护.md)。
