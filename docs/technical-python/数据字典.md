## 通用约定

### b0034 增量：商品证照档案

运行表 `med.product_certificate` 按商品维护独立证照，以 `(tenant_id,id)` 为主键、`(tenant_id,product_id)` 为商品外键，强制RLS。同商品、同类型、同编号唯一，包含停用记录；当前每商品最多100份。

| 字段 | 当前实现 |
| --- | --- |
| certificate_type / number | DRUG_APPROVAL、DEVICE_REGISTRATION、DEVICE_FILING；编号最多120字，不含租户自动猜测类型 |
| holder_name / issuer | 原件载明持有人及发证/备案机关，各200字；草稿可空，核验时必填；暂为原件文本，未自动合并机构身份 |
| covered_models | 原件覆盖规格型号文本500字；当前绑定商品，不代表已实现多商品/包装覆盖关系 |
| issued_on | 可空日期，独立记录签发/备案日期，不使用原有valid_from推导 |
| validity_mode / valid_from / valid_until | FIXED需合法起止；NOT_STATED、UNCONFIRMED时两日期为空；核验药品批准及器械注册证要求FIXED |
| evidence_ref / note | 原件内部凭据号120字、备注500字；当前不含原件文件上传 |
| state / version | DRAFT、VERIFIED、INACTIVE；独立乐观版本，API字符串；每次内容修订回DRAFT |
| revision_editors / reviewed_by / reviewed_at | 本轮修订者及核验记录；建档人与本轮修订者不能核验通过 |
| created_by / updated_by / created_at / updated_at | 维护责任与时间；与父商品分别记录 |

`med.audit_event`新增`catalog.certificate_created/revised/reviewed`，资源为product、详情含certificate_id、完整前后值、版本、操作原因及核验凭据。每次写入在同事务内保存审计；无删除接口。历史采用审计快照，不是多份业务生效版本并行。

兼容层在证照列表返回`legacy.type=LEGACY_UNCLASSIFIED`及父商品原始编号、日期、来源版本，只读且不会自动核验。旧product/SKU身份、资质、库存和历史单据均保留；新证照暂不替代交易准入。列表另计算有效期情况和当前类别匹配情况，与核验状态分别显示。

### 既有通用约定

所有业务对象的 tenant_id 为 uuid 必填；id 为 uuid 必填，复合主键为二者。可变实体有 created_at/updated_at timestamptz、created_by/updated_by uuid、version bigint；不可变事实只追加创建信息与来源。控制面表另行说明。类型后 ! 表示必填；未标 ! 表示允许为空但业务规则可能按场景要求。

数量 numeric(20,6)、金额 numeric(20,2)、成本 numeric(24,8)、单价 numeric(20,8)、税率 numeric(9,6)。所有关系引用带 tenant_id；需要主体或 SKU 一致时采用更强复合外键。所有列表索引及唯一业务键均包含租户。原始码为 bytea，API 用 base64，不使用数值类型。

本字典分为可机读参考脚本已覆盖的核心表和其余逻辑表。后者必须在对应模块迭代前生成独立 Alembic 迁移，并补齐约束和索引；不能把逻辑字段清单当成已经运行的数据库。

## 结构性审查清单

1. 控制面表与业务租户表分库；所有业务外键和唯一业务键含tenant_id。

2. 部分表组同时出现头行字段仅用于阅读；生产迁移必须规范化并建立明确外键。

3. 对跨主体、数量精度、角色资格、状态和累计量的约束，在数据库与事务应用层分别落实。

4. 过账、成本、审计、流转、审批动作与核销事实只追加；余额投影允许受控更新。

5. 核心脚本不含处方、财务等完整迁移，也不包含库存写存储过程；不得直接用脚本建空库就宣称系统可营业。

入口为“设置 → 商品字段设置”，按企业分别维护DRUG、DEVICE两个商品类别。配置现有资料字段的显示、必填、排序、最短/最长字符数、格式验证和条件必填；不新增任意数据库列，也不执行管理员输入的脚本或正则表达式。商品编码、类别、SKU、基本单位及数量精度仍使用固定身份字段。

新增 `med.product_field_rules`：tenant_id/id复合主键、tenant_id/category唯一，fields为JSON数组，version为递增整数，保留创建/更新人及时间；启用并强制RLS，业务表共76张。无配置记录时读取完整系统默认规则，逻辑版本为0。管理员首次保存后版本为1。字段定义中的名称、类型、可用选项、存储容量、基础必填和器械证照名称联动由服务端维护。

2026-10-18兼容增量（当前b0034，不新增迁移）：`fields[].display_name`为企业显示名称，最长40字符，默认空；旧JSON读取时补默认，旧客户端未传此属性时保留已有值，显式空字符串恢复系统名。写入前检查系统保护名称及规范化重名。原`key`、商品字段值、字段配置版本机制保持不变。`field_code`、`card`、`owner_department`、`review_policy`、`alias_allowed`、`meaning`以及模板信息由服务端运行目录派生，不作为可编辑租户JSON字段存储；现有字段以`catalog.product.<key>`为稳定标识。商品详情/经营读取返回`field_policy.context`，仅包含器械类别或药品销售分类，供显示和条件必填解析。当前药品/器械分别为17/16字段，仍不是全部设计目录的运行实例。

| 配置属性 | 约束与语义 |
| --- | --- |
| key | 系统字段白名单，保存时必须提交当前类别完整清单，拒绝缺失、重复或跨类别字段 |
| visible / required | 必填字段必须显示；基础必填不能隐藏或取消；分类选择字段始终显示 |
| order | 0–999整数，数值越小越靠前；同值按字段键排序 |
| min_length / max_length | 非空文本校验，范围不得超过字段实际容量；选项和日期不接受文本长度/格式规则 |
| validator | NONE、NO_WHITESPACE、ASCII_CODE（英文字母、数字、下划线、横线、点、斜线）、DIGITS（ASCII数字） |
| required_when | 最多5个条件，满足任一条件则必填并显示；DEVICE仅可引用device_class=I/II/III，DRUG仅可引用drug_sale_class=OTC/RX；不允许循环、自引用或跨类别条件 |

隐藏不会删除已有值；有旧值的隐藏字段在录入页仍显示供核对，服务端仍校验其内容。UNKNOWN在分类必填时视为未填写。旧的待核定分类仍保留，系统默认不追溯推断类别；企业启用分类必填后，后续新建、修订和审核都要求明确分类。现有草稿可以通过修订补齐后再审，配置调整本身不回写历史、不自动撤销已审核档案，也不改变已过账单据。

### 器械注册与备案联动

依据[现行《医疗器械监督管理条例》第十三条](https://www.samr.gov.cn/zw/zfxxgk/fdzdgknr/fgs/art/2023/art_70607fc4160041a383e68ff6bfb2826f.html)，一类器械实行产品备案，二、三类实行产品注册；另参考[《医疗器械说明书和标签管理规定》第十条](https://www.samr.gov.cn/zw/zfxxgk/fdzdgknr/bgt/art/2023/art_0b21c1f7edae42d1a1653a98d28ea99b.html)的名称、型号规格、注册人/备案人及证照编号要求。核对时间2026-10-17。

本版沿用 `approval_number` 保存当前有效的产品证照编号，结合 `category + device_class` 确定语义：药品为批准编号；一类器械为产品备案号；二、三类器械为注册证号。不会创建两个必须同时填写的重复字段，不会把产品备案号混同生产/经营企业备案号。切换备案/注册类别时，网页清空当前表单编号等待重新填写；已分类档案修订若切换两种证照制度却沿用原编号，服务端拒绝提交。旧值仍留在审计和既有单据快照中。

保留原资质核验日期管理，不把一类产品备案解释为统一具有注册证5年有效期。编号格式校验与本地字段完整性不代表监管库验证通过；证照真实性、适用范围、分类目录、特殊产品和完整法规要求仍需后续资质管理与人工审核衔接。

### 执行、权限与并发

新增 `catalog.configure` 仅赋予OWNER、ADMIN，c0017为已有管理员补权并撤销旧权限版本会话，需重新登录。读取元数据需要catalog.read；修改记录仅对具备配置权限者返回。新建商品、合并旧值后的修订、审核通过均执行当前企业规则，不依赖前端显示状态。旧客户端省略专业字段仍保留旧值，但不能绕过新规则；原幂等重放保持原成功结果。

保存设置需要expected_version、修改说明及Idempotency-Key，冲突时拒绝覆盖。按企业+类别使用事务级共享/排他锁，默认记录尚未创建时也参与锁定，避免首次配置与商品提交交错。审计保存前后规则、操作者、修改说明和版本；商品建档、修订和审核记录本次使用的规则版本。仅内置安全验证器，不接受任意代码、SQL、正则或自建循环依赖。


## 编辑草稿（b0029 已实施）

`med.document_draft` 存放采购与批发录入草稿，区别于业务订单的待审核状态。复合主键 `(tenant_id,id)`，FORCE RLS；读取、修改另检查 created_by、channel 对应写权限及 entity_id 授权。每个草稿绑定一个经营主体和单据类型，不能通过更新改变归属。

| 字段 | 含义 / 限制 |
| --- | --- |
| entity_id | 经营主体；与 tenant_id 组成外键 |
| channel | purchase / sale |
| created_by | 作者，草稿仅本人可读写 |
| title | 草稿备注，最多120字符 |
| source_order_id / source_version | 成对为空或提供；改单绑定原单及原版本 |
| content | 有结构的 JSONB 表头和最多50行；行键UUID，数量价格税率以字符串保存不完整输入，允许未确认检索词 |
| version | 乐观并发版本，API字符串；0仅用于首次创建 |
| state | EDITING、CONVERTED、DISCARDED |
| converted_order_id | 转单后原单ID；只在CONVERTED时存在 |
| created_at / updated_at | 创建与最近保存时间 |

草稿保存、放弃及正式转单均走幂等命令。正式创建/改单的可选 editor_draft 参数包含草稿ID与版本；原业务校验通过后，在同一事务中锁定并检查草稿来源、版本和状态，再标记CONVERTED。任一步失败整体回滚。旧客户端省略该参数时保留原有命令指纹；服务端金额、库存、信用及审核规则不由草稿内容替代。


## 个人单据字段模板（b0030）

`med.entry_template` 主键为 tenant_id、owner_id、channel（purchase/sale），使用 FORCE RLS；应用层只按当前登录人查询或写入本人模板。跨经营主体复用同租户内本人的同类模板，不跨租户或账号共享。

| 字段 | 含义 / 限制 |
| --- | --- |
| template | JSONB，schema_version=2；完整8列白名单，列键不重复，总体不超过12000字节 |
| columns[].label / visible / tab_stop | 名称最多30字、显隐、键盘停留；核心字段由服务端约束 |
| columns[].width_mode / width | px：商品220–600、其他90–600；weight：1–20，按剩余空间比例分配 |
| columns[].decimals / grouping | 数字显示小数位-1（保留原始）或0–6、千分位；只用于数量/价格/金额 |
| columns[].wrap / tax_display | 文本换行；税率decimal或percent显示；类型与字段对应 |
| version / updated_at | 乐观并发版本及最近保存时间；请求expected_version=0首次创建 |

GET无模板返回version=0、template=null，客户端使用默认/旧版本地配置。POST写入使用既有CSRF/上下文与幂等机制，不创建业务单、不改变商品资料，不修改输入或提交精度。配置冲突返回TEMPLATE_VERSION_CONFLICT；隐藏/不跳格不免除原业务校验。首版为个人单模板，不包含团队模板或动态业务字段。
