# Python部署与运行手册

版本Python 1.0，日期2026年10月9日。本文规定后续工程的配置、发布、恢复及值班操作。当前交付为技术设计及参考代码，不含可直接部署的应用、真实密钥或完整基础设施。命令中的模块路径是约定入口，须在工程实现后使用。

## 运行环境

生产使用Linux OCI容器。核心API、控制API、业务worker分别构建入口，核心依赖由backend/uv.lock冻结；后续AI与连接器使用独立镜像和锁文件。开发、测试、预生产、生产使用独立数据库、身份客户端、私有桶、KMS密钥和域名。

核心运行时为CPython 3.14标准GIL构建；禁止把文档生成环境使用的Python版本当作生产版本。FastAPI、SQLAlchemy、psycopg、Pydantic、Alembic、Authlib及其HTTP客户端必须完成兼容性验证。每次发布记录Python补丁、uv版本、uv.lock哈希、镜像digest和迁移版本。

配置应按进程最小授权发放。API不获得迁移凭证，AI不获得库存写权限。连接串中有秘密时不得直接输出到日志；秘密轮换采用新连接逐步接替，验证旧连接排空后撤销旧凭证。

## 首次建仓

1. 创建backend/src/medinv包、前端工作区和契约目录；Python配置Ruff、mypy及依赖方向约束，前端开启严格类型检查。
2. 用所选Python补丁生成uv.lock并验证uv sync --locked；注册所有原生依赖的Linux wheel或可复现构建证据。禁止生产运行时现装依赖。
3. 创建业务、控制、身份三个数据库；NOLOGIN owner拥有对象，短期migration角色用于迁移，runtime无owner继承、SUPERUSER、BYPASSRLS、CREATEROLE和DDL。
4. 创建两套Alembic版本链，空库及N减1升级均覆盖RLS、函数、触发器和GRANT。core-reference.sql仅用于隔离空库评审，不能代替完整生产迁移。
5. 初始化服务端会话、CSRF、OIDC state和PKCE；真实角色验证前不开放业务写入。
6. 跑A/B租户及缺上下文测试，验证复用连接与请求异常后没有上下文泄漏。
7. 交付采购入库、预占、发货、付款恢复和账表重算的纵向原型。

## 启动约定

开发可使用uv run uvicorn medinv.entrypoints.core_api:app --reload；生产禁止--reload。单容器单进程时用uvicorn medinv.entrypoints.core_api:app --host 0.0.0.0 --port 8000，由平台控制副本数量。若单容器启多worker，连接预算乘以实际worker数，不能再按单进程算。

业务worker约定python -m medinv.entrypoints.business_worker。它在每个进程中创建Engine，启动前不继承数据库连接。生产运行已构建虚拟环境中的命令，不能靠uv run临时解析或更新依赖。应用启动不自动执行Alembic upgrade。

上游负载均衡限制请求体、连接数、请求期限和上传大小，Uvicorn限制承接并发；仅信任已知代理地址的转发头。readiness验证必要配置、受支持迁移版本及业务库连通；liveness不依赖每个外部平台实时可用。

## 发布流程

发布前完成格式、类型、依赖边界、漏洞、单元、数据库、契约、迁移、E2E及性能回归；确认备份新鲜度、回滚兼容窗口和连接surge预算。生产迁移只由单独作业执行并取得互斥，任何两个发布作业不能并发推进同一版本链。

按expand、backfill、contract推进：先增加兼容结构，再分批回填，确认新旧应用均可运行后灰度。业务worker先具备兼容旧新事件的读取能力，API再产生新事件；删除旧字段或事件版本另开后续发布。大索引与锁敏感DDL单独安排。

灰度先选择试点租户，依次核对登录、租户切换、普通查询、模拟单据过账、幂等查询及Outbox积压。出现跨租户、非法负库存、重复过账、无法解释金额差异立即停止扩量并隔离受影响入口。

应用回退只使用兼容现有结构的旧镜像；已经完成的库存及付款事实不因代码回退而删除。禁止自动alembic downgrade回退生产交易表，优先前向修复和业务补偿。

## Python进程健康与优雅停止

先从负载均衡摘除，再停止接新请求与领取任务。等待已开始的短事务完成，设置宽于事务上限的优雅停止窗口；超时终止后由幂等查询核实结果，不能直接判失败。后台任务停止续租后由下一worker接管。

监控CPU、RSS、线程等待、池等待、SQL及锁耗时、事件循环延迟、进程重启与任务最老龄。长期内存增长需检查未关闭游标、ORM实体堆积、全文件读入、无限缓存及日志队列，不以周期重启作为唯一修复。

扩容前计算所有API、worker、会话、控制面和迁移池，预留滚动发布surge。CPU瓶颈可加进程；锁竞争不可用加进程解决；报表与AI任务优先独立限流，保护在线交易。

## 故障处置

| 现象 | 首要操作 | 恢复证据 |
| --- | --- | --- |
| 扫码变慢 CPU高 | 看线程排队及序列化 profile 暂停大后台任务 | 在线P95恢复 RSS稳定 |
| 连接池等待高 | 检查泄漏 长事务和所有进程预算 | 连接归还正常 无池超时 |
| 热点SKU锁阻塞 | 查询阻塞链及成本池争用 限制相关批量操作 | 流水重算一致 锁等待下降 |
| 付款已确认但销售未完成 | 按原销售和操作ID查询 不重复收款 | 合法完成或退款闭环 |
| 提交时连接断开 | 标记结果待核实 查询永久业务键 | 原动作只有一次事实 |
| worker租约长期不恢复 | 检查RUNNING到期重领及fencing CAS | 接管成功 外部无重复副作用 |
| OIDC刷新竞争 | 停止盲目刷新 检查刷新租约及版本 | 会话可用或受控重新认证 |
| 数据库不可用 | 停止交易写入 前端显示维护 | 恢复并核对不确定提交 |
| Redis不可用 | 查询降级并发受限 敏感限流保守 | 账本正常 无流量雪崩 |
| 数据库迁移中断 | 查看Alembic版本 事务状态和残留索引 | 经评审前向恢复 角色权限通过 |
| 库存重算不符 | 暂停受影响SKU写入 保全证据 | 原因明确 审批修复 零差异 |
| 凭证或密钥泄漏 | 撤销轮换 隔离通道 审计范围 | 无持续越权 新密钥可恢复 |

## 备份与灾难恢复

目标RPO不超过15分钟、RTO不超过4小时，必须演练验证。数据库WAL和全量备份、对象版本与清单、身份映射、配置和KMS恢复材料构成完整恢复集。只恢复数据库而丢失附件密钥，不算恢复成功。

先在隔离环境恢复到指定水位，再只读核对数量、成本、应收应付、处方用量、码持有和审计；补查外部付款、订单及监管回执，使用原业务键重放。记录真正数据丢失窗口和恢复总时长，取得业务签字后切流。

单租户恢复从隔离全库恢复环境提取目标租户及附件引用，停目标租户写入后比对并经审批补偿或迁移。不得把旧快照直接覆盖仍有外部既成事实的生产租户，也不得影响其他租户。

## 营业切换与日常运行

至少两轮旧系统导入演练，统一商品、单位、批号、效期、往来、期初数量、成本和追溯身份。导入按batch及row防重；过账使用受控命令，不绕资质。总量按主体、仓库、SKU和批次分层核对。

切换时锁定旧系统截止水位，冻结旧系统写入，导入增量并指定每个平台唯一发送方。试点保留旧系统只读查询；不得让两系统同时主控同一库存。

每日检查备份、账表重算、已收款未完成、Outbox和回执超时；每周复核权限与支持授权；每月检查版本、依赖、容量和成本；每季度恢复演练。退出租户提供加密导出与清单，留存与legal_hold先于物理删除。
