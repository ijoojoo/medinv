# 界面与日期控件统一改造

实施日期：2026-10-19。依据用户提供的 `codex-ui-date-controls-prompt.md`。本次沿用 Vue 3.5.43、Element Plus 2.14.7、现有业务接口和工作区状态管理，没有数据库迁移、历史日期重写或权限变更。

## 1. 实际修改内容

### 界面方案与公共规范

首轮采用“青碧横栏”。根据同日新增的 `erp-interface-refined.html` 参考与用户反馈，现已扩展为横向/侧栏两种布局，导航改为主题色背景，保留用户的蓝色、青碧、紫色偏好；具体实施与新增接口见第5节。

公共变量位于 `apps/admin-web/src/appearance.css`：

| 约定 | 实施值 |
|---|---|
| 青碧主操作 / 选中背景 | `#087968` / `#E6F3EC` |
| 背景 / 内容表面 | `#EDF3F0` / 白色 |
| 正文 / 辅助字 / 分隔线 | `#243C34` / `#627269` / `#DCE6DF` |
| 顶栏 / 页签 / 控件 | 56 / 42 / 36 px；触屏页签增加操作高度 |
| 页面留白 / 内容圆角 | 16 / 8 px，窄屏留白 12 px |
| 字体 | 正文14、导航15、表格13、标题20、辅助12 px；既有商品固定槽位不变 |
| 浮层 | 外壳100、导航200；对话框、日历沿用 Element Plus 的动态浮层层级 |

应用外壳占满真实视口，`.main-shell` 负责工作区纵向滚动；表格内部负责横向滚动。`ResizeObserver` 测量实际可用高度，录入页扣除真实工具栏空间，避免增加顶栏高度后遮住表尾。菜单和日历浮层不占布局位置。

### 系统导航、页签与页面状态

- `BusinessNavigation.vue` 继续使用原有菜单 ID 和权限过滤。悬停只展开，不切换业务模块；跨模块切换同一浮层；离开约220ms后收起，进入浮层或浮层保有键盘焦点时取消计时。
- 悬停打开后首次点击保持展开，再次明确点击关闭；外部点击、选择功能、Esc、窗口或工作区滚动均按规则收起。触屏点击可操作。支持 Tab、Shift+Tab、Enter、Space 和辅助方向键。
- 工作页签不换行，名称省略、完整标题可查看，关闭按钮独立；未保存状态可被辅助技术识别，激活页签自动滚入可见范围。
- 采购、销售单据详情增加独立的对象页签，身份包含租户、用户、经营主体、单据类型、ID和查看模式。再次打开同一对象激活原页签。新单继续使用服务器草稿 UUID，相互隔离。
- 采购、销售列表与详情分离；未应用的搜索文字、日期原文及错误保留。原有筛选、分页、单据草稿、列配置继续使用原机制。工作区纵向滚动按页签保存，已挂载表格自身保留横向位置。
- 关闭有修改的页面提供“保存后关闭 / 放弃修改 / 取消关闭”。表单经过真实提交处理和命令恢复流程，日期或其他校验失败、接口失败时保持打开；保存过程中不提前清除修改状态。商品配置及主体经营设置以提交时的快照作为保存基线，响应后的新编辑仍保留未保存标记。
- 采购、销售列表增加稳定的标题操作区和明确的查询失败状态；失败时保留上次成功结果，不伪装成空列表。没有生成虚假的业务编号、总数或统计金额。
- 商品品类树、七个固定分组、固定槽位、权限及历史字段规则保留；七个字段组保持挂载，以便保留日期原文和校验反馈。

### 统一日期规则

| 文件 | 职责 |
|---|---|
| `dates.ts` | 纯日期严格解析、真实日历校验、业务时区、日历移动 |
| `DateInput.vue` | 原文输入、确认、错误、中文日历、焦点和键盘 |
| `DateRange.vue` | 复用两个日期输入，结束日期受起始日期约束 |
| `dateControls.ts` | 表单提交前收集所有当前输入，校验成功后提交统一确认的值 |
| `main.ts` | 安装统一提交拦截，配置 Element Plus 中文语言包 |

接受完整的 `YYYYMMDD` 和 `YYYY-MM-DD`，允许两端空格。逐字输入不插入连字符，不截断、不重建输入框。失焦或确认后，合法值变为 `YYYY-MM-DD`；非法输入原样保留并显示中文反馈。

年份遵循现有 Python `date` / API 范围1–9999，拒绝0000；真实天数通过公历闰年和月份天数计算，禁止利用日期溢出容错。纯日期不通过 UTC 或时间戳转换。日期时间字段仍使用原有带时区的接口值，不被改成日期字符串。

组件将原始文本、当前解析结果和错误分开，原文立即进入父表单状态；已保存基线继续由所属业务记录 / 草稿管理。提交入口读取输入框当前文本，先确认整组，再向模型写入本次规范值；不等待 blur、不读取“上次合法日期”。动态商品字段的保存及全页校验还会检查全部分组中的日期值。

查询日期 Enter 触发一次整表查询；编辑日期 Enter 仅确认日期。IME组合输入期间 Enter 不查询、不保存。只读、禁用、必填、min/max、自定义禁用日期共用校验规则。可空字段沿用各接口的省略或null约定。固定有效期证照仍要求两端填写；主数据草稿保留原有允许缺失的规则，但已填日期不能非法。

日历始终中文，周一开头；支持上一/下一月和年、今天、清空、关闭。方向键选日，Home/End定位周首末，PageUp/PageDown翻月，Shift组合翻年，Enter选日，Esc关闭。浏览月份不写值；鼠标离开不自动关闭；选择、关闭和Esc恢复输入焦点。使用 Element Plus Popover 的定位与层级，避免被表格裁剪。

“今天”集中使用 `Asia/Shanghai`。查询仍提交日历日期，后端 `platform/document_query.py` 保持北京时间起始日零点包含、结束日次日零点不包含的语义；因此查询结束日及需转换次日的批次效期保留原有 `9999-12-30` 上限。

### 日期入口全量盘点

所有下列输入原先为原生 `input[type=date]` 或动态日期分支；现已使用公共组件。每行的接口格式均为 `YYYY-MM-DD`，未改后端字段类型。核验状态明确区分真实业务回归与公共组件验证，不能理解为每个字段的每种权限组合都已穷举。

| 页面 / 源文件 | 字段 | 空值、范围及接口 | 接入 / 核验 |
|---|---|---|---|
| 采购列表 `DocumentFilters.vue` | 创建日期从、至 | 查询可单端，空值不传；最大9999-12-30；结束≥开始；北京时间时间戳边界 | DateRange；中英浏览器、两时区、真实请求验证 |
| 批发销售列表 同上 | 创建日期从、至 | 同上，sales-orders查询 | 公共范围组件；列表回归 |
| 零售查询 同上 | 创建日期从、至 | 同上，retail/sales查询；零售业务布局不改 | 公共范围组件；列表回归 |
| `PurchaseDetail.vue` | 到货行生产日期、有效期至 | 每行必填；生产日≤收货日（北京时间今天）；效期≥生产日；效期最大9999-12-30 | DateInput；真实到货保存、非法值无请求验证 |
| `OpeningsPage.vue` | 期初行生产日期、有效期至 | 每行必填；生产日≤今天，效期≥今天且≤9999-12-30；与后端合格期初规则一致 | DateInput；人工期初→独立审核→入库回归 |
| `CreditPanel.vue` | 额度有效期 | 必填，customer-credit原格式 | DateInput；追加空值、非法日期、八位输入及真实授信保存验证；保存期间禁止改动 |
| `CatalogPage.vue` | 往来单位资质生效、截止日期 | 必填，截止≥生效；parties原字段 | DateInput；隐藏分组定位、关闭前保存及真实保存回显 |
| `ProductFields.vue` | 兼容商品资料动态有效期字段 | 依已有字段策略必填和范围规则 | 动态日期分支替换；兼容入口，非当前MDM主入口 |
| `MasterFields.vue` | MDM配置为date的自定义字段 | 草稿可缺失；已填值严格校验；保存null沿用原接口 | 固定槽位适配；全分组保存门禁；三宽度十品类槽位回归；追加未发布配置中的日期预览验证 |
| `ProductCertificates.vue` | 签发/备案日期、有效期起止 | 签发可空；固定有效期模式两端必填；首尾联动；空转null | DateInput；追加当前MDM入口建档→独立核验→修订、日期拦截、取消关闭保留输入及空值落库验证 |
| `FinancePage.vue` | 实际收付日期 occurred_on | 必填，不晚于北京时间今天；cash-documents | DateInput；收付、核销和反向操作真实业务回归 |
| `ReturnRefunds.vue` | 实际退款日期 occurred_on | 必填，不晚于今天；return-refunds | DateInput；追加采购/销售退款真实流程、非法/未来日期零提交、八位日期规范化与保存期间锁定验证 |
| `openingImport.ts` / `OpeningImport.vue` | CSV生产日期、有效期 | 保留原CSV契约YYYY-MM-DD；共享严格解析及北京时间今天 | 解析去掉UTC转换；CSV期初业务回归 |

扫描未发现其他原生日期输入、`datetime-local`、`type=month`或 iframe。编码规则里的 `YYYY / YYYYMM / YYYYMMDD` 是编码组成选项，保留；创建时间、审核时间、流水时间等是只读时间戳展示，保留原精度。质量处置、库存台账及其余现有列表没有额外可编辑日期入口。本轮不建设尚不存在的日期报表页面。

### 后续补充：证照、额度、退款及字典

## 4. 边界与剩余问题

- 项目没有 iframe，本项为“不适用”；没有声称改造外部系统页面，也没有引入 postMessage 协议。
- 日期控件已接入上述现有入口；额度有效期、证照核验、采购/销售退款主要流程已有真实验证，未穷举全部业务分支和权限组合。自定义日期验证限于未发布配置预览，见清单核验范围。
- 已有多步骤导入、关系选择等未构成单一可提交表单的编辑，关闭时选择保存会要求先完成当前操作；不代替用户猜测发布、导入或关联决策。普通资料、单据草稿、单一业务表单支持保存后关闭。

- **单位检索**：独立采购/销售编辑页、已有单据修改入口、客户信用账户、缺货补货供应商，以及更多条件均使用 `PartyLookup.vue`。按名称、编码、统一信用代码、许可编号检索；每页20条；上下键选择、Enter确认、Esc关闭。修改名称后立即清除旧ID，慢响应不得覆盖新输入；失败保留文字可重试。业务保存仍由原接口核验资格和权限。
- **字典控件**：Element Plus Autocomplete的外层wrapper承担边框和聚焦提示，内部input移除边框/阴影，涵盖普通、聚焦、禁用状态。上市许可持有人、生产企业、批准/注册/备案信息继续支持直接输入和保存时补充字典，不改变其数据管理规则。

## 6. 紧凑日期下拉与库存 / 质量查询（2026-10-19）

按用户反馈，快捷日期由整排按钮改为同一查询行中的原生下拉框。保留原有 14 种范围，以及“自定义日期”选项；支持键盘方向键选择、Tab 移动。选择范围只填入日期，点击查询或在查询输入中按 Enter 才发出请求。手工修改日期后显示自定义范围；选择快捷范围会同时替换日期框中未通过校验的原始文本，避免旧错误残留。清除筛选恢复“不限日期”。

取消原快捷按钮行及常驻日期说明行；北京时间说明放入控件提示及展开条件内。在 1440px 横向工作区，采购查询可保持单行；850px、480px 自动换行，不裁切日期框或操作按钮。采购、销售及既有零售查询复用该组件，未改动零售收银流程。
