# 岗位分工与业务交接

日期：2026-10-16。版本0.24，业务库b0026、控制库c0016；新增三类退货岗位交接。末尾正常业务验收结果保留原交付基线，退货新增范围见 [退货岗位交接](退货岗位交接.md)。

## 配置岗位

企业所有者或有权限的管理员进入“设置 → 成员与权限”，选择已有成员，编辑角色及经营主体范围。新增采购员、仓储员、销售员、收银员四种角色；现有质量审核员、财务人员继续沿用。

| 岗位 | 可办理的主要业务 | 交给其他岗位的操作 |
| --- | --- | --- |
| 采购员 PURCHASER | 商品及往来单位建档、更正；采购制单、改单、关闭余量；采购退货申请及未交接取消；查看采购与批发订单 | 资质及采购审核、到货登记、验收、入库、收付款 |
| 仓储员 WAREHOUSE | 采购到货登记及拒收交还；批发拣货；客户退回品隔离收货及交还；期初录入、实盘；调拨申请/发出/收货、同仓移库；质量处置及在途损失申请 | 采购/销售/退货制单、审核、验收、复核；期初/盘点/质量过账及批发出库 |
| 销售员 SALES | 批发制单、改单、关闭余量及分配发货；批发退货申请及未交接取消；查看销售及采购、查询关联补货需求 | 客户授信、订单审核、生成采购、拣货、复核、出库及收付款 |
| 收银员 CASHIER | 普通器械及OTC零售建单、现金收款/找零、交付出库、取消未收款单；零售退货申请及未交接取消 | 采购/批发、隔离收货、资金账户管理、财务核销及现金退款 |
| 质量审核员 QUALITY（原有） | 资质审核、采购/销售审核、到货验收、合格入库、出库复核及过账；期初/盘点/调拨/质量审核等 | 制单、收货、拣货及资金操作 |
| 财务人员 FINANCE（原有） | 实际收付款登记、核销及更正、按原款项退款 | 商品库存业务写入、资金账户建立及客户授信 |

初次使用由所有者建立资金账户、核定客户授信；采购员准备商品和往来单位，质量审核员独立核对。所有者与管理员仍保留原有完整能力，原“业务操作员”也保留原权限。c0016为已分配四种新岗位的成员补充退货读取与对应岗位操作权，撤销旧会话；不改变角色、主体范围或启停状态，升级后重新登录。

可以组合岗位，权限取并集。若希望把原操作员改为专职收银员，应移除“业务操作员”后仅保留“收银员”；仅追加新岗位不会收回原权限。权限变更提升成员版本并撤销原会话，成员重新登录后生效。制单人不能审核自己经办的单据、拣货人不能自行复核等原业务规则仍然执行。

角色控制业务操作及现有模块读取权限，范围仍为企业和经营主体；不提供按个人单据、仓库、现金账户或价格/成本字段的独立可见性控制。四个新岗位都有库存及基础资料读取权；采购/仓储/销售因交接需要可读采购或批发相关信息。不可把岗位角色等同于价格保密或个人销售数据隔离。

## 日常交接顺序

1. 采购员完成采购单。质管在工作台“采购待审核”进入原单审核；仓储员在“采购待收货”登记实际到货及批号效期；质管从“到货待验收”和“合格待入库”继续验收与过账。
2. 销售员完成批发单。质管审核，销售员分配发货；仓储员从“发货待拣货”核对实物；质管从“发货待复核”和“发货待出库”继续复核与过账。
3. 收银员在零售页开单，核对现金实收及找零，再核对批号数量完成交付。收银不需要财务核销权限；已收款未出库的单据可从工作台继续交付，退款交财务或具备退款权的管理员。
4. 财务在“往来结算”核对采购应付和销售应收，登记实际款项后再核销；登记款项本身不会自动清账。

工作台仍按有权读取的业务显示企业待办，可能包含需要另一岗位办理的环节；从原单查看进度和交接。按钮和后台命令分别核验操作权限。本轮没有新增个人派单、待办认领、人员排班或自动分配。

三类退货由采购、销售、收银分别从原单发起；客户退回品由仓储登记隔离收货与交还，质管独立复核及过账，财务撤销必要的原核销并登记原账户退款。采购退货由质管复核后核对实际交接并出库；当前没有新增独立采购退货发运单。小团队可组合岗位，但制单人、收货人不能同时复核同一笔退货。

库存差异从工作台继续交接：运输短少和自有隔离品处置各增加待审核、待过账/核销入口，父调拨收齐后遗留损失仍可核对取消。仓储申请、质管独立复核过账，盘点结单后才解除冻结。完整办理顺序见 [库存岗位交接](库存岗位交接.md)。

## 本机体验

完整验收企业：**试用岗位企业-e9079735**。账号与岗位如下，均使用独立身份及独立会话：

| 账号 | 岗位 |
| --- | --- |
| demo.owner | 企业所有者，初始配置和成员管理 |
| demo.purchase | 采购员 |
| demo.warehouse | 仓储员 |
| demo.quality | 质量审核员 |
| demo.sales | 销售员 |
| demo.cashier | 收银员 |
| demo.finance | 财务人员 |

登录后选择上述企业。密码只保存在本机 `.cache/演示账号.md`，不同岗位请使用独立浏览器会话。本轮新账号只加入独立岗位验收企业，不自动加入原两家演示企业。

已有开发环境准备新增演示身份时，按顺序执行：

```text
backend/.venv/Scripts/python.exe scripts/prepare_identity.py
backend/.venv/Scripts/python.exe scripts/seed_demo.py
backend/.venv/Scripts/python.exe scripts/sync_demo_identity.py
```

该流程只针对本机固定演示账号，保留已有密码、成员角色和库存；为新岗位建立身份映射，不自动授予企业成员关系。新企业仍使用 [企业开通与开账](企业开通与开账.md) 的明确清单加入成员。部署本轮代码后需重启认证和核心服务，使角色目录一致。生产账号开立与企业自助邀请不在本轮范围。

开发验收入口：`pnpm --dir apps/admin-web run test:handoff`。每次创建一个独立测试企业，七个真实登录账号协作，业务通过原页面或正式HTTP命令办理，未直接写入业务数据库。结果及截图在artifacts目录，测试企业保留供查看。

## 验收结果口径

| 节点 | 库存数量 | 库存成本（元） | 应收未结（元） | 应付未结（元） |
| --- | ---: | ---: | ---: | ---: |
| 采购10件，含税单价13元，税率13% | 10 | 115.04 | 0 | 130 |
| 批发4件，含税单价20元 | 6 | 69.024 | 80 | 130 |
| 零售2件，现金50元、找零10元 | 4 | 46.016 | 80 | 130 |
| 财务收款80元/付款130元并核销 | 4 | 46.016 | 0 | 0 |

库存成本按原批次成本精度核对，不能把每条成本先截成两位小数再汇总。采购、收货、销售记录分别保留采购员、仓储员、销售员身份；关联待办结清。还验证采购员不能审核资质、仓储员不能审核采购/创建销售/自行复核、销售员不能拣货、收银员不能读取财务往来或管理账户；更改收银角色后，原核心会话返回401。最后恢复收银员角色供本机体验，仍须重新登录。

测试范围、数量和部署结果见 [岗位协作验证](岗位协作验证.json)。本场景的4个余额核对节点计为1条业务浏览器用例。
