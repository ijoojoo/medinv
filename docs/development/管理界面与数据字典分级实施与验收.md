# 管理界面与数据字典分级实施与验收

日期：2026-10-21。版本：0.29.0；业务迁移 b0049；控制迁移 c0017。按用户本次提出的导航、资料、设置、审批设计、消息及质量分类要求实施，优先于原计划 N07。

## 1. 可用入口及实际行为

| 入口 | 本次实现 | 使用边界 |
| --- | --- | --- |
| 采购 → 采购入库 | 去掉指向同一工作区的重复菜单；订单、收货、验收、入库保留为工作区内环节 | 原单地址、权限和办理动作继续有效 |
| 销售 → 销售出库 | 共用工作区名称，继续办理订单、分配、拣货、复核、出库 | 零售收银仍单独保留 |
| 资料 → 往来单位 | 与商品资料一致的左侧分类、摘要、页签和维护区域；供应商、客户、供销双向分类；供应商/客户信息卡 | 复用机构、主体范围、多证照、审核和修订逻辑；没有重建或合并旧档 |
| 资料 → 商品档案 | 增加商品信息卡，展示已保存身份、生产与资质、经营信息；旧档原始记载单独展示 | 信息卡不代表资质核验通过；未保存表单不冒充已保存资料；完整证件仍从质量管控读取 |
| 资料 → 职员资料 | 编码、姓名、分级部门、岗位、联系信息、入离职日期和状态；查询、分页、修订、版本及历史 | 职员档案与登录账号授权分开；不包含人事、考勤和薪酬 |
| 设置 → 企业设置 | 按基础资料、采购与销售、仓储与质量、财务结算、人员与权限、消息与提醒、系统级设置分组 | 已有配置链接到原维护功能；提醒参数可真实保存并生效；系统管理独立页面按用户要求后置 |
| 设置 → 审批流设计 | 保存业务类型和 1—10 个顺序节点，节点名称、审核角色、或签/会签，添加、删除、上移、下移和历史 | **当前保存设计稿，不接管现有单据审批**；运行实例、任务分派、条件分支、发布绑定及撤回转办继续后续实现 |
| 消息 → 消息和提醒 | 权限内业务待办、单位资质到期、养护到期三类；个人已读、刷新、分页、原业务入口 | 待办可进入具体原单；资质/养护进入相应模块；已读不等于任务已完成；没有邮件、短信或外部推送 |
| 质量 → 质量处置 | 原隔离库存处置，加商品停售/解除停售；按经营主体保存原因、版本和审计 | 质量停售独立于普通经营“允许销售”；资料维护不能解除质量停售；解除后仍须满足其他准入条件 |
| 质量 → 质量台账 | 首个台账为商品养护：商品、批号、日期、类型、人员、检查情况、异常说明、下次日期、草稿/完成/作废 | 完成后不改写内容，只能留痕作废；不修改库存、成本或购销状态；异常若需停售须另做质量处置 |

所有新增写入沿用真实后端、版本冲突、幂等和事务提交，没有使用浏览器本地存储模拟业务成功。新增台账和设计页面保留未保存离开提示，失败保留当前内容。

## 2. 数据字典设计与兼容

“商品字典”统一改称“数据字典”。按用户提供的 HTML/CSS 和设计说明实现一级分类侧栏、二级字典页签、来源标签、状态开关、计数、紧凑表格、编辑抽屉、页脚保存、局部筛选和 Ctrl/Cmd+K 全局查找。搜索结果能定位字典与对应行；窄屏侧栏转为横向分类，表格在自身区域滚动。

七组为商品资料、采购供应、销售运营、仓储物流、质量合规、财务结算、系统与对接。原 12 个字典全部保留；新增供应商等级、客户等级、配送方式、结算方式、职员部门、职员状态、养护类型，共 19 个定义。部门是树形字典，职员状态是系统标准只读字典，其余按系统与企业扩展或企业自定义管理。

- 字典定义和分组来自版本化服务端配置，不在本轮开放任意新增字典定义、修改系统状态或生成业务字段。部门已接职员、养护类型已接台账；供应商/客户等级、配送/结算方式本轮建立选项基础，尚未全部绑定交易字段。
- 在原字典 JSON 中追加 `id/code/description/parent_id/origin/is_default`。未增加一套平行字典值表。旧项未保存元数据时，以租户/系统范围、字典键、**完整原值**生成稳定 UUID5；系统项身份共享，企业扩展隔离。首次保存写入元数据，历史交易文本不重写。
- 字典值名称与已保存编码/身份不允许修改或删除；允许修改说明、启停及合法排序。新增尚未保存的行可移除。停用保留历史文字，后续选项只返回启用项。旧客户端省略元数据时保留原字段，避免覆盖丢失。
- 系统标准由后端拒绝企业修改；前端只读不是唯一保护。系统/企业来源由服务端计算，不信任客户端标签。
- 部门父子必须属于同一字典，拒绝自引用、循环、超过五层以及停用父级下的启用子级；同级排序，不能用排序改变父子关系。
- 采购审核及三类验收用语使用显式默认项。首次兼容旧配置时从原首个启用项确定默认；保存后排序不改变默认，禁止缺失、多个或停用默认项。原采购结论读取也已改为明确默认项。
- 引用数统计当前商品、往来单位或规格资料的实际精确值引用，按字典批量查询。界面注明**不含历史快照**；未支持统计的字典显示“未统计”，不显示伪造的零。该数字不是全系统删除判据，已保存值仍一律保留。
- 全局搜索在服务端当前租户范围内执行，最多返回 50 项；各下拉在聚焦和字典保存后刷新启用选项，不改写用户已填值或历史值。保存需变更原因、预期版本和幂等键；冲突保留草稿，由用户重新核对。

参考文件在本轮开始时已读取；后续原路径已无法访问，因此本轮完成的是依据已读取设计结构及样式的实现与新页面视觉检查，没有完成对原 HTML 渲染截图的逐像素比对。

## 3. 设置、消息及质量执行口径

企业设置中的 `reminders_enabled` 控制消息提醒汇总；`work_queue_enabled` 控制业务待办是否进入消息页；证照/养护提前天数均为 0—365，按当前经营主体生效。关闭汇总不关闭原业务工作台。商品字段、准入规则、仓库、成员权限等保留原有配置范围和权限，通过设置页统一查找。

资质提醒读取本主体未停用、固定有效期的往来单位证照，包含已过期项；未核验记录也可能提醒，不表示许可有效。养护提醒读取每商品和批号最新已完成记录的下次日期；没有下次日期不生成提醒。时间口径使用北京时间。读取标记按账号和消息身份保存，其他人员的未读状态不受影响，底层事实更新会产生新的消息身份。读取标记只查询当前页，避免无限加载历史已读项。

质量停售修改独立 `quality_stopped` 标记，保留普通 `enabled/purchase_enabled/sales_enabled` 及其他经营参数。批发/零售共用销售准入检查，公共库存预占在商品共享锁内重验。测试直接覆盖新销售、分配、已复核出库、公共预占、普通资料写入不能绕过和解除后继续出库。已经成功提交的幂等重放继续返回原事实；解除停售不自动复活取消单据或解除其他质量/资质限制。

审批设计使用顺序节点，节点身份不可重复，支持 QUALITY/ADMIN/OWNER 角色和 ANY/ALL 设计属性。现有独立复核规则仍是实际执行来源；启用自定义运行流前，必须补齐发布版本、业务绑定、禁止自审、节点人员快照、幂等推进和撤销并发规则。

## 4. 数据与权限

`b0048` 扩展字典键约束并新增 `med.management_record`，保存职员、企业设置、审批设计、养护台账和个人已读标记。按租户、主体、记录种类、业务键唯一，强制租户 RLS，关联真实经营主体，严格 DTO 校验，运行角色仅 SELECT/INSERT/UPDATE。业务记录有版本、创建/修改人、时间和审计前后值。

`b0049` 只向 `med.product_entity_settings` 追加 `quality_stopped boolean NOT NULL DEFAULT false`；不将现有经营停用自动推断为质量停售。业务库强制 RLS 表增至 96，核心 OpenAPI 路径增至 180，控制库仍为 c0017。

| 功能 | 读取权限 | 写入权限 |
| --- | --- | --- |
| 字典、商品/单位信息卡 | catalog.read | 字典 catalog.configure；信息卡无写入 |
| 职员 | members.read | members.manage |
| 企业提醒设置 | catalog.read | catalog.configure |
| 审批设计 | catalog.configure | catalog.configure |
| 养护台账、验收记录 | quality.read | 台账 quality.write；验收记录无写入 |
| 商品停售 | quality.read + 商品资料读取 | quality.review |
| 消息已读 | tenant.read + 对应来源权限 | 仅个人读取标记，不能确认业务完成 |

经营主体授权和租户隔离仍由后端检查。前端菜单过滤仅改善使用体验。
