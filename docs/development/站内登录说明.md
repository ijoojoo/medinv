# 站内登录说明

打开 `http://127.0.0.1:5173/`，直接填写“企业账号”和“密码”，点击“登录工作台”。不再需要进入独立的 Keycloak 页面；登录、重试和退出都保持网站地址与统一样式。

原有账号、密码、企业成员身份和角色权限沿用。开发演示使用 `demo.owner`、`demo.quality`、`demo.viewer`；密码仍在本机忽略文件 `.cache/演示账号.md` 中，本文不复制密码。账号密码错误时在表单提示；账号未加入企业时显示登录未完成，并提供重试入口。

## 旧工作区升级

停止认证服务，依次执行以下操作。保留数据库及 Keycloak 数据卷，不重新初始化数据：

```text
backend/.venv/Scripts/python.exe scripts/prepare_identity.py
docker compose --env-file deploy/.env -f deploy/compose.yaml up -d keycloak
backend/.venv/Scripts/python.exe scripts/wait_http.py http://127.0.0.1:8080/identity/realms/medinv/.well-known/openid-configuration
backend/.venv/Scripts/python.exe scripts/sync_demo_identity.py
```

先启动或重启管理端 `pnpm --dir apps/admin-web dev`，确认同源 discovery 可访问，再启动认证服务 `backend/.venv/Scripts/python.exe scripts/dev.py auth`。其余核心 API 和预占回收服务按 README 启动。

同步脚本只处理三个本机演示账号，验证对应关系后更新身份地址；有变化账号的旧会话会被注销，需要重新登录。重复执行不会注销映射未变的账号，也不会重置密码或修改业务数据。无需新增数据库迁移。

首次安装仍按 README 完成环境、数据库迁移和演示数据初始化；上述升级步骤不能替代完整安装。

## 开发与排查

- 业务访问始终使用 `127.0.0.1:5173`。不要混用 localhost、8080 或其他端口。
- 修改主题配置后，需要重建 Keycloak 容器或重启服务；旧 realm 的主题设置通过同步脚本生效，单独修改导入文件不会更新已存在的 realm。
- 认证服务启动失败时，先检查管理端代理和 Keycloak；现在 discovery 使用网站内的 `/identity/realms/medinv/.well-known/openid-configuration`。
- 身份服务管理控制台仅在本机 `http://127.0.0.1:8080/identity/admin/` 可用，业务用户无需访问。网站的 `/identity/admin/` 和 master realm 返回 404。
- 登录页面仍由 Keycloak 原生认证模板处理，业务服务只接收授权码；账号密码不会另存进业务数据库。详细设计见 [ADR 0022](../adr/0022-站内统一登录与同源身份入口.md)。

本次交付不更改进销存业务版本和数据库结构；继续在 0.24 主线上推进。
