# 进销存本机试用部署

本包将已完成初始化的进销存环境交给 Docker 统一运行。页面、业务、认证和预占回收不再需要四个终端；采购、批零、退货、库存和结算仍使用现有业务接口及数据库。本机入口固定为 `http://127.0.0.1:5173`，账号、企业和数据沿用原环境。

当前是单机试用包，采用本机 HTTP、Keycloak start-dev 和本机配置文件，不是可直接开放公网的生产 SaaS 部署，也不是包含业务数据的备份。当前交付版本为0.28.0，业务链b0047、控制链c0017，始终以 `deploy/trial/compatibility.json` 为准。原部署工具初次验收在b0026/c0016完成；历史同主机恢复及原单续办已另有记录，N06结构化规则与本次部署验收见[结构化准入验收](结构化经营范围与交易准入实施与验收.md)；0.27.0附件恢复专项结果见[私有附件验收](私有附件服务实施与验收.md)，跨机器恢复和全业务连续恢复仍按后续计划验收。

## 前提与首次切换

- Docker Engine 与支持 `env_file.format: raw`、`up --wait` 的 Docker Compose；本机验证版本为 Compose 5.1.0。
- 管理命令需要 Python 3.11 以上，只使用标准库；业务运行在镜像中的 Python 3.14.8，不依赖主机虚拟环境。
- 已按根目录 README 完成数据库、身份及成员初始化，保留原 `deploy/.env`、`.cache/keycloak/medinv-realm.json` 和 Docker 数据卷。已有数据库不能重新生成密码或会话加密密钥。
- 从源码构建还需要 Node.js 24、pnpm 11 及锁定的前端依赖；从交付包加载镜像不需要这些构建工具。
- 构建时需要访问镜像仓库；交付包含 core/web 两个应用镜像，PostgreSQL、Keycloak 基础镜像须另行准备。若本机配置指定自定义 Keycloak 镜像，应先在目标机器准备相同镜像。本包不宣称断网安装能力。

首次切换先保存当前作业，再停止原开发环境的 Vite、核心 API、认证和 expiry 进程。工具发现 5173、8000、8001 被其他进程占用会退出，不会强行终止它们。数据库和 Keycloak 可以继续运行，统一工具复用 `medinv-dev` 项目及其数据卷。

Windows 在项目根目录执行（`python` 不在 PATH 时替换为 `backend/.venv/Scripts/python.exe`）：

```text
python scripts/trial.py build
python scripts/trial.py check
python scripts/trial.py start
python scripts/trial.py status
```

`check` 需数据库已经运行，只读检查密钥格式、源码和镜像指纹、端口及两条数据库版本。数据库已停止时直接使用 `start`，它先启动数据库，核对版本后再启动应用。版本不符时退出，不自动迁移、补种演示数据、重置密码或删除数据。

`start` 生成私有运行配置到 `.cache/trial/`，业务容器仅接收业务/授权读取账号，认证容器仅接收认证库账号及身份密钥，不传入数据库所有者、迁移或 Keycloak 管理员密码。该目录及 `deploy/.env` 应按本机凭据文件管理，不可提交或发给试用客户。

## 日常启动、停止与检查

```text
python scripts/trial.py start
python scripts/trial.py status
python scripts/trial.py stop
```

停止会依次停止应用和数据库等六个服务，保留容器、数据卷、配置和构建清单。再次 `start` 使用原数据继续运行。不要使用带删除数据卷参数的清理命令。

状态检查包括页面、业务两库连通、认证库连通、身份服务元数据和六个容器状态。预占回收目前检查进程正在运行，不代表每次扫描都成功；实际回收行为沿用既有专项验证。启动失败时检查 `.cache/trial/last-operation.log`，工具会隐藏已知密钥及数据库连接串；该文件仍按内部运维资料保存。

| 用途 | 地址或方式 |
| --- | --- |
| 管理页面、站内登录及业务 | `http://127.0.0.1:5173` |
| 页面检查 | `http://127.0.0.1:5173/health/web` |
| 核心服务及两库连通检查 | `http://127.0.0.1:5173/health/core` |
| 认证库连通检查 | `http://127.0.0.1:5173/health/auth` |
| 本机身份管理，仅运维使用 | `http://127.0.0.1:8080/identity/admin/` |
| 本机数据库，仅运维使用 | `127.0.0.1:55432` |

试用容器模式不在主机开放 8000/8001，原两个 API 文档地址只适用于开发模式。需要回到开发模式时先执行 `trial.py stop`，然后按 README 启动数据库、身份和四个开发进程；两种模式不要同时启动。

## 构建与交付

业务或页面源码改变后必须重新 `build`，不能仅重启旧镜像。每次构建保存源文件 SHA-256、应用镜像 ID 和数据库兼容版本到 `.cache/trial/release.json`，启动会再次核对。源文件改变、镜像被同名替换或版本不匹配均拒绝启动。

```text
python scripts/trial.py build
python scripts/trial.py package --output outputs/releases/medinv-trial-0.26.0-20261020.zip
```

导出到一个尚不存在的新文件名，不覆盖旧交付。ZIP 包包含应用镜像 `images.tar`、构建清单、所需源码/迁移/部署脚本、接口契约及操作说明；旁边生成 `.sha256` 校验文件。不包含本机密码、会话密钥、身份导入文件、数据库、浏览器会话或测试缓存。历史验证 JSON、截图和测试报告留在开发工作区，不随交付包分发。

0.26.0增量见[往来单位多证照与授权验收](往来单位多证照与授权实施与验收.md)。2026-10-20 的0.25.0源码基线、测试结果及本地交付包索引见[当前版本收尾与交付基线](当前版本收尾与交付基线-20261020.md)。本地 Git 提交与包校验值分别记录，交付包不包含 `.git`；其 `.delivery.json` 侧车文件将源码提交、镜像、迁移和包SHA-256关联。

接收方先使用可信渠道取得的校验值核对 ZIP，再解压到专用目录：

```text
python scripts/trial.py load
```

`load` 核对源文件及 `images.tar` 指纹后导入两个应用镜像，再核对镜像 ID；不操作数据库。SHA-256 用于核对完整性，不是发布者数字签名。

接收方需要另行完成或恢复已有数据库和身份配置，核对原密钥及上述版本后，才能 `check/start`。README 的“安装与升级”是工程初始化流程，会建立演示资料；建立实际空白试用企业应按[企业开通与开账](企业开通与开账.md)，不要复制演示库存。本包尚无“一键初始化全新客户环境”或自动升级功能。

## 实现边界

`deploy/compose.trial.yaml` 叠加原基础配置。Nginx 提供构建后的静态页面和同源 API 代理。业务、认证及回收容器共享页面容器的网络命名空间，使认证服务可访问既有回环 issuer，保持原 OIDC 发行者和端点核验；该布局只适用于当前固定单机地址，不是多节点扩容方案。

四个应用容器以非 root 用户、只读根目录运行，临时文件进入内存临时目录，禁止提权并移除额外能力。页面代理只开放应用 realm 和主题资源，拒绝身份管理入口、其他 realm 及路径编码绕行；本机 8080 管理入口继续供运维使用。请求访问日志关闭，避免身份回调参数进入访问日志。数据库及 Keycloak 基础服务仍沿用原开发配置。

应区分“停止后再启动原数据卷”和“从备份重建环境”：本篇初次部署验证只覆盖前者。后续已完成同主机独立卷恢复及原单续办，见[备份恢复与原单续办](备份恢复与原单续办.md)。跨机部署、生产 HTTPS、凭据托管和容量验证尚未交付。

## 0.27.0 私有附件的数据位置

原件文件存放于业务库的 `med.catalog_attachment.content`，随业务库备份与恢复。重建应用容器或解压交付包不包含、也不会覆盖原件数据；不要把交付 ZIP 当作数据备份。现有 `scripts/recovery.py` 的加密三库备份覆盖附件与关联历史，解包总量仍限制为256 MiB。附件较多时应先规划专用备份设施。
