# 统一单据明细列配置实施与验收

日期：2026-10-20。以用户提供的统一列配置方案为设计基线，采用方案 A 的整表明细与统一配置入口。范围为采购四环节的录入 / 办理及历史查看，共八个场景。销售沿用原个人录入模板，零售内部界面不变。

## 修改内容

### 操作与页面

采购订单新建 / 修改继续使用独立工作标签、编辑草稿和原多行录入表。点击“字段设置”进入“配置单据明细列”：左侧按来源或已选字段检索，右侧调整选中列。支持显隐、拖动和前后移动、别名、固定像素 / 剩余空间比例、显示小数位、千分位、文本换行、税率小数 / 百分比、录入回车停留。只读字段不参与停留，商品与数量保留基本连续录入停留点。固定宽度90–600像素，商品列至少220；比例1–20。

采购订单详情、到货记录、验收记录和待入库 / 已入库明细使用共享 DocumentLineGrid；保留来源联查、审核历史、状态和原操作按钮。到货、验收办理改为宽表明细，仍使用原业务提交接口及职责分离；入库为核对合格结果后过账，不新增可改数量。

录入与查看分别保存配置。需要同步时，在目标配置中点击“从录入配置复制”或“从记录查看配置复制”，核对后保存；仅复制适用字段，自动保留目标必填列，不修改来源配置。配置未保存时关闭、取消、Esc 或恢复默认后取消均不应用。关闭后焦点回到入口。保存响应中断可继续按原请求和幂等键确认，另一个窗口修改会提示重新读取。

到货日期继续使用统一 DateInput，支持 YYYYMMDD / YYYY-MM-DD，非法日期不能提交；回车在有效日期确认后进入下一个停留字段。隐藏字段不清除业务值；必填录入列不能隐藏；后台业务校验及数量、价格、包装换算规则保留。

明细“导出当前视图”导出当前可见列、排序、名称和格式；只导出已授权读取的行，保留历史缺失状态说明，并沿用 CSV 公式注入防护。采购录入原“完整明细”导出 / 导入继续保留，两者含义不同。此版本不增加正式单据打印或完整凭证导出接口。

### 配置与数据接口

新增 GET / POST `/api/v1/document-columns/{stage}/{mode}?entity_id=...`。stage 为 orders / receiving / inspection / posting；mode 为 editor / view。读取返回字段目录、规范化列配置、配置版本及兼容提示。写入只接受显示属性，schema_version=1，expected_version 作乐观锁，Idempotency-Key 用于结果不明重试。

配置表主键：tenant_id + entity_id + owner_id + document_type + mode，强制 RLS。读取 / 保存均要求当前主体 purchase.read；保存个人显示偏好不授予制单、验收或入库权限。未自定义时采用系统默认；采购录入优先继承旧服务端 entry_template，没有旧服务端配置时可读取本浏览器旧设置，明确提示后由用户保存到服务器。销售旧配置不覆盖。未知字段读取时过滤并提示，提交未知或重复字段直接拒绝。当前没有可供继承的企业模板管理模块，本次不新增企业模板发布流程。

现有 GET `/api/v1/catalog/entry-products` 的 purchase 通道新增受控 document_values / document_status；订单详情新增相同投影。不会根据数据库列或任意 MDM JSON 自动开放字段。只开放采购读取权限下的商品身份与单据字段，未开放主档保密 / 运营字段；所有 SQL 投影与稳定键由服务端白名单指定。

新增 purchase_order_line.document_snapshot，在订单正式创建、修订生成新行时同事务留存商品名称、编码、规格、组织角色、业务证件编号、主数据与规则版本等。采购四环节展示同一订单行留存的商品身份；批号、生产日期、有效期及环节数量来自实际到货 / 验收 / 入库事实，不从商品主档取批号。订单修订历史保留原留存值。原过账库存、成本、应付和幂等处理不变。

历史记录没有快照时显示“历史未留存”，不以当前主档冒充历史。已留存但空白显示“未维护”，类别不适用显示“不适用”；没有提供某环节字段时不合成业务事实。历史验收明细不提供实时待验余额列，办理验收时仍显示待验数量。数量单位明确区分交易单位与基本单位。监管主体共用一个逻辑字段，按主数据中的品类、监管子类型和器械类别选择真实角色；生产角色独立，业务证件不展开成额外商品行。

## 2026-10-20 补充：主数据同义字段统一

### 统一字段与配置兼容

此前单据目录错误地将 `regulatory_subject` 对应的三个角色拆成 `authorization_holder`、`registrant_name`、`filing_holder`。现在八个采购场景统一为 `regulatory_subject`，默认名称“持有人／注册人／备案人”。字段检索输入持有人、注册人或备案人均找到同一项。创建、记录查看、复制配置及当前视图 CSV 共用同一稳定键。

旧配置读取时转换，不直接改写数据库或提升版本。若原三列中有可见列，继承第一项可见列的位置、宽度、换行设置；全部隐藏则继续隐藏。旧系统默认名称换为统一名称，自定义名称保留。若已有明确的新字段配置，则以其设置为准，不被残留旧字段重新打开。保存后仅留一个规范字段，旧页面提交的三个旧键也可合并。其他未知键、重复原键、非法宽度、必填隐藏仍按原规则拒绝，原租户/经营主体/账号隔离、乐观锁及幂等控制不变。

### 取值与历史

新建采购订单的 `document_snapshot.schema_version=2`，保存统一名称、当前角色、对应组织 ID/名称/角色集合、监管子类型、原主数据版本和规则版本。取值调用商品主数据已有 `regulatory_role`，覆盖药品及适用的饮片、器械、保健食品、特医食品、婴配乳粉、化妆品。普通饮片、普通食品、日用品、服务等按当前主数据规则不适用时显示“不适用”；尚未确定必要类别且没有名称时提示“待明确类别”。不会以生产企业代填。

旧 v1 快照仅从已经记录的名称映射：药品持有人、二三类器械注册人、一类器械备案人。旧产品表本来以 `registrant_name` 共用注册/备案名称；在没有新版主档标记、且 v1 的备案列为空时，允许使用同一旧快照已经保存的这个名称。新版主档快照缺少备案人时，不以其他角色替代。其他品类若旧快照未保留对应主体，显示“历史未留存”。旧快照无副作用读取，不批量改写，不查询当前企业名称补造历史。

### 历史、权限与多行性能

采购和销售新建/改单时写入 `schema_version=3` 的 `document_snapshot`，保存显示值、缺失/不适用状态、字段权限及既有监管主体来源信息。记录查看、采购后续环节及导出使用制单快照。旧 v1/v2 或尚无快照的字段显示“历史未留存”，不从今天的资料补写。销售改单形成新版本并重新采集资料，原版本快照留在已有审计证据中。

新增字段须满足当前资料读取权限；快照记录的较严权限也继续生效，旧快照较宽权限不能绕过当前较严权限。原核心单据白名单仍按单据读取权限显示。未经权限过滤的原始快照不直接返回详情或审计历史接口。

商品关联数据按产品集合读取，不因多张证件/多个条码扩大单据行数。恢复草稿/改单时，同一编辑器中的重复商品共享正在进行的读取；读取完成即释放，不跨主体、权限上下文或以后打开的单据长期缓存。加载期间保存按钮暂不可用并显示“正在读取商品资料”，完成后恢复，防止快速提交被定位到尚未加载的行。
