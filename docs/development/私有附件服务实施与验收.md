# 私有附件服务实施与验收（N05）

更新日期：2026-10-21，北京时间。应用 0.27.0，业务库 b0046，控制库 c0017。

## 交付范围

商品和往来单位共用私有附件服务。商品从“商品档案 → 维护 → 证件详情与核验 → 维护本商品发起的证件原件 / 核验”进入；往来单位从“资料详情 → 质量管控”进入。页面底部的“原件附件”支持上传、图片预览、原文件下载、替换及历史版本查看。

上传保存的是文件版本。新增或修订证照时选择“证照关联附件版本”，填写证照操作说明并保存，才会建立证照关联；核验仍须由独立人员完成。替换附件不会自行改变当前证照、核验状态或交易准入。调整证照的关联版本会形成新的证照修订，回到待核验，历史中可以下载修订前、后的原件。

## 数据与事务

- 新增 `med.catalog_attachment`，包含租户、商品或往来单位归属、文件族、前一版本、版本号、原文件名、媒体类型、字节数、SHA-256、二进制内容、上传说明、操作人与时间。
- 单个记录代表不可变文件版本。运行账号仅有 SELECT、INSERT 权限，没有 UPDATE、DELETE 权限；替换以新行保存。父资料行锁串行化版本替换和容量校验，过期的替换基线返回 VERSION_CONFLICT。
- 二进制内容以 PostgreSQL `bytea` 保存；文件、元数据、审计与幂等结果同事务提交，提交前权限失效时一起回滚，没有数据库与文件目录之间的半成功状态。
- 两类证照增加可空 `attachment_id`，指向固定文件版本；采用租户复合外键，保存时再验证属于当前商品或往来单位。证照审计快照保留附件 ID。
- 旧客户端修订不发送新字段时保留原有关联，明确传 null 才解除当前关联。解除关联不会删除文件或历史引用。旧请求未发送该字段时仍使用原幂等摘要规则。
- 附件以当前业务库持久化，重建应用镜像不会清除附件。交付 ZIP 不携带附件与业务数据。

本阶段选择数据库存储以复用现有事务、RLS 和备份体系；后续达到大文件或大容量需求时，再设计对象存储、隔离扫描、生命周期与迁移工具。没有引入公开静态目录、匿名链接或外部云服务。

## 接口与权限

| 接口 | 用途 | 权限 |
| --- | --- | --- |
| GET `/api/v1/catalog/{area}/{id}/attachments` | 当前资料全部附件版本元数据，最多100行 | catalog.read |
| POST `/api/v1/catalog/{area}/{id}/attachments` | 二进制上传；query 为 filename、reason、可选 previous_id | catalog.write、来源、CSRF、上下文、幂等键与提交授权检查 |
| GET `/api/v1/catalog/{area}/{id}/attachments/{attachment_id}/content` | 下载固定版本文件，校验长度与 SHA-256 | catalog.read、当前会话与上下文 |

`area` 仅允许 products、parties。商品沿用租户共享范围；往来单位附加当前经营主体权限。相同机构下不同主体的往来单位不共享文件访问权限。仅知道附件 UUID 不能绕过登录、租户、主体和父资料校验。

上传流逐块计数，最大 5 MiB，不依赖 Content-Length。请求体为 application/octet-stream；代理上限为6 MiB。文件只接受 PDF、PNG、JPEG，检查扩展名、文件标识和结束标识；拒绝路径分隔符、控制字符和空文件。这是基础格式识别，不是完整格式解析或病毒扫描。PDF 只下载；图片通过鉴权取回后的短期浏览器 Blob URL 预览，关闭时释放。

文件响应使用 `Cache-Control: no-store`、`X-Content-Type-Options: nosniff`、attachment 内容处置及 sandbox CSP。列表和审计不包含二进制正文。接口错误不回显上传内容。

每份父资料含历史最多100个附件版本、100 MiB；一个证照当前关联一个文件版本，多页原件可使用一个 PDF。暂不提供删除、覆盖历史、外链分享、OCR 和自动审核。

## 页面与恢复提交

上传和证照保存分别提交，页面明确提示两者关系。待上传文件、上传说明及证照关联修改接入既有未保存离开保护；切换质量页签保留编辑。上传中不能重复提交，证照保存需先处理待上传内容。

重试键由账号、企业、父资料路径、文件摘要与上传元数据计算；响应丢失后保持相同文件和说明重试，服务端返回原结果。浏览器存储不保存文件正文。刷新后可先查附件列表，必要时重新选择相同文件与说明继续确认。

## 备份与验证

附件、证照关联和历史审计都在业务库中，现有加密三库备份覆盖这些内容，无需额外文件目录。现有本机备份工具仍有解包总量256 MiB上限；附件容量增加时应切换经验证的专用备份设施，不以单份资料容量限制替代整体备份容量管理。

最终测试和恢复结果见[验证记录](私有附件服务验证-20261021.json)。本次为N05及相关回归，不代表全项目或正式营业验收。
