# 采购审批发布与执行实施与验收

日期：2026-10-21。版本：0.32.0；业务库 b0054，控制库 c0017；102 张强制 RLS 业务表，190 条核心 API 路径。

## 操作入口

“设置 → 审批流设计”维护设计名称、业务、节点顺序、节点名称和审批角色。先保存设计稿，再填写发布说明，点击“发布并用于新采购单”。同一经营主体当前使用一个采购流程；页面显示生效设计版本、发布版本、节点和发布/停用历史。

当前可发布采购的顺序或签流程：每个节点由一个具备指定角色的独立成员通过，然后办理下一节点。节点角色支持质量审核员、企业管理员、企业所有者，按成员实际角色匹配；有较大权限不自动等于具有全部角色。配置时应保证对应岗位有可用的独立成员。制单人、本版内容修订人及重新提交人不能审核自己的申请。

新建采购单、由服务端编辑草稿转单、销售缺货生成补货采购均绑定当时生效的流程。采购详情显示节点、当前轮次、流程版本与审批记录；当前节点可通过或退回，其他角色能够查看进度。所有节点完成后，原采购单才成为已审核，继续收货、验收、入库。部分节点通过不允许提前收货，也不写库存或财务账。

## 版本、修改与退回

| 操作 | 对单据的影响 |
| --- | --- |
| 只保存设计稿 | 已发布流程与单据不变 |
| 重新发布 | 后续新建或内容修订绑定新版本；在途单据使用原快照 |
| 停用后续绑定 | 后续新建或内容修订沿用原独立审核；已绑定流程继续办理 |
| 当前节点退回 | 单据保持待审核，保存退回节点、人员、时间与原因 |
| 退回后重新提交 | 沿用该单原流程，轮次加一，从第一个节点重新办理；以前轮次保留 |
| 到货前修改采购内容 | 内容版本加一，绑定当时生效的流程；原审批实例及决定保留 |
| 取消采购单 | 活跃流程同时取消，原决定与原因保留 |

发布前已有的采购单保持原独立审核方式，直到发生采购内容修订。重新提交与修改内容是两个不同操作；前者保留原流程，后者重新取当前配置。

资料仍随主体一次审核：商品的批准号、证件等属性，往来单位的证件、经营范围等属性，不增加独立审批层级。本次对商品/往来单位审批设计限制为一个统一节点；其设计尚未替换原主体审核机制。既有内置业务规则继续可修改，历史记录和已绑定流程保留当时事实。

## 实现与保护

新增 `med.approval_policy` 保存经营主体当前发布配置；`med.purchase_approval_instance` 按采购单内容版本保存流程快照、轮次、当前节点与决定。两张表启用强制租户 RLS，运行账号没有删除授权。发布、节点决定、退回、重提和业务状态在同一事务中记录审计。

发布使用设计版本和发布版本双重校验；采购动作使用原单版本、原单行锁及幂等提交。并发通过同一版本只推进一个节点。请求提交前继续核查会话及权限；已撤销主体权限不能通过旧幂等请求读取结果或办理事项。流程停用只影响未来绑定，不删除原审批。

新增采购流程查询/发布与退回/重提接口；节点通过继续使用原采购审核接口，因此原接口也执行角色和节点约束。采购资料详情包含当前审批及最近20个旧内容版本的流程；完整记录另保留于审计。发布页展示最近30条发布/停用记录。

消息处理页的时间显示同步改为北京时间，与原业务记录一致。

## 当前边界与后续

会签、条件分支、金额分级、委托转交、加签以及销售等其他业务执行继续后续开发。会签设计可保存，但发布接口明确拒绝；不将其当作或签执行。当前审批在原采购单办理，未增加独立审批任务箱或主动消息推送。

迁移前已将业务库一致性快照加密保存到本机私有备份目录，原始大小185,536,451字节。本快照只覆盖业务库，不等于本版本三库及附件的完整恢复演练。新增迁移保留原资料，不执行破坏性回退。

接下来优先补质量记录筛选与导出，再完善日常开单和往来单位导入。会签和其他业务流程按实际试点需要扩展；真实经营范围样本仍待整理，可配置默认规则不替代试点核对。
