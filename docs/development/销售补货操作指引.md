# 销售缺货与补货

适用：0.24追加交付，业务迁移b0026。入口为“销售 → 批发销售 → 查看销售单 → 缺货与补货”；也可以从企业工作台的“销售待分配”进入原销售单。

2026-10-17补充：有效、已审核且未冻结的新商品可先建批发销售单，无需先有采购或库存记录。审核后可按缺口生成首张采购，分次到货、验收、入库后回原销售单分批发货。待验和合格未入库继续抵扣建议，拒收数量退出抵扣；示例见[多商品分批履约验收](多商品分批履约验收.md)。实际分配仍要求合格库存，零售缺货限制保持不变。

## 从缺货到发齐

1. 销售单独立审核后，点击“缺货与补货”。同一SKU的多行需求合并计算，显示未分配需求、当前可售、当前缺口、已关联未入库及建议补货数量。
2. 核对原仓库是否已有其他采购在途，选择已审核供应商，填写基本单位含税进价及税率。进价留空，不采用客户销售价；默认税率0.13仍需按实际采购约定核对。可减少本次数量，暂不采购的商品填0。
3. 点击“保存补货采购单”。保存前重新校验销售状态、版本、未分配需求、可售量和已关联采购量；需求变化时提示刷新。采购单默认进入待审核，来源销售单及创建时单据版本一并保存。
4. 在采购详情继续独立审核、登记到货、独立验收及合格入库。制单人仍不能审核自己的采购单；入库时才增加库存、成本和供应商应付。
5. 点击“返回原销售单”或采购详情中的“查看来源销售单”。在原销售单“分配发货批次”核对可售量，继续拣货、独立复核和销售出库，原订单保留未发齐余量。

以后再次打开原销售单，可从“关联补货采购”继续办理已生成采购，不依赖浏览器临时草稿。返回销售时需重新展开“缺货与补货”读取最新状态。刷新建议会重填建议数量并保留当前已填进价和税率；查询失败会移除旧建议并提示重试。

## 数量口径

| 字段 | 计算与用途 |
| --- | --- |
| 未分配需求 | 已审核销售单的需求数量，扣除当前已预占及已出库数量；同SKU汇总。非已审核待发状态不再建议新增采购 |
| 当前可售 | 原销售仓库的共享可售库存，复用原分配规则，扣除预占 / 锁定，排除隔离、冻结及不满足最低剩余效期等库存 |
| 当前缺口 | 未分配需求减当前可售，不小于0 |
| 已关联未入库 | 本销售单关联采购中，同仓同SKU的未到货未关闭数量，加已到货但尚未入库且未被拒收的数量。待审核采购也计入；已取消采购不计入 |
| 建议补货 | 当前缺口减已关联未入库，不小于0；商品资质或冻结状态不满足销售准入时不生成建议，先核查商品状态 |

例如原库存10件、已审核销售15件：建议补货5件。生成5件采购草稿后，已关联未入库为5，建议新增为0。5件合格入库后，可售变为15，未入库量变为0；确认分配15件后进入原发货流程。

拒收部分及时退出未入库抵扣，采购关闭未收余量后相应数量也退出；已到货未验收和验收合格未入库的部分仍保留抵扣。多次到货、分次验收和部分入库沿用已有采购流程。

## 使用范围

- 本轮按一张销售单准备补货，每次选择一个供应商，最多50个不同SKU，以基本单位填写数量和进价。可按供应商拆分多次生成；不支持本入口按包装开单、多个销售单合并采购或自动供应商推荐。
- 当前可售是共享库存参考，不为本销售单锁货。其他销售或零售可能先占用，补货入库后仍须重新分配；没有自动出库或交付承诺。
- 抵扣只包含本单已关联采购，不自动扣减其他采购在途，也不是全企业需求计划。多个销售单会共享库存，请核对其他订单和在途后再确认采购。
- 待验收和未到货数量尚未保证效期、质量及到货时间；实际拒收、验收和入库结果决定最终能否用于发货。
- 来源关系用于追踪。销售关闭或修改不自动取消采购，采购变更也不修改销售。采购后续改到其他仓库或商品后，不匹配原销售当前仓库 / SKU的数量不抵扣该行建议。需要取消或更正时分别在原单办理。
- 查看需sales.read和purchase.read，生成另需purchase.write及采购业务开关；继续办理各环节仍按原权限执行。只读账号可查看关联，不能生成采购。

## 开发与部署

`GET /api/v1/sales-orders/{id}/replenishment`返回销售上下文、按SKU汇总的补货建议及关联采购。相同路径的POST接收expected_version、supplier_id、lines；每行sku_id、qty、unit_price、tax_rate，不接受包装单位和重复SKU。使用既有会话、CSRF、Origin和Idempotency-Key规则。当前核心API为120条路径。

新增业务迁移b0026，在现有采购主表记录来源销售ID和创建时版本，按租户外键关联；来源字段不可修改。仍为75张业务RLS表，无新权限和运行依赖。普通采购及补货采购共用同一事务内的采购创建逻辑；本入口额外在经营主体锁内核验最新缺口，防止针对同一来源重复生成超出当下建议的采购。库存查询、供应商与商品校验均复用既有实现。

升级时停止业务写入及回收任务、备份后迁移到b0026，再部署包含本轮变更的核心API和管理端并恢复任务；同为0.24的旧镜像不包含此功能，请以[验证记录](销售补货验证.json)中的镜像ID识别。本机已在迁移前保存业务库备份。
