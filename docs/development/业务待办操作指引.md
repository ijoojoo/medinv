# 进销存业务待办

适用：0.24追加交付，2026-10-19更新工作台入口。选择“工作台 → 高效业务台 → 进销存业务待办”；也可在“设置 → 界面与操作”固定该方案。集中衔接采购、批发、零售、退货、仓库调拨、库存盘点、隔离品处置及期初开账的未完成业务，办理入口沿用原单据。

## 日常办理

1. 选择有权限的经营主体，再选择待办环节；也可输入原订单号、到货 / 发货单号、往来单位或仓库名称查询。调拨按调出仓或调入仓名称均可查找，仓库栏显示“调出仓 → 调入仓”。
2. 点击“查看原单”，在对应采购、批发、零售、退货、调拨、盘点或质量处置详情中核对并继续办理。原单仍控制操作权限、独立审核、数量和版本；看得到待办不等于能执行每个动作。退货待办直接打开该退货申请，第二行显示原到货、发货或零售单号，可用任一单号查找。
3. 完成后点击“返回业务待办”，保留此前主体、环节、关键词和页码，并重新查询状态。已完成当前环节的单据从该环节移出，后续尚未完成的环节继续显示。
4. 其他人办理后，点击“刷新业务待办”获取最新结果。切换企业或重新建立权限上下文会清除待办筛选及原单入口，避免沿用另一企业的内容。

首页先显示6条，“查看全部待办”后每页50条；优先显示需要核对的过期预占，其余按单据时间从早到晚。汇总数量来自完整筛选集合。多个待办可能属于同一原订单：例如一笔采购到货同时存在“到货待验收”和“合格待入库”，或销售订单有多个不同进度的发货子单。查看原单后，应按待办中的到货 / 发货凭据找到对应记录。关键词为不区分大小写的普通文本查找，百分号和下划线不作为通配符。

## 已接入的32个环节

| 业务 | 待办环节 | 进入原单后办理 |
| --- | --- | --- |
| 采购 | 采购待审核 | 独立审核，或按现有流程更正 / 取消 |
| 采购 | 采购待收货 | 登记到货，或确认不再收货后关闭余量 |
| 采购 | 到货待验收 | 对尚未验收数量登记质量结论 |
| 采购 | 合格待入库 | 核对对应验收记录并将合格部分入库 |
| 采购 | 拒收待退回 | 核对拒收实物并登记退回供应商的交接 |
| 批发 | 销售待审核 | 独立审核，或按现有流程更正 / 取消 |
| 批发 | 销售待分配 | 核对未分配需求与可售库存，分配本次发货 |
| 批发 | 发货待拣货 | 核对对应发货子单并登记拣货 |
| 批发 | 发货待复核 | 独立核对商品、批号和数量 |
| 批发 | 销售待出库 | 对已复核子单确认出库 |
| 零售 | 零售待收款 | 核对原零售单后收款，或取消未付款单 |
| 零售 | 零售已收款待出库 | 继续批号数量核对及交付；无法交付时走原实际退款取消流程 |
| 采购退货 | 采购退货待审核 | 独立核对本次退回数量、批号和质量 |
| 采购退货 | 采购退货待出库 | 按原单确认实物出库，回转库存、成本及应付 |
| 批发 / 零售退货 | 退回品待收货 | 清点本次实物并登记隔离保管位置，不直接增加可售库存 |
| 批发 / 零售退货 | 退回品待验收 | 收货后由独立人员验收；旧版未收货流程的历史申请仍按原规则复核 |
| 批发 / 零售退货 | 退回品待入库 | 验收通过后确认入库，恢复库存及原成本 |
| 批发 / 零售退货 | 退回品待交还 | 验收拒收且仍在保管的实物，实际交还后登记结清 |
| 采购 / 批发退货 | 退货退款待核对 | 核对可退原款项及实际资金往来，已经发生退款才登记 |
| 零售退货 | 零售退货待退款 | 已退货入库且金额大于零，按本次退货金额登记原现金退款 |
| 仓库调拨 | 调拨待审核 | 核对同主体调出 / 调入路线、批号和数量，由其他成员独立审核 |
| 仓库调拨 | 调拨待发出 | 确认实物发运，重新检查可用库存，转入专属在途库存 |
| 仓库调拨 | 调拨待收货 | 按实际批号、数量分次收货；合格与隔离分别登记，短少从原单处理损失 |
| 库存盘点 | 盘点待实盘 | 逐行核对实物批号、数量和依据，录入全部实盘结果后提交 |
| 库存盘点 | 盘点待审核 | 由非制单人、非实盘提交人的成员独立核对差异及成本依据 |
| 库存盘点 | 盘点待过账 | 独立人员确认差异过账或无差异结单，释放盘点冻结 |
| 运输短少 | 在途损失待审核 | 进入父调拨和本张损失，独立核对实际短少或拒绝申请 |
| 运输短少 | 在途损失待核销 | 核对剩余在途后核销；迟到已收齐的申请仍需取消 |
| 自有隔离品 | 质量处置待审核 | 独立审核放行或报损依据 |
| 自有隔离品 | 质量处置待过账 | 确认实物处置后过账，记录质量状态或库存成本变动 |
| 期初库存 | 期初待审核 | 独立核对整仓实物清单、批号效期、数量及账面成本 |
| 期初库存 | 期初待启用 | 核对后启用库存与成本；制单人不能启用自己的单 |

期初按单号、清单凭据或仓库名称查找，进入原期初单，返回后保留原筛选。保存及审核不会增加可售库存，启用成功后才可用于出库；取消、拒绝或已启用的期初单不再显示。审核或启用失败仍保留原待办，先处理资料、仓库状态或人员分工问题，再继续原单。

采购已经收齐或已关闭未收余量，并不表示已到货业务结束；尚未验收、尚未入库和拒收未退回记录继续显示。分次验收产生的多笔合格待入库记录分别列出，避免只显示采购订单总状态而遗漏后续操作。

销售待分配包含暂时缺货的未分配需求，不能据此承诺可发货数量。库存、资质、效期、信用、盘点冻结等仍由原业务命令校验。未拣货批发和未付款零售的预占到期后，在原单状态尚未变化前继续保留待办并提示核查；自动回收或人工取消后，按新状态刷新。已拣货 / 已复核批发以及已付款零售的占用受保护，不因原始到期时间显示过期预占提示；已付款零售不因此再次收款或自动退款。

## 权限与实现约定

- `GET /api/v1/work-queue`：必填entity_id，kind默认all，search最多100字符，offset为0至100000。返回items、has_more及当前账号可见的kinds；核心API现为120条路径，本轮仅扩充kind枚举，没有新增路径。
- 每类待办分别复用purchase.read、sales.read、retail.read、returns.read、transfers.read、counts.read、quality.read或inventory.read。采购 / 批发退款核对还需同时具备finance.read；只有returns.read可看7类退货待办，兼具finance.read可看8类。普通调拨3类及损失2类使用transfers.read，盘点3类使用counts.read，隔离品处置2类使用quality.read，期初2类使用inventory.read；查看不授予相应写入或独立审核权限。无任一有效读取权限时返回403，显式查询无权限环节也返回403；使用原主体范围和数据库RLS隔离。
- 单次查询将允许读取的环节合并后统一排序分页，响应禁止缓存。item_id标识该环节凭据，target_id指向原订单；退货待办的两者均为退货申请ID，page为returns，不能误用source_posting_id。entity_id用于进入同一主体的页面。退货按申请时间排序，仓库为原入库 / 出库仓库。
- 这是只读业务入口，不新增库存、应收应付、资金、审计或Outbox写入。所有办理继续使用已有接口、职责分离、幂等和版本控制；无新权限、数据库迁移或依赖。
- 进入采购原单前先加载收货所需的仓库及库位选项，避免直接进入后默认收货库位为空。加载失败可在采购页刷新重试。

## 退货退款的判定边界

采购 / 批发的“退货退款待核对”要求退货已过账、尚有退款登记额度，并且存在曾核销该原单、目前仍有未核销未退余额的有效原收付款。它是核查入口，**不是应退金额或欠款清单**。退款仍需确认实际发生、使用原账户，服务端再次检查最新余额。同一原款项可能服务多张分次退货，待办之间不独占资金，不能相加当作应退总额。

未收付款的退货不提示现金退款；无原核销关系的同单位余额不计入；原款项已全部核销或全部退回时也不提示。有关核销需要调整时，应从原退货 / 结算页面按真实业务处理；待办不会自动撤销核销。部分退款后若仍有可退原款项，保留核对提示；全部登记或可用资金耗尽后移出，作废错误退款登记恢复余额后可能重新出现。

零售仅在本次退货已入库、金额大于零且尚无本次退款记录时提示。零金额退货不产生退款待办。上一张退货已入库但尚未退款时，新一张分次退货仍可按现有规则申请，两张单的退款与实物环节分别保留。拒收的隔离品只进入待交还，不进入退款；登记实际交还后取消申请并移出待办。

已收货尚未验收或已验收未入库的退货仍可在原单自愿交还；待办优先显示其正常下一环节。质量拒收才集中为“待交还”。查询与点击入口都不会代替实物操作，也不会调用银行或支付渠道。

## 调拨的在途判定与办理

调拨待审核对应DRAFT，待发出对应APPROVED，待收货对应IN_TRANSIT和PART_RECEIVED，分别使用transfer_review、transfer_dispatch、transfer_receive。page为transfers，item_id和target_id均为原调拨ID；每张调拨每次只显示其当前环节一条待办，按申请时间排序，不按每笔收货记录重复生成。页面直接打开原调拨详情，返回列表仍可按原方式操作，返回待办保留筛选并重新读取。

申请和审核都不预占库存，待发出不保证现时可发；发出失败仍保留在原环节，需按原单检查库存、资质、效期或盘点冻结。发出后数量进入在途，不可作为可售库存。分次收货不关闭剩余待办；合格和隔离收货都按实际到货结清相应在途，只有合格部分进入可售库存。

“调拨待收货”表示仍有未结在途，不保证全部货物会继续到达。发生短少时，进入原调拨的损失处理，依据实际核查申请、独立审核、核销。草稿或仅审核通过的损失不会扣减在途，也不会让待办消失；实收加已过账损失等于发出量后，RECEIVED或CLOSED_WITH_LOSS才移出。取消或审核拒绝的未发调拨也移出。

新增的损失待办只提供入口，不自动提交或取消损失。若损失申请后货物又到齐，原调拨可收齐并移出收货待办，未处理的旧损失申请继续显示在独立损失待办，可直接进入原单核对取消，不能再次核销已到货数量。同仓移库、跨主体调拨未纳入这3类待办；本轮另增2类损失待办及2类质量处置待办，见 [库存岗位交接](库存岗位交接.md)。

## 盘点冻结与结单

盘点待实盘对应COUNTING，待审核对应SUBMITTED，待过账对应APPROVED，使用count_enter、count_review、count_post。page为counts，item_id和target_id均为原盘点ID；每单每次只有一个当前环节，按建单时间排序。可用原单号或仓库名称查找，直接打开原盘点详情，也可返回普通盘点列表。

创建盘点后，所选主体批次在其他库位、仓库的库存与共享成本池也被冻结；只有选中库位参与本单数量差异调整。三个未完成环节均显示冻结提示。查询、录入、提交或审核通过都不解除冻结，也不会增加可售数量；请同时暂停实物移动。原单不能以漏填实盘代替零库存，录入错误或自己审核被拒绝时继续保留原环节。

**实盘无差异仍需独立审核并过账结单**，不能因为差异为零而直接移出待办。正式过账后有差异才写数量 / 成本变动，无差异则仅完成结单并释放冻结；盘点不生成应收应付。过账与审核均不能由制单人或实盘提交人执行。原有库存快照、资质、期间、版本和权限检查仍然有效。

取消或审核拒绝后状态为CANCELLED，冻结解除并移出待办；原库存与成本不因取消而调整，可重新建单实盘。快照变化、期间关闭等导致过账失败时，仍保留待过账及冻结，按原单提示处理，不能通过待办强制解冻。POSTED和CANCELLED不再进入盘点待办。

本轮沿用一次提交全部实盘结果的原流程，没有新增暂存部分读数、盲盘、多轮复盘或自动结单。盘点过程及成本政策详见 [库存盘点操作指引](库存盘点操作指引.md)。
