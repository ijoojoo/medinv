# 质量记录筛选与导出实施与验收

日期：2026-10-21。版本：0.33.0；业务库 b0054，控制库 c0017；102 张强制 RLS 业务表，191 条核心 API 路径。无数据库迁移。

## 使用

进入“质量 → 质量记录”，查看采购验收明细。支持验收日期起止、供应商、商品名称/编码/规格、批号、仓库、行验收结果和综合查询；“近30天”按北京时间填入日期并查询。“全部合格、部分拒收、全部拒收”指本次验收中的这一条明细，另可筛选所有含拒收数量的行。

每页50条，汇总显示全部筛选结果的验收次数、明细条数及按基本单位分别统计的合格/拒收数量。一份验收有多行时验收次数只计一次；不同基本单位不相加。数量使用精确小数。修改筛选后需点击查询，再翻页或导出，避免输入条件和当前结果不一致。

有采购查看权限时，采购单号可以打开原采购单。没有采购查看权限的质量记录读者仍可查看和导出记录，但不显示原单操作入口。

“导出筛选结果 CSV”导出全部符合已应用条件的明细，不受当前页影响。文件采用 UTF-8 BOM，包含24列：验收时间、采购内容版本、采购/收货/随货单号、留存的供应商/仓库/商品信息、批号、生产日期及效期、基本单位、数量、验收结论/意见以及人员和记录标识。按导出请求时的数据生成，后续新增的验收可能使导出与先前页面查询数量不同。

单次最多10,000行，这是导出资源保护上限；超出明确拒绝，需缩小筛选范围，不静默截断。编码、批号和精确数字按文本保护；公式前缀、引号、换行经安全处理。需要在表格中计算时应核对文本列并转换为数字，不将带文本保护的值直接当作计算列。

## 历史事实与权限

商品信息取原采购行快照；供应商及仓库名称取对应采购内容版本的审核留存。今天修改资料名称不会回写报表历史。没有留存的名称显示“历史未留存”，不使用当前档案补造。关键供应商、商品名称或基本单位缺失时额外提示历史信息不完整。验收人暂以稳定账号标识显示，未用当前职员姓名冒充历史签名。

列表和导出共用查询条件与 `quality.read`、经营主体范围、强制租户 RLS。列表各查询使用同一个只读一致性快照；导出查询读取一个只读快照。查询、导出均不修改验收事实、库存、过账或审计数据。导出响应禁止缓存；浏览器对切换企业/主体及离开页面后的迟到响应作废处理。

界面沿用业务报表宽布局、2560px上限。筛选由四列收为两列/单列，明细表在内部横向滚动。

## 本轮验证

- 完整后端回归：1,090项通过，544.16秒。之后补充历史信息缺失、多单位/多行计数边界，质量专项9项通过；两批结果不相加称作全量。
- 真实浏览器场景通过：隔离测试企业建档、审核、采购、收货、三次验收；筛选后合格3个/拒收3个，部分拒收CSV导出1行；原单跳转、空结果、重置、近30天、筛选未查询时禁止导出通过。
- CSV包含中文、逗号、引号、换行、公式前缀和精确小数；61行跨页导出完整，超限明确拒绝；权限、主体、租户、北京时间日期边界及资料改名历史不变均有集成测试。
- Ruff、后端严格类型检查173个源文件、Vue TypeScript、Prettier和构建通过。1440px与768px截图已检查，无页面整体横向溢出，无浏览器脚本异常。
- 本地构建、启动、版本与镜像核对通过；六项服务运行。Linux非root、两库、191条API路径及后台到期扫描通过。

机器结果见[验证清单](质量记录验证-20261021.json)。截图在 `outputs/quality-records/`，详细运行日志与下载样本在 `artifacts/quality-records/`。

## 范围与后续
