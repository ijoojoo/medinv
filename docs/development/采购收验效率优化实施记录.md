# 采购收验效率优化实施记录

日期：2026-10-20。

## 办理行为

- 收货按原订单行顺序自动列出全部待收商品。首次默认为订单基本单位数量；已分次收货的，默认为剩余待收数量，已收齐或关闭的余量不再次带入。
- 数量填 0 表示本次未到货，该行不提交，批号、日期、货位不强制填写；移除此行同样不影响原订单。新增到货行优先补入尚未分配的余量；更换来源商品时重新计算可分配数量并清空原批号日期，避免串用。拆批数量合计超限会定位提示。
- 验收依原订单顺序展示仍有待验余量的行。默认合格数量等于该行待验数量，拒收数量为 0；两项均为 0 的行暂不提交。已完成的验收不会重复默认进新记录。合格加拒收不能超过本行待验余量，并继续校验商品数量精度。
- 同一订单行存在多个批号时，以批号及记录 ID 保持确定顺序。收货记录、验收记录、入库核对使用一致的订单行顺序，不依赖随机内部编号排序不同商品。

## 键盘与显示

数量获得焦点时全选，包括鼠标点击和键盘换格。Enter / Tab 按显示列和已保存停留设置前进，Shift 反向。新默认收货停留顺序为数量、批号、生产日期、有效期、下一行数量；商品和货位已带入，默认跳过。验收默认在各行合格数量之间连续录入，拒收数量可点击或在列设置中开启停留。用户已有列偏好继续保留，可恢复默认后保存以使用新默认顺序。

日期支持 8 位紧凑输入。无效日期在向前换格前提示，Shift 可退回修改。Ctrl / Command + Enter 提交当前办理表单，仍经过字段、日期和业务校验。数量、日期和原先列设置的读写规则不因键盘操作绕过。

表格随当前录入格纵向和横向滚动，表头保持可见。收货单位换算说明改为可展开区域，减少多行时的重复占位；办理窗口适配视口高度，底部保存区保持可见。

## 结论字典与兼容

“资料 → 商品字典”增加四类严格字典：采购审核意见、验收结论·合格、验收结论·部分拒收、验收结论·全部拒收。初始值分别为同意、合格、部分合格、不合格；各类别中排序靠前的启用值作为默认值。允许新增同类常用表述、调整排序、停用，至少保留一个启用值；不能改写或删除历史值。

审核下拉只选择通过审核时的意见用语。验收下拉根据实际合格、拒收数量选择相应类别，不让文字选项改变真实数量或绕过审核。存在拒收时，新增办理请求要求补充核验依据及拒收原因；全合格或同意审核可不填额外说明。最终记录保留“结论；补充说明”。窗口提供更新结论选项入口，保留已录入数量、批号和说明。

新增 GET `/api/v1/purchasing/review-options`，要求 purchase.read，仅返回当前租户采购结论字典；字典维护仍要求 catalog.configure。采购审核和验收提交增加可选 conclusion。带 conclusion 的请求服务端校验它是否属于本次数量结果对应的启用字典，并校验组合说明容量；界面打开后被停用的选项不能继续提交。老接口的 reason / note 自由文本仍兼容，未传 conclusion 时不改变原幂等请求内容。已提交的同一幂等请求可重试，不受随后字典维护影响。

制单与审核、收货与验收的人员分离，数量上限、批次效期、库存及应付过账、租户和主体权限保持原规则。
