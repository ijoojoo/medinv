## 字段模板、显示名称与部门维护

入口为“设置 → 商品字段设置”。管理员选择药品或医疗器械，可按基本信息、质量管控、经营信息筛选，也可按原名称、企业显示名称或稳定标识查找字段。字段配置显示语义说明、卡片归属、维护部门及审核方式；这些信息由系统维护，不能通过租户设置改为免审核。

允许自定义的字段可填写最长40字符的企业显示名称，留空恢复原名。显示名称应用到建档、修订、属性详情、经营检索词及字段校验提示，不改变数据库键或字段含义。系统名称、类别联动名称和其他字段别名不能重名，比较时忽略空白、英文大小写与全半角差异。分类、原证照编号与日期、注册人/备案人等名称受系统控制：I类显示备案人及备案人地址，II/III类显示注册人及注册人地址，待核定仍显示通用名称。

卡片用于组织录入，审核方式决定维护影响；基本信息不等于免审信息。当前只有字段模板中的检索别名/助记码属于经营直接维护，其他现有模板字段修订仍需质量重审。推荐级别、ABC/双ABC、经营备注及价格继续走既有直接保存流程。经营卡片单独加载时带有商品分类上下文，条件必填与建档保持一致；修订质量资料不重复编辑经营检索词。隐藏字段有旧值或条件必填生效时仍显示供核对。

运行模板暂为`DRUG_BASE`（17字段）、`DEVICE_BASE`（16字段），器械按待核定/I/II/III解析展示状态。药品基础模板保持现有DRUG兼容含义，不把历史DRUG自动认定为成药，不启用饮片等新类别。本次只实现字段模板基础，尚未提供自建字段、任意模板绑定、按部门分配逐字段权限或全部493项设计字段。

接口兼容：原字段设置API返回`template`及字段元数据`field_code/card/owner_department/review_policy/alias_allowed/meaning`；写入仅新增`display_name`。商品详情和经营信息读取返回`field_policy`，其中`context`只包含商品分类选择值，供名称和条件解析。租户旧JSON未保存显示名称时按空值处理；旧客户端未传`display_name`保留已有别名，显式传空字符串才清除。幂等摘要也保留旧请求形状，已有成功请求可重放。审核方式、字段类型、稳定标识不得通过写入接口改写。

运行字段标识采用`catalog.product.<原接口键>`，用于当前兼容层；不冒充设计目录中已经拆分的最终语义字段。商品名/品牌混合字段、原资质日期和机构名称文本继续保留原义，后续仍需分域核对。CSV导入表头、接口键、列表固定栏目和历史变更字段名继续使用现有规范，不随别名重命名。无数据库迁移，旧字段配置、商品ID、单码、库存和历史单据不改写。

## 独立商品证照（b0034）

入口为“资料 → 商品档案 → 资料详情 → 质量管控 → 商品证照档案”，在卡片内维护。一个商品最多100份记录，支持药品批准证明、医疗器械注册证、第一类医疗器械产品备案。原有批准/注册/备案编号及日期原样保留为“类型待核对”的只读参考，不自动生成已核验证照，不推断签发日期。

证照保存编号、持有人/注册人/备案人、发证/备案机关、覆盖规格型号、签发/备案日期、有效期方式及起止日期、原件凭据和备注。有效期方式区分待核实、固定有效期、原件未载明；固定期限要求起止日期，其他方式不填推测日期。未知信息可先存草稿；核验前补齐持有人、机关、原件凭据并确认有效期。当前药品批准证明及器械注册证的核验要求固定有效期。备案记录允许按原件登记“未载明”，不等同于承诺永久有效。

器械分类已核定为I类时只能维护备案类型；II/III类维护注册类型。分类未知可补录草稿，核验前需先核定商品分类。依据为[医疗器械监督管理条例第十三条](https://www.samr.gov.cn/zw/zfxxgk/fdzdgknr/fgs/art/2023/art_70607fc4160041a383e68ff6bfb2826f.html)。分类变更后，列表动态提示既有证照与当前分类不符，旧核验记录保留。

证照状态为待核验、已核验、已停用；核验状态与有效期分别显示，历史过期资料仍可核验原件内容，但不会显示为当前有效。制单人及本轮修订者不能核验通过；停用后须补充修订依据再核验。每次内容修订清除本证照当前核验状态，变更记录保留完整前后值、版本、操作者、原件/核验凭据和操作原因。当前采用最新记录加不可改写审计快照，不是“新旧两个业务生效版本并行”。

记录使用独立版本、事务幂等与租户隔离。同一商品的同类型同编号不能重复建档（含已停用记录），应修订原记录。核验再次检查当前商品分类，避免编辑期间分类已变化；过期版本会拒绝保存。切换卡片保留未提交内容，有修改时禁止直接返回列表，退出企业/登录会提示未保存资料。

**实施边界：此阶段是补充档案，不自动替代旧商品资质及购销准入条件。** 补录、修订、核验和停用只更新证照域，不改商品审核状态、经营字段、库存、成本和历史单据。若发现需要立即禁止经营的质量问题，仍需使用原有“停用资料”。食品、日用品等分类建档、企业多证照、证照与多个商品/包装关联、原件上传、国家登记库自动核实、有效版本发布和交易校验切换尚未实施。

新增API：`GET/POST /api/v1/catalog/products/{id}/certificates`，`GET .../{certificate_id}`（含50条分页记录），`POST .../{certificate_id}/revise`，`POST .../{certificate_id}/review`。权限沿用catalog.read/write/review，写入沿用上下文、CSRF、Origin和幂等键。证照停用没有物理删除入口。

更新：2026-10-17。零售页面保留，独立收银端 / exe 另行规划。本轮完善管理端商品、供应商和客户资料。

## 当前：部门卡片、统一编码与商品导入（b0033）

商品建档和详情以商品类别为首项。新建页面只提供一个“商品编码”：保存时同时用于商品主档和初始库存单元。商品主档描述商品身份，SKU 是单据和库存实际引用的单位；当前一档一个初始 SKU，不需要操作员重复输入两套码。数据库的对象和历史引用保留。老资料若两码不同，在基本信息的“历史库存编码”中核对；不批量改码，也不改写已开单据。旧 API 仍接收显式的两套编码，以兼容旧客户端。

详情按职责整理如下。供应商、客户沿用同一结构，价格、条码与包装仅用于商品。

| 卡片 | 内容与保存规则 |
| --- | --- |
| 基本信息 | 类别、商品编码、名称、厂家、规格、基本单位及通用资料；商品条码与包装版本在此维护，原审核规则保留 |
| 经营信息 | 推荐级别、ABC / 双 ABC、助记码、经营备注及往来单位日常联系资料；直接保存留痕 |
| 质量管控 | 管理类别、批准 / 注册 / 备案编号、资质期限、储存条件、持有人 / 注册人、经营范围类别、质量备注；修改后独立审核 |
| 价格信息 | 按基本单位维护参考采购价、参考批发价、建议零售价和备注；含税人民币、最多 6 位小数，空值与零价区分，直接保存留痕 |

价格使用独立版本，更新不改变商品的审核状态和资质版本，不修改历史成本或成交价；当前不会自动填入采购 / 销售单。追溯卡片登记商品级标识，单盒追溯码仍属于后续单据追溯流程，尚未连接外部平台。

药品与器械各新增一本“经营范围类别”严格字典，企业按自己的经营分类维护，初始为空。对应字段支持原有显隐、排序、必填、条件必填和格式规则。范围分类与质量备注纳入资质修订，运营分类仍直接保存。当前只形成结构化档案，尚未依据新范围字段自动放行或阻断交易。原有已保存字段模板读取时补入新增字段默认规则，已有字段配置不被覆盖。

### 自动编码设置

入口：“设置 → 商品字段设置 → 自动编码规则”。药品和器械分别设置启用、前缀、日期段（无 / 年 / 年月 / 年月日）、流水位数和下一流水号。默认药品 `YP000001`、器械 `QX000001`。设置需要 `catalog.configure`，变更须说明原因并留痕。

- 留空编码时，在正式保存事务中取号；预览和导入预检不占号。手工编码仍可填写。
- 日期按中国标准时间生成；流水连续递增，换日或改前缀不自动归零。流水位数是最小补零位数，超过位数保留完整数字，不截断。
- 流水只能向前调整；取号同时核对既有商品编码和 SKU 编码并跳过冲突。并发建档序列化取号，失败事务不消耗流水；已提交后网络重试沿用原幂等结果。
- 禁用自动编码后，新商品必须手工填码。旧商品编码不因规则调整而改变。

### 商品批量导入

入口：“资料 → 商品档案 → 批量导入商品”。下载 CSV UTF-8 模板，填写商品类别、名称、厂家、规格、基本单位、资质编号及起止日期等；可按模板补充分类、质量和检索字段。商品编码可空，由各类别规则分配。每批 1—100 条、最多 256 KB；Excel 文件先另存为 CSV UTF-8。

预检使用当前类别字段和字典规则，提示文件内 / 已有编码重复，以及类别、名称、厂家、规格、资质编号完全相同的档案。此项是准确匹配核对，尚未做同义名或模糊查重。支持只看错误行、下载保留原字段的待修正清单，修正后重新上传。确认提交时再次检查最新配置，全部通过才在同一事务中写入；任一行失败整批不写入，已申请流水也回滚。全部导入为待审核，仍需另一位有权限的人员审核。

导入只新增主档，不覆盖已有资料，不导入价格、经营评级、包装版本和平台映射。页面切换保留当前预览；浏览器刷新尚不恢复未提交文件。结果可导出商品编码清单；编码按文本处理，保留前导零。

## 字段设置与字典衔接

在“设置 → 商品字段设置”查看每个绑定字典的字段：选值方式、符合当前长度 / 格式的可选数量、被过滤值数量。规则配置弹窗同时预览兼容情况；需要补充选项时，应用字段调整后点击该行“维护字典”。基本单位为固定必填字段，提供独立维护入口。

维护字典在当前工作页内展开。字段的显隐、必填、顺序、格式、条件及修改说明保留；字典独立保存，返回后使用最新选项重新校验尚未保存的字段规则。修改字典不是同时提交字段规则，需返回并点击“保存字段设置”。切换工作页保留待保存内容，切换企业 / 退出或关闭浏览器有未保存提示；字段草稿未实现跨刷新恢复。

字典页展示其适用的商品类别、字段、必填状态和格式限制，按已保存的字段规则实时检查当前字典修改。商品名 / 品牌与储存条件分别核对药品和器械；剂型核对药品；基本单位始终必填，推荐级别与 ABC 为选填。

- **严格字典 + 必填或条件必填**：必须至少存在一个启用且符合长度 / 格式的值；无可用值时不能保存字段配置，也不能保存会导致该冲突的字典修改。
- **严格字典 + 选填**：无有效选项仍可保存，页面提示可留空。
- **建议字典**：无有效建议值仍可按字段规则手工输入；明确停用的值依旧不能新录入。
- 已启用但不符合某类别字段规则的值仍保留在字典中，在该字段的下拉和建议列表里过滤。已有资料值不被自动改写；历史值可保留只豁免字典成员校验，不豁免长度、格式、必填等规则。

服务端在字段规则保存及字典保存两个方向校验，错误码 `DICTIONARY_RULE_CONFLICT`（422）。事务锁统一按“相关类别字段规则 → 租户字典”顺序取得，确保并发调整必填 / 格式与停用选项时不能共同提交不可填写的配置。版本、权限、幂等、审计机制保持不变。

单本字典 GET 响应增加 `bindings`，包含类别、字段、必填 / 条件、长度、格式、启用数、有效数、不兼容值及是否冲突。该项在 b0032 / c0017 引入；当前版本见上文。

## 经营维护与商品字典（b0032 引入，b0033 扩展）

卡片首次打开按需读取，切换后保留编辑内容；左右方向键、Home / End 可切换标签。新建先保存基本档案，再从详情补充经营及编码信息。已有包装、修订、审核和历史记录功能保留。b0032 原先每个平台独立成卡；b0033 已按上文合并。

**按变化的字段决定是否审核，而不是每次保存都重审：**

| 信息 | 保存规则 |
| --- | --- |
| 商品 / 单位名称、资质编号、有效期、商品身份与分类属性、经营范围及核验档案等 | 保留原修订及独立审核流程，资质变动后进入待审核 |
| 推荐级别、ABC 第一维、双 ABC 第二维、经营备注、检索别名 / 助记码 | 经营卡片直接保存，记录前后值、操作人及原因，不改审核状态 |
| 单位简称、日常联系人、联系电话、收货地址 | 同属经营信息，直接保存留痕；不会改写已开单据地址，也不代表变更法定代表人或授权人员资质 |
| 平台编码 | 在对应平台卡片单独登记 / 停启用，维持原防重复、来源凭据及不可改写规则 |

经营更新不会将已审核档案打回，也不会将待审或停用档案变为已审核；审核人、审核时间、本轮资质修订人保持不变。资质与经营共用档案版本，防止不同卡片或不同成员同时保存时静默覆盖。旧版完整修订接口若实际仅变化上述日常经营字段，也按经营变更处理；混合资质变更仍重新审核。原单据快照保持不变。单独改经营分类不会被后来新增的其他资质必填规则阻断；修改助记码本身仍受该字段配置规则约束。

ABC 和双 ABC 暂按企业定义的两个维度人工维护，均为 A / B / C，第二维可空。不自动假定维度代表销售额、毛利或周转，也不做自动计算。

| --- | --- | --- |

| 商品名 / 品牌 | 药品、器械商品名 | 建议选用 |

字典支持新增、数字排序、停用 / 启用、建议选用或只能选用（推荐级别与 ABC 固定为只能选用）、版本检查及变更原因。最多 200 项，值长度不能超过绑定字段容量；已存在值不删除、不改名，要纠错时停用旧值并新增。建议选用允许字典外文本，但明确停用的值不能新录入。严格模式只允许启用值；未修改的历史值允许原样保留，不自动改写或清空。必填、长度、格式、器械类别联动仍由“商品字段设置”管理，与字典规则叠加。新打开的录入使用最新字典，服务端保存时再次验证；旧页面遇到配置变更需刷新字典后选择。

字段字典当前为上述已绑定字段提供选项，不是任意新增数据库字段或任意运行脚本的扩展系统。查看需要 catalog.read，维护字典需要 catalog.configure；经营维护需要 catalog.write，单位仍按经营主体授权。

## 编码登记规则

详情中的“对接编码”可登记商品条码、UDI DI、医保药品 / 耗材 / 体外诊断试剂编码、医保机构编码、美团、饿了么、淘宝、旺店通及其他系统编码。

1. 商品映射挂在明确的 SKU 上，可进一步指定该 SKU 的已审核包装版本。同一 SKU 可有多条编码；包装停用后映射保留，列表提示核对。当前没有外部编码直接下单或扫描推断包装的能力。
2. 往来单位映射挂在当前经营主体内的单位档案。商品编码不能填到单位；医保机构编码不能填到商品；医保药品编码仅用于药品，UDI DI、耗材和试剂编码仅用于医疗器械。
3. 标准编码不填写账号范围。平台及自定义编码必须填写明确的店铺 / 账号 / 系统标识，不默认猜测。SKU 编码映射在租户内唯一；单位编码映射在租户及经营主体内唯一。相同类型、账号范围、外部编码不能同时启用两条，数据库唯一约束防止并发重复。
4. 编码必须为字符串，保留前导零和大小写，拒绝内部空白或控制字符；不把所有类型强制成统一数字长度。不同编码体系的官方校验、查询授权和接口版本适配留给具体连接器。
5. 登记必须填写来源凭据与原因。原编码值、对象、包装和来源不能覆盖修改；错误时先停用再重新登记。停用不删除历史；重新启用需再次检查重复和包装可用性。状态修改校验版本并留痕。
6. 编码登记和启停需要 catalog.write，查看需要 catalog.read；不代替商品或单位资质审核，不改变原档案的审批状态。写入复用租户隔离、主体权限、幂等和提交前授权校验。

登记编码仅表示本企业维护了一条映射，不代表医保可结算、官方认证或第三方接口已经接通。本轮不发送数据到外部平台。

- 经营卡片有未保存修改时，基本信息明确提示其显示的是已保存内容。切换卡片不覆盖未保存输入；原保存快捷键、返回前保存/放弃/取消、返回列表定位继续有效。经营保存仍只提交变动字段与原因，不修改资质审核状态、共享机构关联或法定身份资料。

## 基础资料查询列表列设置

商品主数据及供应商/客户列表增加统一“列设置”入口。支持检索字段、显示/隐藏、拖动排序、前移/后移按钮、80–640px整数列宽和文本换行。修改只在“保存并应用”后生效；取消不影响当前列表；“恢复默认列”先恢复弹窗中的草案，保存后才覆盖个人设置。名称、编码和审核状态保持显示，资料操作入口保留。

商品保留原默认列，并从当前主数据列定义补充可选的单值字段和条码。组织、证件仍使用原摘要；各字段的无权限、不适用、待核实和未填写状态优先于内容显示，不因列设置暴露受限字段。列表截断的长文本可悬停查看，开启换行后按列宽折行。其他复杂集合继续从详情维护。查询条件、分页及原“导出当前范围”的字段和权限规则不随列配置变化。

往来单位保留默认名称/编码、类型、联系/信用代码、资质有效期和状态列，并可增显简称、助记码、机构性质、许可/备案编号、默认收发货地址、注册/经营地址、推荐级别及ABC分类。供应商、客户及双向单位共用同一套个人列设置；业务身份筛选不清空设置。操作列固定在右侧。

当前设置保存在本浏览器的localStorage，键包含版本、企业、账号和列表类型；商品与往来单位分开，账号/企业之间不共用。仅保存列标识、显隐、顺序、宽度和换行配置，不保存资料内容。无效或旧格式的设置回退默认值，未知字段及重复字段被忽略，必显字段不能通过缓存关闭。浏览器拒绝存储时保留弹窗并明确提示，当前列表不变；暂不提供跨浏览器或跨设备同步。没有数据库迁移或后台接口改动。

实现入口：`catalogColumns.ts`、`CatalogColumnSettings.vue`、`ProductMasterWorkspace.vue`、`CatalogPage.vue`。验收入口：`tests/catalog-columns.spec.ts`；既有查询、维护、回跳及往来单位日常维护用例继续回归。
