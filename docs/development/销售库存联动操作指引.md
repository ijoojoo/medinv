# 销售开单与可售库存联动

适用：0.24追加交付；2026-10-16。本功能已接入批发开单、修改销售单、分配发货和零售建单，数量均以商品基本单位显示。

## 开单时查库存

1. 在“销售 → 批发销售 → 新建销售单”选择发货仓库和商品，页面下方显示“仓库可售库存”。零售则在“销售 → 零售收银 → 新建零售单”加入商品后显示。
2. 修改仓库、商品或批发最低剩余效期后自动重新查询；数量、价格等已填写内容保留。
3. 有其他人收货、预占或出库后，点击“刷新可售库存”查看最新结果。查询失败会清除旧结果并提示重试，不把失败当作零库存。
4. 零售建单仍须一次足量预占；批发可以先按客户需求下单，审核后分批发货，不会因为眼下缺货就自动减少订单数量。

按箱、盒等包装开单时，开单数量仍按所选交易单位填写；库存面板始终显示基本单位。例如一箱3个、可售7个，不能把7个理解为7箱。包装换算沿用已审核包装版本。

## 按可售量分批发货

1. 销售单独立审核通过后，进入“分配发货批次”。面板按该订单仓库和最低剩余效期查询。
2. 点击“按可售量填入本次发货”。系统重新查询，按“订单本行未分配数量”和“该商品剩余可售数量”中的较小值填入；同商品多行按显示顺序共享库存，不会每行重复使用整份可售量。
3. 核对本次数量，必要时手工减少；不发的行填0，再确认分配。全为0时不能成功分配。
4. 继续拣货、独立复核、出库。剩余订单数量保留，后续有货再继续分配；双方不再履约的余量仍走原关闭流程。

“按可售量填入”只替换当前弹窗的本次发货数量，不修改销售单数量、不直接生成出库或应收。全部发货数量依旧是基本单位。

## 可售数量口径

从所选主体、实体仓库的合格库存中扣除已预占和锁定量；排除商品或批次冻结、未批准或已失效商品、过期或效期未确定批次、隔离及盘点冻结库存。批发另满足订单的最低剩余效期，零售仅开放已审核非处方药和普通器械。没有库存的可见商品明确显示0。

查询是操作参考，不占库存，也不承诺未来可发数量。实际建单预占或发货分配仍在原事务中重新校验；其他人先占用后可能提示库存不足，刷新后重新核对即可。客户经营范围、资质、信用等仍由原销售审批和分配流程校验，不能用库存面板代替。

## 当前接口与运行范围

- `GET /api/v1/selling/stock`：entity_id、warehouse_id、重复传入的sku_id（1至50个），minimum_shelf_days为0至3650；使用sales.read及主体范围。
- `GET /api/v1/retail/stock`：entity_id、warehouse_id、重复传入的sku_id（1至50个）；使用retail.read及主体范围。
- 响应包含商品基本单位、可售数量字符串、商品准入状态、仓库和查询时间。共享原分配候选查询，最多2000条候选库存；超限报错，不截断求和。不新增写权限或数据库迁移。
- 查询不包含其他仓库、待验收、在途或采购订单未到货数量，不自动创建补货采购单，不锁定客户报价或售价。

## 本次业务验证

用真实采购流程准备10件库存，零售先预占3件；批发开10件订单，按当前可售量先发7件。取消未付款零售单后，再发3件，原批发订单发齐。最终库存及预占为0，两笔客户应收为140元、60元，出库成本合计115.04元；采购应付不因查询或分批发货改变。

测试同时覆盖效期筛选、切仓、查询失败重试、产品准入、盘点冻结、权限与主体隔离，以及既有包装、销售改单和零售业务。详见 [本次验证记录](销售库存联动验证.json)。
