# 工作台三方案实施与验收

实施日期：2026-10-19。依据用户提供的 `homepage-three-options.html` 和 `codex-homepage-implementation-prompt.md`。采用现有 Vue 主应用、业务权限与 Python 服务，不嵌入原型 iframe，不另建业务数据副本。

## 使用入口

- 工作台右上角“工作台方案”：经营洞察台、风险指挥台、高效业务台。
- 设置 → 界面与操作 → 工作台方案：用预览卡片选择。
- 选择按企业、账号、经营主体保存在当前浏览器。刷新后恢复；不宣称已跨浏览器同步。没有有效偏好时，有财务读取权限默认经营洞察台，其余默认高效业务台。
- 有效方案随权限变化：经营洞察台要求 `finance.read`；风险指挥台要求已接入业务类别的读取权限；业务台只列出当前岗位已授权的待办与快捷入口。失效偏好自动回退。
- 主导航、主题、工作标签、经营主体选择和已打开的录入草稿继续共用。切换方案保留当前页面内的周期和待办筛选；切换企业或主体重建业务上下文并丢弃旧请求结果。

## 页面分工

| 方案 | 主体内容 | 下钻方式 |
| --- | --- | --- |
| 经营洞察台 | 近7/30日销售、毛利、回款；逐日趋势；应收账龄、应付余额；库存成本结构；逾期和效期关注项 | 应收或库存明细抽屉，每页20条；应收可进入销售原单，库存进入库存查询 |
| 风险指挥台 | 当前未闭环汇总、风险类别分布、重点业务范围；明确尚未接入的历史趋势 | 分类汇总 → 事项列表 → 按需展开 → 原单办理；默认不展开任何事件详情 |
| 高效业务台 | 4个常用环节汇总、完整待办检索、常用操作、规则提醒、本人最近草稿 | 默认展示6条，查看全部后每页50条；沿用原单流程和权限 |

三个方案按附件的层次和视觉方向实现；风险方案以 Markdown 的“宏观风险总览”要求为准，未照搬 HTML 中默认选中事件的旧列表。

## 统计口径

### 期间指标

时区为 Asia/Shanghai；近7/30日包含未结束的今天。前期比较为紧邻的同长度日期段，页面提醒本期今日未结束。所有统计只读，金额在后台按 Decimal 汇总；前端用整数分格式化与比较，仅图形坐标转为浮点数。

- **含税净销售**：已过账批发出库、零售出库，减去已过账批发和零售退货。未过账订单、已收款未出库零售不计销售。
- **毛利**：不含税净销售额加对应成本流水净变动（出库成本为负，退货成本为正）；毛利率的分母是不含税净销售额。成本先按过账行汇总，避免多次分配放大收入。
- **净回款**：已确认收款登记，加零售实际收款，减已确认销售退款、零售取消退款和零售退货退款。含收回往期应收；零售按找零后的实际金额计入。作废款项不计。收款按业务日期，零售收退款按登记时点转换为业务日期。
- 历史记录缺少金额或成本时，相关期间指标显示“—”，明确提示信息不完整。逐日趋势保留缺口，不连线伪造缺失日期，不把缺失算为零；完整期间日均不显示。无业务发生且没有缺失事实的日期显示真实零值。
- 趋势为逐日折线，不平滑制造中间值；支持指针查看和前一日/后一日按钮读取准确日期、金额。前期非正值或信息不全时不显示误导性增长率。

### 当前余额快照

账款和库存独立于近7/30日选择。刷新经营数据会同时刷新期间和余额；切换期间仅刷新期间。各区展示读取时间，明细重新读取时可能因其他岗位办理而变化。

- 应收、应付来自现有结算余额视图，已扣核销与退货影响。
- 应收按未到期（含今日到期）、逾期1—30日、逾期超过30日分组；逾期客户按客户去重。列表按应收义务逐笔列示，总额与同一时点的分组口径一致。
- 库存结构为本主体正数量的实物批次成本池，包含在途和隔离库存，排除服务类；按商品类别统计成本金额，不把不同单位的数量相加。
- 近效期采用 `expiry_exclusive` 实际失效时点，范围为当前时点之后的90日；已过期单列，互不重复。明细列出商品编码、批号、有效期至、基本单位数量和成本金额。
- 无库存读取权限的财务用户看不到库存信息，相关明细服务也拒绝访问。

### 待办与风险

待办沿用现有32个业务环节。一次查询中完成权限过滤、字面关键词检索、优先条件、环节筛选、总数、分组计数和分页。卡片计数来自完整匹配集合，不是当前6/50条列表的长度。“优先核对”当前仅表示现有规则认定的预占过期；不冒充 AI 风险推断。

风险首页当前接入四类互斥事项：质量处置待审核/待过账、采购拒收待交还、客户退回品拒收待交还、在途损失待审核/待核销。汇总和分类使用同一查询快照，权限不同的人员只看到各自范围。

草稿来自本人服务端草稿，合并当前打开的编辑状态；明确区分服务端已保存、未保存修改、保存中或保存失败。接续草稿复用原草稿与工作标签，不重复创建单据。

### 常用入口与草稿接续（第二轮）

- 高效业务台 → 常用操作 → **调整入口**：最多选择9项；支持拖动、上移/下移；保存后生效，取消不改变原设置。“恢复默认入口”仅改变待保存的选择，需要保存后生效。入口来自现有模块和采购/销售开单，不另建业务流程。
- 常用入口按当前浏览器、企业、账号、经营主体分别保存；权限变化时隐藏失效入口，不能通过旧偏好绕过权限。不提供跨浏览器同步。
- **继续草稿**显示最多4份：当前窗口的未保存、保存异常或版本冲突优先，其余按最近保存排序。读取失败仍显示当前已打开草稿的输入状态。
- **全部草稿**统一查看本人采购、销售草稿；支持类型筛选和备注、往来单位名称、仓库名称、改单原单号的关键词查询。搜索匹配已保存内容，当前窗口待保存内容单列，接续时保留未保存输入。
- 查询显示准确总数，每页20份；信息包括往来单位、仓库、已选择商品行数、最近保存时间和原单号。空白商品行不计数，不能把行数当作完整性或可转单校验。
- 采购、销售记录页的 **我的草稿**复用同一浏览器，初始选中对应单据类型。打开已有草稿复用原草稿编号和工作标签；保存、版本冲突、转单仍使用原有规则。
- `GET /api/v1/document-drafts`：`channel=all|purchase|sale`（默认all），`search`最多100字，`limit=1..50`（默认50），保留`offset`；返回`items/total/has_more`。跨类型读取只包含有编辑权限的类型，强制本人、租户和经营主体范围；未授权明确类型返回403，不可见主体返回404；响应禁止缓存。
- 新增摘要字段`party_name/warehouse_name/source_number/line_count`，列表不返回草稿内容；草稿中未完成、无效或失效的资料引用不会使查询报错。总数与本页使用同一只读快照；没有新增数据库迁移。
- 实现拆分为`WorkbenchShortcuts.vue`、`workbenchShortcuts.ts`、`WorkbenchDrafts.vue`、`DraftBrowser.vue`和`draftSummaries.ts`，减少工作台与记录页的重复逻辑。

### 待办与原单接续（第三轮）

- 从业务待办或风险事项打开采购、销售原单，统一使用独立原单标签。同一企业、主体、单据只复用一个标签；不再替换采购、销售记录页的查询内容。
- 每张原单标签分别记住最近一次待办来源：工作台方案、已应用的关键词、尚未提交的输入、环节/风险类别、优先条件、分页位置和每页条数。切换到另一张原单时，来源提示与返回目标随当前原单变化。
- **返回业务待办**恢复对应筛选并重新读取最新数据，优先定位原事项的查看按钮；事项已不在本页时定位邻近行并提示以最新列表为准。超过最新末页时自动回退到有效页，避免已办理后留在空的末页。
- **返回风险事项**恢复原风险方案、类别、关键词和分页，重新打开事项抽屉；等待数据读取与抽屉展开完成后定位事项。其他已有单据继续沿用其原办理页面。
- 关闭当前由待办打开的采购/销售原单标签，在原有未保存校验通过后回到对应待办。原有“返回采购/销售列表”入口仍用于进入记录列表。
- 再次激活已打开的采购/销售原单会读取最新状态。若当前原单有未完成操作或正在保存，保留输入并提示完成/取消后刷新，不直接重建正在填写的表单。
- 来源与定位信息只保存在当前打开的工作区；切换企业、主体或重置会话后清除。页面刷新后原单深链接仍可打开，待办来源不做跨刷新持久化。本轮没有修改业务接口、数据库或零售页面布局。
