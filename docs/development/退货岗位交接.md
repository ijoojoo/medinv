原管理员、业务操作员的退货操作能力保留。岗位可组合，合并后取各岗位权限并集；制单人、隔离收货人仍不能独立复核自己经办的退货。收银员不因能够申请零售退货而获得现金退款权。

## 办理顺序

1. 经办岗位从对应已过账原单填写本次退货数量和原因。不能超过剩余可退数量，已有未完成申请时继续原申请；采购员不能申请销售或零售退货，销售和收银也只能申请各自类型。
2. 客户退回品由仓储核对本次数量、批号和实际隔离位置，登记实物交接。此时不增加自有库存和可售数量；质管独立验收通过后仍需正式过账。采购退货不经过客户隔离收货，由质管复核后核对实际交接并确认出库。
3. 若原应收应付已核销，退货过账可能提示先撤销原核销。财务从该退货详情核对原记录并撤销必要核销，质管再继续原过账。系统不自动撤销款项登记，也不会因退货再次打开原采购或销售订单。
4. 已发生款项的业务，在退货过账后由财务按原账户登记退款：采购记录实际收到供应商退款，批发记录实际退还客户款项，零售按本次申请的全部金额登记现金退款。剩余有效款项可重新核销剩余应收应付。
5. 不合格的客户退回品由质管拒收，保管责任仍然存在。仓储确认全部实物实际交还客户后登记交还，结清保管并取消该申请，不增加库存、成本或退款。

未实际交接的申请可由对应经办岗位取消。已登记隔离收货后必须按原流程交还，不能用“取消申请”跳过保管责任；已过账单不能直接取消。

## 范围说明

本轮划分的是退货操作权限。四个岗位可读取授权企业及主体中的退货进度，未增加按退货渠道、个人、仓库、价格或成本字段的读取隔离。工作台仍按业务读取权显示待办，可能包含需要交给其他岗位的环节；对应动作只有获授权岗位可办理。

当前没有新增采购退货的独立仓储发运环节，也没有新增退款审批、原路支付平台退款、换货或跨企业退货。退款是实际款项的人工登记，不触发银行或支付机构转账。

## 可重复验证

管理端目录执行 `pnpm run test:return-jobs`，建立独立企业，用七个真实登录账号准备原采购与批零单，再从实际岗位页面办理三类退货、财务核销更正与退款、拒收实物交还。业务数据全部经正式接口和页面产生。

场景采购10件，批发4件、零售2件，先收付并核销原款；三种退货分别1件，最后库存5件、成本57.52元。采购退款13元、批发退款20元、零售退款20元分别由财务核对登记，余款重新核销后应收应付均为0；另一次零售退货拒收交还不改变库存与成本。证据和执行范围见 [退货岗位验证](退货岗位验证.json)。

本轮成功验收企业为“退货协作企业-ee4fab6c”。各岗位演示账号登录后切换该企业即可查看对应单据；账号说明沿用本机私有账号清单。
