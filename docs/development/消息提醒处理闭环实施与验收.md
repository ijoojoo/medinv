# 消息提醒处理闭环实施与验收

日期：2026-10-21。版本：0.31.0；业务库 b0053，控制库 c0017；100 张强制 RLS 业务表，188 条核心 API 路径。

## 可操作的功能

消息中心包含业务待办、资质到期、经营范围异常、主体资料待审、养护提醒五类来源。资质到期同时覆盖往来单位证件与商品证件；商品证件按关联商品定位，已经生效的原资料继续作为当前核查依据。范围异常按已审核的类目、供销方向、证件组合和当前企业规则计算，界面列明原因、分类编码与准入控制方式。

“当前提醒”显示当前触发条件；“处理中”保留团队跟进事项，原条件消除后显示“已消除，待确认关闭”；“已关闭”保留结案历史。个人已读与团队处理分别保存。支持认领、分派本主体在职职员、计划日期、处理说明及最近50条处理记录。职员搜索只返回编码、姓名、岗位，不返回联系方式。账号认领与职员负责人是两种关系，“仅我认领”按登录账号筛选。

点击提醒进入对应单位的经营范围/质量管控页签、商品证件维护或具体养护记录；地址带经营主体、记录及页签，刷新后能够继续定位。业务待办仍从原业务单据办理。

## 核查与权限

- 关闭前由后端重新读取原事项，条件仍存在时拒绝关闭；提醒开关关闭也不能绕过该检查。
- 证件续期草稿不提前清除原证件风险。证件和经营范围随主体统一审核生效，再重新核查。
- 关闭后条件再次出现，当前提醒显示“再次触发，待重新认领”；原处理历史继续保留。
- 资料或触发原因变化时提示重新核对；处理版本并发保护、幂等提交、提交前权限复核与事务审计共同生效。
- 只读成员可阅读提醒和处理记录；操作成员只能处理自己有来源读取权限、且在授权经营主体范围内的事项。
- 页面来源和处理历史都经过权限过滤，跨租户及跨主体请求不能读取或改动记录。

企业设置的“消息与提醒”提供总开关、五类来源开关、证件/养护提前天数。所有新增规则选项可配置。关闭显示开关不改变采购、销售的准入规则。

## 实现与数据

新增 `med.reminder_case`，保存稳定来源键、来源快照、认领账号、职员负责人、计划日期、处理状态及版本。完整操作写入审计表。个人已读仍使用原 `management_record`。长消息标识使用稳定摘要作为幂等目标，保留原消息标识作为阅读与追踪依据。

新增查询处理事项、查询处理历史、负责人搜索、处理动作四条 API，原消息查询与已读接口继续兼容。业务待办核查改为按准确来源键检索，超过第一页的待办不会误判为已完成。

经营范围按最多250个范围/业务方向组合分批核查，每批最多返回50条异常；下一批使用扫描游标，不遗漏被正常范围隔开的异常。消息中心在打开或刷新时重新计算。此版本为站内按需核查，后台主动推送、短信、微信、库存/应收到期来源继续后续开发。
