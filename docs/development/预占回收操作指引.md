# 预占到期自动回收

适用版本：0.17。默认预占有效期为 15 分钟，后台进程开启后分批回收符合条件的到期记录。

## 业务人员

- **未收款零售**：到期后不能收款。后台处理后，列表及详情显示“已超时取消”，详情显示处理时间。库存占用已释放，需要交易时重新开单。还未回收时也可按原流程人工取消。
- **待拣货批发子单**：到期后自动取消该子单并释放占用，原销售订单仍为待发齐，信用占用保留。刷新销售详情后点击“分配发货批次”，使用新的分配操作；原子单及批号仍保留供查阅。
- **已拣货 / 已复核**：系统保留占用。核对实物归位后人工取消子单，再重新分配。自动任务不会替仓库确认商品已经放回。
- **已收款待出库**：库存继续受保护，可解决拦截后恢复出库，或实际退款后取消；不要再次收款。

自动回收不产生库存出入库、不改变成本、不登记收付款，也不冲减应收应付。质量、效期、冻结等原因可能继续影响可用库存。

页面在打开、刷新详情或原有轮询时读取最新状态；已打开的操作框可能遇到版本冲突，刷新后按当前状态处理，不应反复提交旧单操作。

## 本机启动和停止

先执行 `python scripts/dev.py migrate`，业务链应为 b0018、控制链应为 c0013，再部署 0.17 一致版本的 API 与管理端。新增后台进程使用第四个终端：

```text
python scripts/dev.py expiry
```

单次有界扫描（不是扫描全部积压）：

```text
python scripts/dev.py expiry --once
```

Windows 没有 python 命令时，替换为 `backend/.venv/Scripts/python.exe`。按 Ctrl+C 停止进程；重启会重新扫描，已提交的释放不会执行第二次。不启动该进程，API 仍会拦截超时操作，人工取消继续可用。

## 部署和参数

独立任务命令：`python -m medinv.entrypoints.expiry_worker`。与 API 使用相同的业务 / 控制运行数据库连接，不能使用迁移账号。Linux 镜像可覆盖默认 CMD 启动该命令。

| 环境变量 | 默认 | 作用 |
| --- | --- | --- |
| MED_RESERVATION_EXPIRY_ENABLED | false | 是否允许任务执行；本机 dev.py 显式启用 |
| MED_RESERVATION_EXPIRY_INTERVAL_SECONDS | 15 | 每轮结束后的间隔，范围 1–300 秒 |
| MED_RESERVATION_EXPIRY_BATCH_SIZE | 25 | 每租户每轮候选上限，范围 1–100 |
| MED_RESERVATION_TTL_SECONDS | 900 | 新预占有效期，范围 60–3600 秒；修改不重写历史预占 |

每轮最多访问 10 家租户，并在逐项之间应用 5 秒软预算。达到最后一家后回绕，忙行和失败项在后续循环重试。大量企业或积压会增加延迟，不能把扫描间隔理解为每单最多等待 15 秒。两个工作进程允许同时运行，通过主体行锁和终态校验避免重复释放；尚无生产吞吐承诺。

启用前检查迁移、备份、运行角色和待处理积压；任务会处理已存在的符合条件超时记录。发布、回退时先停止任务和业务写入，保持版本一致。停用开关需重启进程生效；不提供运行中动态配置。

## 故障处理

启动日志包含间隔和批量；有候选或错误时输出 scanned / released / skipped / errors。日志不输出连接密码、用户令牌或 SQL 参数。控制库不可用时不执行回收；单项失败回滚来源单、库存占用、审计及 Outbox，并继续处理其他项。`--once` 出现扫描或单项错误返回非零。

若占用长时间未释放，先确认进程存活及最近错误，核查单据是否已经付款、拣货、复核或主体被停用，再查符合条件预占积压。不要直接修改库存余额。人工取消走现有单据操作；付款单走恢复出库 / 退款取消。

自动操作的审计身份为固定系统 UUID，原因包含“系统自动回收”；不是某个员工登录执行。详情保留原子单和批次，自动释放时间不可清除。

完整事务设计见 [ADR 0017](../adr/0017-预占到期自动回收.md)。
