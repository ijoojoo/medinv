# 多品类商品主数据实施与验收

日期：2026-10-19。依据用户提供的 `codex-product-master-prompt (1).md` 实施。运行版本沿用 0.25.0，业务库升级到 b0038、控制库 c0017，91 张业务租户隔离表、153 条核心 API 路径。

## 1. 实际修改内容

### 工作台与固定表单

“资料 → 商品档案”使用左侧品类树、右侧查询 / 维护工作区；“设置 → 商品字段设置”进入完整配置工作台。商品查询每行对应原 `med.product.id`，不另建一套商品身份。

覆盖中西成药、中药饮片、医疗器械、普通食品、保健食品、特殊医学用途配方食品、婴幼儿配方食品、化妆品、日用品和门诊医疗服务，共 10 个可建档配置。食品下设置普通食品和特殊食品分支；特殊食品再分保健、特医和婴幼儿配方。原 DRUG 无充分证据细分时显示“药品（旧档待确认细类）”，不会自动推断成药或饮片。

固定七个页签：基本信息、价格信息、质量管控、运营管控、扩展属性、第三方对接、自定义属性。本次内置 58 个逻辑字段与 58 个槽位；基本信息 B001–B015 按用户方案固定顺序。字段不适用仍保留控件位置；集合使用摘要入口及独立维护窗口，不撑高槽位。三列、两列、单列由容器宽度决定。同宽度下切换品类不补位、不移动其他字段。

树箭头只展开 / 收起；节点名称只改变查询范围。正在编辑商品的真实品类、完整路径与浏览树独立。父分组新建必须明确选择可建档类别；不默认普通食品。页签切换保留输入；离开未保存编辑时提供保存、放弃、取消。显式保存资料草稿后才持久化，浏览器输入不冒充服务端草稿。

### 主体、证件、服务和经营层级

组织身份保存在 `med.catalog_organization`，角色保存在 `med.product_organization_role`。持有人、注册人、备案人、生产企业、受托生产企业、服务机构分别保存真实角色代码。同一组织可承担多个合法角色；不根据名称相似自动合并，也不将旧名称文本猜成身份。

产品证件沿用 `med.product_certificate`，增加 `med.product_certificate_link` 支持一证多商品。关联明确的证件版本，并明确选择一份业务适用证件；多个证件不以第一条、最大 ID 或最近更新时间自动决定。已核验证件修订或停用后，旧版本关联不能继续作为新业务准入依据。备案原件未载有效期时允许 `NOT_STATED`，不填写推测日期。关联版本及原始证件信息保留快照。

价格、包装、条码、医保和平台编码复用原独立入口。商品统一编码仍自动生成，已有商品 / SKU 编码和单据引用保留。门诊服务共用商品身份与计费单位、服务机构、科室和参考单价，数据库禁止生成其库存 SKU，不要求生产批号或产品效期。

组织经营设置保存于 `med.product_entity_settings`，按经营主体独立维护启用、允许采购、允许销售、推荐级别、ABC / 双 ABC 和经营备注。无独立设置时沿用原主档默认值；独立修改不改变公共商品资料版本或质量审核状态。既有全局经营默认值保留。当前组织层级是已有经营主体，不将其表述为已经实现独立门店组织模型。

### 配置职责与四种版本

| 职责 | 实际位置 | 边界 |
|---|---|---|
| 字段身份、含义、类型与绑定 | `domain/master_schema.py` 的内置字段目录；已发布 payload.fields | 受控白名单，不接受任意 SQL / 脚本 |
| 完整配置快照 | `med.catalog_schema` | 草稿、预览、发布；已发布行禁止修改和删除 |
| 公共页签与槽位 | payload.tabs / payload.slots | 基本信息 15 槽位固定；其他页签统一调整顺序后发布 |
| 品类树 | payload.nodes；发布投影 `med.catalog_category` | ID、代码、已确定的 profile 不改义；停用代替删除 |
| 品类规则 | payload.rules[profile][field_key] | 适用、别名、只读、必填、条件必填、长度和受控格式 |
| 查询列 | payload.columns；`master_projection.py` | 稳定字段键取值，不依赖中文标签或表单位置 |
| 商品资料历史 | `med.product_master_revision` / product.data_version | 保存字段值、实际角色、证件版本、当时品类路径 |
| 证件版本 | 原 product_certificate / certificate_revision | 独立证件内容、核验与历史 |
| 并发版本 | product.version、配置草稿 version、主体经营设置 version | 条件更新，冲突不静默覆盖 |

配置支持树管理、字段目录、品类规则、全局布局、版本和跨品类预览。发布检查循环、非法移动 / 删除、重复槽位、非法绑定、必填与不适用冲突、受控别名和条件值。影响预览显示受影响分支、商品数量与需重新校验数量；预览令牌随内容和影响变化，过期不能直接发布。

业务规则与标签 / 布局分别比较。新版改变业务约束时，已采用新主数据的商品办理采购、销售、零售前必须按新规则维护并重新审核；仅改标签、只读显示或布局不会触发该业务重审检查。编辑提交仍必须带当前配置版本，旧会话得到明确冲突并保留输入。回滚通过复制旧配置生成新草稿再发布；不回退商品值，新增加的字段 / 节点仍保留身份并停用。

### 真实业务接口适配

新建、修改、全量校验和新主数据 CSV 导入调用同一后端聚合服务。旧商品创建 / CSV、旧修订和旧经营信息中的重叠字段也接入已发布规则；现代主数据的旧整表修订入口明确拒绝绕过，要求从新工作台修改。旧字段规则及商品字典继续保护旧接口与字典值。

采购、批发销售、零售采用新证件准入及主体经营开关。新成交快照额外保存 `master_identity`：商品身份、资料版本、表单版本、真实组织角色、明确业务证件。生产企业摘要只来自生产 / 受托生产关系，证件编号只来自显式业务选择；不会拿持有人当生产企业。已确认旧单据和历史商品快照不回写。

库存期初、盘点、调拨、质量作业及退货的当前资质检查也使用统一资格函数，旧商品仍保留原有效期检查。它们原有批次 / 商品历史快照继续使用既有来源；本次不能据此宣称所有历史单据都具备新的完整主体证件链。

查询按品类分支、审核状态和关键词在数据库中先筛选、排序再分页；关键词支持商品信息、真实组织 / 角色、证件编号、单位和编码。多主体、多证件、多条码使用集合投影，不重复商品行。查询计数与导出使用同一服务。导出采用 UTF-8 CSV、稳定键和角色摘要，权限数据不返回；超过 5,000 条要求缩小范围，不静默截断。当前未实现任意字段的高级筛选设计器或服务端大批量异步导出。

## 2. 字段映射与首期配置

- [58 项字段映射矩阵](../technical-python/商品主数据首版字段映射矩阵.md)：实际含义、类型、权威存储、页签 / 槽位、适用类别与基础必填。
- [完整首版种子配置](../../contracts/mdm/product-master-form.v1.json)：确定性字段 / 节点 UUID、树、七个页签、槽位、选项、规则与查询列。
- [原 493 项规划目录](../technical-python/MDM主数据与字段设计.md)：继续作为专业字段细化依据，不将全部规划字段宣称为已上线。

金额和数量使用 Decimal；温湿度、整数等有独立精度 / 范围检查。正式审核检查全部页签与关系，草稿允许缺失，但非空值仍检查类型、引用和角色。明确区分未提交、清空和赋值；未提交、无查看权限或配置停用的旧字段不会自动清空。存在私有字段时读取和历史响应均按当前权限裁剪。

规则执行不依赖 UI 灰显。实际角色由监管代码决定；监管子类型 / 器械类别未明确时显示待核实，不直接认定不适用。单条件规则支持“字段等于某个合法值 → 必填”，文本格式支持无空白、ASCII 编码、数字串；任意表达式、多层复杂规则引擎不在本次范围内。

专业规则核对依据：

## 4. 接口与源码入口

| 能力 | 路径（统一 `/api/v1/catalog/master` 前缀） |
|---|---|
| 已发布树 / 字段 / 布局 / 规则 | `GET /schema` |
| 配置历史快照与预览 | `GET /schema/{id}` |
| 保存配置草稿 | `POST /schema/draft` |
| 预览令牌校验后原子发布 | `POST /schema/{id}/publish` |
| 受控自定义字段元数据 | `GET /custom-field` |
| 统一查询 / 分页 / 导出数据源 | `GET /products` |
| 商品聚合及历史目录 | `GET /products/{id}` |
| 全页签正式完整性校验 | `POST /validate` |
| 创建 / 部分更新草稿 | `POST /products` |
| 商品历史快照 | `GET /products/{id}/history/{version}` |
| 主体经营设置 | `GET /products/{id}/entity-settings`；`POST` 同路径 |
| 真实主体查询 / 创建 | `GET /organizations`；`POST` 同路径 |
| 可关联证件查询 | `GET /certificates` |
| CSV 预检 / 提交 | `POST /import/preview`；`POST /import` |

写入携带稳定字段键、商品 ID（新建省略）、category_node_id、form_revision、expected_version、values、reason，并沿用幂等请求头。配置发布携带预览令牌与草稿并发版本。确认响应前保留原输入；版本冲突不自行覆盖或自动转成另一品类。

主要前端：`ProductMasterWorkspace.vue`、`MasterFields.vue`、`MasterTree.vue`、`MasterConfiguration.vue`、`ProductEntitySettings.vue`、`productMaster.ts`、`master.css`。后端入口在 catalog 的 `master.py`、`master_config.py`、`master_projection.py`、`entity_settings.py` 和 `profile.py`；复用原 code_rules、certificates、dictionaries、operations、prices、packaging 服务。未引入低代码平台、规则服务或事件溯源系统。

## 9. 多品类主数据字典与字段规则贯通（2026-10-19）

### 选值与语义

新版商品工作台及配置布局预览复用商品字典，绑定依照稳定字段键完成，别名不创建新的字典。表单响应 `GET /api/v1/catalog/master/schema` 增加 `dictionaries`，与不可变字段定义和已发布配置 `payload` 分开返回，不改写既有配置快照。

| 逻辑字段 | 当前适用范围 | 处理方式 |
|---|---|---|
| `base_unit` | 十类商品 / 项目 | 物品基本单位与服务计费单位共用字典；保留品类别名及30字符容量 |
| `dosage_form` | 中西成药 | 使用剂型字典，按已发布长度及格式规则过滤 |

| `storage_conditions` | 九类实物商品 | 使用储存条件字典；服务不适用，固定槽位仍保留 |
| `drug_business_scope` | 中西成药、中药饮片 | 药品经营范围类别严格字典 |
| `device_business_scope` | 医疗器械 | 器械经营范围类别严格字典 |

- 建议字典支持输入或选择，严格字典仅提供启用且满足当前品类长度 / 格式的选项。MDM不接受的“未知”“不适用”等占位文案也不作为候选。
- 新建或重新打开资料时重新读取字典；编辑过程中不覆盖用户输入。服务端在实际保存、校验、导入时继续采用当前字典校验，不能通过绕过页面写入停用值或非法值。

- 字典控件使用单层边框、可关联的标签与原有94px槽位；严格选值支持上下键。六个字段仍保留原必填、权限、只读和条件联动规则。建议字典的手工输入不会自动扩充受管理的选项；组织、生产企业和证件的直接输入自动复用 / 补充机制保持独立。
