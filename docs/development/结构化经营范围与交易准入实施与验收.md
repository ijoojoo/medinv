# 结构化经营范围与交易准入：N06

更新：2026-10-21。应用 0.28.0；业务库 b0047；控制库 c0017。

## 交付口径

本次实现可配置范围、独立复核、交易重验及隔离测试。用户已明确“暂未整理，先实现可配置规则与测试验证”。因此没有为现有试用企业推断、预置或启用真实经营资格；试点许可证范围、分类映射及内部质量要求仍须由企业核定。

新增入口为“质量 → 经营范围与准入”。普通药品、医疗器械分别使用既有严格字典 `drug_business_scope`、`device_business_scope`；采购、批发销售按经营主体分别配置。已有首营、类别、有效期、商品资质、冻结、库存、信用等校验继续执行。零售、退货、调拨及其他品类不扩展新规则。

## 配置与生效

1. 在“资料 → 商品字典”维护经企业确认的经营范围分类，在商品资料填写对应的结构化范围值。系统只按完整字典值匹配，不从许可证原文分词、模糊匹配或推导上位类别。
2. 选择经营主体和适用业务，录入本企业范围。每条记录含商品类别、范围字典值、核验起止日期、凭据编号。当前没有新增本企业证照档案模块；本企业凭据仍由人员核对并填写外部编号。
3. 录入往来单位范围，另须选定本主体内供应商或客户及其证照版本。证照原件范围、有效期及附件可供核对；选择哪份证照支持哪一范围由企业核验人员负责，系统不凭证照类型自动认定法定资格。
4. 管理员使用 `catalog.configure` 保存草稿，当前生效规则保持不变。启用和停用都须由具有 `catalog.review` 权限、且未参与本轮草稿修改的人员独立复核。所有本轮编辑者均参与自审排除；不是只排除最后保存者。
5. 复核发布将整份配置原子切换为生效版本。只有启用状态的生效配置参与交易拦截；未经保存的页面内容不参与试算，已保存草稿也不会拦截交易。
6. 证照更新后，范围仍引用原固定版本；人员刷新证照、核对原件并点击“已核对，关联当前证照版本”，再保存与独立复核。系统不会自动把旧范围授权迁移到新证照。

配置限制：每主体、每业务最多 200 条本企业范围、1,000 条往来单位范围；同一对象、类别、字典值不能重复。两端范围都使用明确的核验起止日期，含起止日；长期证照不等于永久免复核。证照有效期未注明或待确认时不能作为本规则的有效依据。

## 匹配与重验

启用后，每个商品须同时满足：

- 商品范围存在，且属于相应药品或器械字典的当前启用值。
- 本企业存在相同类别和范围的有效核验记录。
- 当前往来单位属于此经营主体，角色、原有审核状态及有效期符合对应业务。
- 往来单位存在相同类别和范围的有效核验记录。
- 关联证照确属此往来单位，版本未变、已独立核验、用途正确且仍在有效期。采购要求供货用途 `SUPPLY`，批发要求客户购货用途 `PURCHASE`。

重验入口包括采购正式保存/修订、审核、收货、验收、合格入库，以及批发正式保存/修订、审核、库存分配、拣货、复核和出库。公共库存预占接口另外核对真实销售订单来源并执行范围重验，不能绕过销售入口。取消、关闭及已成功过账结果重放沿用原有恢复语义，避免新资质状态阻断已完成事实的读取。

拦截返回 `ADMISSION_BLOCKED`，显示商品名称、范围及具体缺项；多项错误可通过“准入试算”查看。试算区明确标记草稿或生效版本；通过只表示范围条件通过，不代表其他业务条件或法定经营资格已全部满足。

业务单据保存的商品展示快照及实际过账的商品快照记录规则版本、核验日期、双方范围、关联证照及固定版本。后续配置变化不改写历史快照。

## 数据、接口与权限

`b0047` 新增 `med.admission_policy`，按租户、经营主体、采购/批发渠道唯一；保存草稿 `payload` 和生效快照 `active_payload`、版本、参与编辑者、复核人和时间。未建配置时等同未启用，不进行数据回填。新表强制租户 RLS，运行角色只有查询、插入、更新权限。业务库共 95 张强制 RLS 表。

| 接口 | 用途 | 权限 |
| --- | --- | --- |
| GET `/api/v1/catalog/admission/{entity_id}/{channel}` | 当前配置及最近 30 次操作记录 | catalog.read + 主体范围 |
| POST 同路径 | 保存草稿 | catalog.configure + 主体范围 |
| POST `.../review` | 独立复核、原子发布 | catalog.review + 主体范围 |
| POST `.../preview` | 按指定商品与往来单位试算已保存配置 | catalog.read + 主体范围 |
| GET `.../products?search=` | 试算商品检索，最多 50 条，可缩小范围 | catalog.read + 主体范围 |

`channel` 为 `PURCHASE` 或 `WHOLESALE`。API 快照共 171 条路径。配置写入使用原有会话、CSRF、上下文代次、版本冲突、幂等及提交前授权防护；审计同时保存前后配置和操作原因。复核前再次读取证照与字典，保存时有效不代表复核时仍有效。

发布和正式交易通过主体锁串行化。事务内按需锁定往来单位、商品、字典及证照到提交，防止校验与生效状态发生竞态。失败时规则、审计、幂等结果以及业务库存/账务修改统一回滚。

最终自动化结果、镜像、运行服务和校验值见同目录 `结构化准入验证-20261021.json`。本轮为 N06 与相关进销存回归，并非全项目全量验收。

- 浏览器新增准入场景 1 项与证照/附件回归 4 项全部通过；另对准入页完成截图复查。
- Ruff、严格 mypy（162 个源文件）、Vue/TypeScript 生产构建、所选浏览器测试类型检查及格式检查通过。
- Linux 镜像非 root 运行、双数据库连接、171 条实际 API 路径及方法、预占回收单次扫描通过；本机六项服务就绪。
- 新建隔离恢复副本，三数据库表数量一致、95 张业务表强制 RLS 核验通过；备份时 119 份准入配置的全部字段及生效/草稿内容一致，逐一通过运行角色和租户上下文读回。副本已停止、卷保留，原环境继续运行；没有切换应用入口或验证跨机器恢复。

仅有既有的 TestClient 弃用提示和前端大分块提示。恢复数据校验通过后，本地辅助脚本首次调用了不存在的停止函数；已改用现有恢复工具停止副本，并核对停止状态。该问题未影响数据库恢复结果。

浏览器验证使用新建隔离软件测试企业，包括管理员配置范围、引用证照、草稿试算、禁止自审、质量人员发布、创建采购订单、证照停用后试算及实际交易拦截、只读用户。现有批发试用企业的结构化规则保持未启用。

迁移前已保存三数据库加密备份，密钥与备份分别位于私有缓存目录。新增表不执行破坏性降级。交付包 `outputs/releases/medinv-trial-0.28.0-20261021.zip`、本地标签 `v0.28.0-local-20261021`，提交与镜像等关联信息由同目录 `.delivery.json` 记录；包内不含业务数据库、凭据及密钥。

## 未完成范围与后续

- 真实试点范围分类、证照组合和质量规则尚未整理；不将技术验收标记为真实经营资格验收。正式启用前由试点人员提交样本、核定映射并独立复核。
- 当前是一组明确的范围声明和版本规则，不是任意表达式引擎，也不自动判断每种主体、器械类别和业务的全部法定证照组合。
- 本企业原件档案/附件、批量范围导入、规则过期提醒及更细的人员授权准入可在实际样本明确后增量完善。

## 设计参考

设计采用供货方、购货方与商品资质分别核验和动态检查的思路。法规背景参考市场监管总局公开的[药品经营质量管理规范](https://www.samr.gov.cn/zw/zfxxgk/fdzdgknr/bgt/art/2023/art_bc07ffdb7a1c4e46be371ac5a4a65f9c.html)及国家药监局[2023 年第 153 号医疗器械经营质量管理规范公告](https://www.nmpa.gov.cn/directory/web/nmpa/xxgk/ggtg/ylqxggtg/ylqxqtggtg/20231207173141173.html)。这些来源不能替代具体企业的适用范围、证照原件与质量人员核定；本轮未把示例分类固化成全国统一准入结论。
